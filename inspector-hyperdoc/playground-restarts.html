Playground restarts

clog-moldable-inspector

The Playground Debug action opens a debug report when evaluation fails. That report is intentionally lightweight: it keeps the condition, the captured source, a backtrace, and a small recovery surface that fits the normal inspector UI.

The recovery actions are:

  • Retry re-evaluates the captured source with the same object bound to *.
  • Abort keeps the report visible but marks the recovery attempt as stopped.

This is restart-inspired rather than a live dynamic Common Lisp restart. HyperBook does not keep the original evaluation frame paused for Playground debug reports. If you need the paused-thread model with live restart objects, use the Sessions entry and inspect a full debugger session.

Relevant implementation files:

  • hyperbook-server/playground-eval.lisp
  • hyperbook-server/playground-debug.lisp
  • hyperbook-server/web-debugger.lisp

You can alt-click the Retry or Abort button to inspect the action thunk and see how the recovery flow is implemented.
