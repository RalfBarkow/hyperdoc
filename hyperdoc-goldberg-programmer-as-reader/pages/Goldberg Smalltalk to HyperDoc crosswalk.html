Goldberg Smalltalk to HyperDoc crosswalk

hyperdoc

Goldberg's Smalltalk-80 examples are not copied as a nostalgia exercise. They are translated into HyperDoc architectural commitments: readable layers, uniform objects, dynamic cross-reference, source-state coherence, and history as part of the reading surface.

Inspectable objects

  • Readable malleable layer
  • Hidden protected layer
  • Message-set browser
  • Program as dynamic database
  • Change file as audit trail

Crosswalk

Goldberg / Smalltalk-80 ideaHyperDoc carry-forward
Readable, malleable layers above hidden implementation layers Keep user-facing pages, topics, and operations inspectable while making runtime and datastore boundaries explicit.
System browser organized by classes and messages Topic pages, source pages, code-path graphs, and backlinks act as browsable indexes over multiple object kinds.
Message-set browser for implementors and senders What part of the system knows about that? becomes an operation returning owners, references, and backlinks.
One code database with multiple access paths Generated authoring artifacts, page files, topic objects, and runtime inspector objects should remain linked instead of becoming divergent documentation stores.
Change file as ordered audit trail Journal, provenance, and materialization metadata answer How did I get here?.
Debugger and inspector for current state and why/why-not questions Failure objects, state-machine traces, and operation reports make negative outcomes readable.

ASDF system boundary

The generated ASDF system deliberately keeps registration and materialization as explicit operations. Loading the system makes objects and operations available; it does not silently rewrite the host HyperDoc registry or page tree.

  • (materialize-goldberg-hyperdoc-pages)
