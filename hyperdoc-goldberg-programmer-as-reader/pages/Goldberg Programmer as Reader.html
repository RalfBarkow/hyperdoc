Goldberg Programmer as Reader

hyperdoc

This page rewrites Adele Goldberg's Programmer as Reader as a HyperDoc source station. The central claim is not merely that programmers should write clearer code, but that exploratory systems should be designed so programmers can read the running system, its parts, its interfaces, and its history.

Source claim

Goldberg distinguishes ordinary runtime correctness from readability. A program may be free of write-and-run bugs while still having read bugs: failures that prevent later readers from learning, finding reusable parts, and safely rewriting.

HyperDoc carries this claim forward by treating a documentation page, a topic, a code object, an inspector view, and a clickable operation as different surfaces over one reader problem: how does the system answer the programmer's next comprehension question?

HyperDoc rewrite

  • A topic captures a reusable concept from the paper, such as Message-set browser or Change file as audit trail.
  • A page is an authored reading surface that preserves local context and editorial order.
  • A reader operation turns a comprehension question into a clickable example.
  • The ASDF system hyperdoc-goldberg-programmer-as-reader keeps the code, pages, and materialization operations together.
