HyperBook Journal Tools

A journal-aware HyperBook should expose more than page content. It should also expose operations over the journal itself: replay, checking, chronology repair, and compaction.

The immediate reference for this is the local plugin repository ~/workspace/wiki-plugin-journalmatic. That plugin already defines a concrete tool set for scanning and repairing Federated Wiki journals. This page uses it as the reference surface for thinking about Lisp-side journal objects and tools in HyperDoc/HyperBook.

Why this matters

HyperBook already treats pages, links, and views as inspectable objects. A page journal should get the same treatment. Many of the hard failures seen in localhost FedWiki pages are not content problems. They are journal problems: malformed actions, missing creation, chronology drift, or a journal that can no longer replay the current page state.

A journal checker is therefore not an optional maintenance script. It is part of the object model for a writable wiki page.
