Software Heritage revision links from Git commit hashes

hyperdoc

In HyperDoc's FedWiki story rendering path, a full 40-character Git commit hash can become a Software Heritage revision link instead of remaining inert text. This is the concept layer behind Clickable commit IDs in FedWiki stories: a commit hash is treated as an archived reference token that resolves to a specific Software Heritage revision object.

What the capability does

The capability translates a full commit hash into an external URL of the form https://archive.softwareheritage.org/swh:1:rev:<hash>/. The result is a clickable archival reference inside story text, without requiring a new HyperBook or a second reference model.

Why full 40-character hashes matter

The supported form is a full Git revision hash. A full hash is precise enough to identify one revision object directly. Short hashes are convenient for humans, but they are not the contract this renderer path uses for direct Software Heritage revision links.

Why Software Heritage links are useful in story text

A Software Heritage revision link turns a repository-local identifier into an archived reference that can be opened directly from a story. That is useful when story text discusses commits as evidence, provenance, or review anchors.
