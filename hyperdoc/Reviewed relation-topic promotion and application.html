Reviewed relation-topic promotion and application

hyperdoc

Runtime relation objects remain first-class inspectable objects in HyperDoc. When one of those relations deserves durable topic identity, the relation is promoted through a reviewed proposal and an advisory patch plan before any authored file is edited. That keeps runtime inspection fast while preserving authored sources as durable reconstruction points.

Reviewed promotion, not automatic topic creation

Promotion to topic identity is reviewed, not automatic. Relation objects can emit a proposal, an authoring bundle, and a collision-aware patch plan, but those outputs remain advisory by default. They are meant to help a reviewer decide whether the relation deserves durable topic treatment at all.

Exact-title collision is the merge key

The practical merge key for hyperdoc/topics.lisp is the exact canonical :title. If that exact title already exists, the reviewed path is to edit the existing factory in place. It is operationally dangerous to append a second factory with the same exact title.

Stale append plans must therefore refuse exact-title duplication instead of silently appending another factory. The reviewed plan can stay inspectable, but the apply seam must stop before mutating authored files when the exact title already exists in the authored target.

Approval-gated application seam

Application is separate from proposal and patch-plan generation. Bundles and patch plans are advisory by default; mutation happens only through an explicit approval-gated seam. That seam is restricted to local authored repo targets only: hyperdoc/topics.lisp and a candidate HyperDoc page file.

Approved application yields an inspectable application result object. The result records patch-plan identity, repo-root evidence, applied paths, performed actions, and safe approval evidence. Approval evidence remains inspectable without exposing the raw approval token in inspector views.
