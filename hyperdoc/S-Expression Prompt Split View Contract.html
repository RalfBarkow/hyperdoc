S-Expression Prompt Split View Contract

hyperdoc

This page defines the reference contract for executable prompts that must move between HyperDoc pages, FedWiki stories, topic maps, inspector views, and rendered HTML. The durable object is the S-expression topic/relation program; the other surfaces are projections unless a slice explicitly changes that authority.

Page genre

Reference/contract page. This is not a walkthrough example; it names the invariants that prompt/projection slices must preserve.

Three-layer executable prompt

  1. Knowledge: rules, constraints, invariants, repo boundaries, terminology, and validation policy.
  2. Input: concrete execution data such as source page path, parsed DOM/tree, selected story items, source evidence, and the operator task.
  3. Output contract: required response views, validation predicates, replay expectations, and exact success/failure shape.

In Lisp this is represented by executable-prompt. The prompt can carry its durable topic map program directly, while still preserving the three explicit layers for inspection and replay.

Split-view response

A valid response for this workflow has two synchronized views:

  • FedWiki story view: a human-readable sequence of story items.
  • Topic map program view: the corresponding S-expression topic/relation program.

The split view is represented by split-view-response. Validation succeeds only when both views name the same topic ids and relation ids.

Projection authority

The topic map program is the durable program. HTML pages, parsed Plump DOM trees, FedWiki story JSON, DMX topic maps, inspector views, and rendered pages are projections of that program. A projection slice must not silently invert authority by treating rendered HTML or story JSON as the durable source unless the task says so explicitly.

Validation contract

  • html-page-to-topicmap-program projects a HyperDoc HTML page, pathname, HTML string, or Plump-backed page DOM into the S-expression topic/relation program.
  • hyperdoc-html-to-topicmap-program reloads a materialized HyperDoc split-view page by reading the embedded durable program, falling back to plain HTML projection when no embedded program is present.
  • plump-dom-to-topicmap-program projects a parsed Plump DOM/tree into the same program form.
  • topicmap-program-to-fedwiki-story-items renders the human story projection.
  • topicmap-program-to-hyperdoc-html materializes the durable program and optional story/prompt layers as a HyperDoc HTML split-view page.
  • split-view-response-to-hyperdoc-html materializes a validated response while preserving story order.
  • validate-split-view-response verifies the crosswalk between story items and the program.
  • validate-topicmap-program-equivalence verifies that a reloaded program preserves source, input, output contract, topics, relations, and relation evidence.
  • validate-split-view-response-roundtrip verifies program equivalence plus FedWiki story item order.

Success shape is (:success :fedwiki-story-view :topic-map-program-view :validated-crosswalk). Failure shape is (:failure :crosswalk-mismatch :missing-story-topics :extra-story-topics :missing-story-relations :extra-story-relations).

SLY mREPL replay

The first section loads only the pure prompt/projection core. It must be able to construct executable prompts, parse local HTML strings, project topicmap programs, generate story items, and validate the split view without loading HTTP, TLS, DMX write-path, server, explorer, or inspector systems. 

(require :asdf)
(asdf:load-system :hyperdoc/s-expression-prompts)

(defparameter *example-program*
  (hyperdoc:html-page-to-topicmap-program
   "<article><h1>Prompt Split View</h1><p>Program is durable.</p></article>"
   :source-path "smoke.html"
   :source-title "Prompt Split View"))

(defparameter *example-prompt*
  (hyperdoc:make-executable-prompt
   :knowledge '(:rules (:program-is-durable)
                :boundaries (:no-http-stack :no-dmx-write-path))
   :input (getf (rest *example-program*) :input)
   :output-contract (getf (rest *example-program*) :output-contract)
   :topicmap-program *example-program*))

(defparameter *example-response*
  (hyperdoc:make-split-view-response
   :fedwiki-story-items
   (hyperdoc:topicmap-program-to-fedwiki-story-items *example-program*)
   :topicmap-program *example-program*))

(defparameter *example-html-page*
  (hyperdoc:split-view-response-to-hyperdoc-html
   *example-response*
   :prompt *example-prompt*
   :title "Prompt Split View Round Trip"))

(defparameter *example-reloaded-program*
  (hyperdoc:hyperdoc-html-to-topicmap-program *example-html-page*))

(defparameter *example-reloaded-response*
  (hyperdoc:hyperdoc-html-to-split-view-response *example-html-page*))

(defparameter *example-reloaded-prompt*
  (hyperdoc:hyperdoc-html-to-executable-prompt *example-html-page*))

(defparameter *example-program-validation*
  (hyperdoc:validate-topicmap-program-equivalence
   *example-program*
   *example-reloaded-program*))

(defparameter *example-roundtrip-validation*
  (hyperdoc:validate-split-view-response-roundtrip
   *example-response*
   *example-reloaded-response*))

(assert (getf *example-program-validation* :success-p))
(assert (getf *example-roundtrip-validation* :success-p))
(assert (equal (hyperdoc:executable-prompt-knowledge-of *example-prompt*)
               (hyperdoc:executable-prompt-knowledge-of *example-reloaded-prompt*)))

(format t "~&~S ~S~%"
        (type-of *example-reloaded-response*)
        *example-roundtrip-validation*)

Load the inspector only for the split-view tab or CLOG-backed inspection. This second section is intentionally outside the pure core boundary. 

(asdf:load-system :hyperdoc/inspector)

(defun i (object)
  "Safe inspector helper for SLY mREPL.
Prefer CLOG only if it is already loaded; otherwise use CL:INSPECT.
Never calls SLYNK:INSPECT-IN-EMACS directly."
  (let* ((clog-package (find-package "CLOG-MOLDABLE-INSPECTOR"))
         (clog-symbol
           (and clog-package
                (find-symbol "CLOG-INSPECT" clog-package))))
    (cond
      ((and clog-symbol (fboundp clog-symbol))
       (handler-case
           (progn
             (funcall (symbol-function clog-symbol) :object object)
             object)
         (condition (condition)
           (format t "~&CLOG inspector failed; falling back to CL:INSPECT: ~A~%"
                   condition)
           (inspect object)
           object)))
      (t
       (inspect object)
       object))))

(i *example-reloaded-response*)

Inspector surface

The inspector exposes a Split view tab for split-view-response objects. The tab shows the story items first for human reading, then the exact S-expression program, then the validation result.

Boundary

  • No DMX write-path mutation is implied by this contract.
  • No public deployment behavior is implied by this contract.
  • No broad UI redesign is implied by this contract.
  • The pure prompt core is :hyperdoc/s-expression-prompts; it must not depend on or load :drakma, :cl+ssl, :hunchentoot, :clack, :usocket, or HyperDoc server/explorer/inspector systems.
  • Existing topicmap projection semantics stay intact; this route adds a durable executable prompt program above them.
