ASDF introduction frame

ASDF is the Common Lisp build/load facility used to locate, define, compile, and operate on systems. It should be understood together with Build system versus package manager: ASDF is not itself the installer or package-distribution layer.

The quick-start framing of the manual can be summarized through ASDF quick-start summary: there is a user-facing path around ASDF user workflow, an author-facing path around ASDF system definition, and an implementer-facing path around ASDF extension protocol.

In practice, ASDF is commonly used alongside Quicklisp, while ASDF-Install and clbuild are historical tools that should not be confused with ASDF itself.

This matters for HyperDoc architecture as well. Because a system is the named boundary that asdf:find-system, asdf:load-system, and asdf:test-system operate on, it is also the right primary scope object for examples and test surfaces in HyperDoc. For that translation, see Understanding ASDF Systems in HyperDoc and ASDF Systems, Examples, and Tests in HyperDoc.

Working model

  1. Find the system in the current image: (asdf:find-system :hyperdoc)
  2. Open the corresponding .asd file and locate the module/component list.
  3. Confirm the file containing your new definition is listed as an ASDF component.
  4. Confirm component order is correct when :serial t is used.
  5. Reload the system with force and re-check function availability.

Minimal steps

(require :asdf)
(asdf:find-system :hyperdoc)
(asdf:load-system :hyperdoc :force t)
(fboundp 'hyperdoc::prepare-aarch64-image-topic)

Undefined-function path

If fboundp is still NIL after reload, treat it as a component wiring issue first:

  • wrong package name in the function reference
  • file not included in the ASDF component list
  • component order places use before definition
  • different server process/image than the one you reloaded

Operational note

For this repository, run these steps through the Nix development shell (nix develop or ./dev.sh) so ASDF source registry and dependency resolution are consistent.
