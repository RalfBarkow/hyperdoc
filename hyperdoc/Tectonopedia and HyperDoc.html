Tectonopedia and HyperDoc

hyperdoc

This page compares Tectonopedia and HyperDoc as neighboring reference systems for documentation and publication architecture, without treating them as the same kind of system.

Shared concerns

  • Documentation is authored in a structured source form, not just written as flat prose.
  • Publication matters: source documents are transformed into a navigable web surface.
  • The target artifact is reference-oriented and exploratory, not only a linear manual.

Key differences

  • Tectonopedia is a TeX-authored documentation publishing pipeline and web application.
  • HyperDoc is a page/object/runtime-linked documentation system inside a live Lisp environment.
  • Tectonopedia emphasizes source transformation and publication assembly; HyperDoc emphasizes inspectable runtime objects, object links, and page navigation.

Source medium and publication model

Tectonopedia starts from TeX source, compiles it through Tectonic-specific tooling into raw HTML outputs, and then bundles those outputs with frontend assets into a web application. HyperDoc starts from HTML/Markdown/Lisp pages and runtime objects that are already part of the live documentation system.

Runtime/interactivity boundary

Tectonopedia is relevant to HyperDoc as an example of executable or computation-adjacent publishing, but it is not a live object browser or moldable inspector environment. HyperDoc's interactivity is runtime-linked: page links, inspectable objects, and views stay connected to Lisp objects in the running image.

What HyperDoc can adopt, reinterpret, or leave out

  • Adopts: treating documentation as authored source that is transformed into a navigable web publication surface.
  • Reinterprets: publication pipeline thinking as page/object/runtime-linked documentation rather than TeX compilation.
  • Leaves out: the idea that source-to-HTML compilation alone replaces live inspection, object browsing, or moldable runtime views.
