Walter Olthoff and James Kempf's 1989 paper belongs in HyperDoc as a bridge between Common Lisp object-system pedagogy, formal language-design practice, and inspectable runtime semantics. The paper is not just another CLOS citation: it shows how an executable algebraic specification can act as a second view of a proposed language feature before implementation hardens the design.

Why this source matters here

HyperDoc already treats Common Lisp as a durable software-knowledge medium and keeps distinct surfaces for pages, topic objects, and inspectable runtime objects. This paper adds a sharper historical precedent: a formal artifact can accompany a semi-natural-language standard draft, reveal ambiguities, and suggest the shape of the implementation protocol. That makes it a reference for HyperDoc's own preference for explicit, inspectable, reconstructable documentation objects.

Core assimilation

The paper specifies the method-combination and method-application component of CLOS using Axis, an executable typed functional specification language. In HyperDoc terms, it promotes CLOS dispatch from prose-only explanation into an inspectable model with named sorts, operations, and algorithmic steps.

  • Applicable methods: the intermediate set selected by matching actual arguments against method parameter specializers and inherited classes.
  • Effective method: the actual composed method body produced from the applicable methods and the selected method-combination discipline.
  • Standard method combination: the before/after/around/primary protocol treated as the paper's formalization target.
  • Class precedence: the class-linearization dependency that orders applicable methods and therefore affects the effective method.
  • MOP mapping: the algebraic sorts and operations suggest CLOS kernel objects and operations for method combination.

Relation to existing HyperDoc Common Lisp pages

  • Definitive Common Lisp Books keeps CLOS and MOP references as an advanced object-system neighborhood. Olthoff and Kempf should sit beside Keene and AMOP as a design-semantics source, not as a beginner tutorial.
  • Winston and Horn Lisp 1989 gives the teaching arc for classes, generic functions, and class precedence. Olthoff and Kempf gives the formal method-combination bridge behind that object-system surface.
  • Source-oriented and image-oriented development in Common Lisp is the long-lived software-environment side of the same question. Olthoff and Kempf add the language-design side: executable specifications can keep semantics inspectable before they become runtime convention.
  • A framework for maintaining the coherence of a running Lisp is a later image-coherence counterpart. McDermott asks how a running Lisp image stays coherent as code changes; Olthoff and Kempf ask how a language feature's semantics stay coherent while the standard itself is still moving.

Assimilation boundary

Treat this source as a historical and conceptual bridge, not as the final ANSI CLOS definition and not as a complete specification of Common Lisp. Its formalization targets the CLOS method-combination/application component of a draft standard, deliberately omitting user-defined method combination and parts of Common Lisp outside the modeled component.
