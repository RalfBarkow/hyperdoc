Two Installation Models: SD Image vs Classic Installer

NixOS on Raspberry Pi has two different workflows. They should not be mixed.

SD Image Model

Use this when you flashed an official Raspberry Pi SD image. The machine boots into an already installed NixOS system. The correct path is: 

edit /etc/nixos/configuration.nix
nixos-rebuild boot
reboot

First-boot access paths inside the SD-image model

The SD-image model still contains three distinct first-boot access paths. These are access variants inside the same installation model, not a third installer.

Path What must already be true Continuation
stock official SD image only the upstream SD image was flashed SSH is optional; if reachability or login prerequisites are missing, continue from a local console
semi-headless bootstrap the Pi booted, but remote login is not ready yet use HDMI/keyboard once to establish the login path, then continue remotely
fully headless custom image the image already contains OpenSSH, a normal admin user, and an authorized key boot, discover host/IP, SSH in as the declared admin user

Remote SSH provisioning to a machine that is already running and reachable is real, but it should not be confused with what the stock official Raspberry Pi SD-image tutorial guarantees on first boot.

Inspect the branch logic here: rpi-first-boot-access-dry-run-example.

Classic Installer Model

Use this when you are performing a normal installation to a mounted target filesystem. The correct path is: 

mount target under /mnt
nixos-generate-config --root /mnt
nixos-install

Do Not Mix Models

Do not run installer commands on a machine that is following the preinstalled SD-image workflow. Do not assume that nixos-rebuild boot can replace nixos-install in a classic install.

The practical rule is simple:

  • If you flashed an official SD image, stay in the SD-image model.
  • If you are building a system under /mnt, stay in the installer model.
