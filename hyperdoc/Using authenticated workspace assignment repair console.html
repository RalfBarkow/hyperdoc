Using authenticated workspace assignment repair console

hyperdoc

This page documents the narrow HyperDoc-side mutation surface for workspace-assignment backfill. Diagnosis stays read-only in the existing DMX object inspector and repair triage views. Mutation now happens in a separate Repair console tab that asks for explicit credentials at action time, builds an authenticated DMX client ephemerally, and then calls the same guarded workspace-assignment repair executor already used behind the MCP tool repair_workspace_topic_assignment.

In the broader surface vocabulary, the repair console is the worked mutation surface. In the broader boundary vocabulary, it is also a worked authentication boundary and an adjacent mutation-side crossing requirement for the later transition boundary around guarded journal and repair stages.

Console entrypoints

There are two entrypoints into the repair console:

  • single object: open the title-first launcher page Operational definition: chunk, chunk note, manifest note, content topic, then open (make-operational-definition-note-proxy) and select the Repair console tab
  • backlog: open (make-dmx-shared-workspace-repair-triage) and select the Repair console tab

Both entrypoints keep the same operational split intact:

  • workspace assignment target remains 919815
  • topicmap placement remains 919822
  • foreign objects such as 922451 stay excluded
  • already-correct objects such as 922586 stay excluded from backlog repair

Credential modes

The repair console supports explicit credential mode selection. The current first cut offers:

  • username/password
  • authorization header
  • bearer token

The UI keeps the active mode explicit and only uses the fields relevant to the selected mode for the current action. The durable learning page HyperDoc three-mode DMX auth crosswalk now keeps the DMX-side Credentials path, the AuthorizationMethod distinction, and the later JSESSIONID aftermath inspectable without widening this console into a general login surface.

Ephemeral credential handling

Credentials are ephemeral in this flow. They are entered into the repair console, used immediately to construct an authenticated HTTP DMX client, and then discarded with the console refresh after the action returns.

  • They are not written into topic content.
  • They are not written into workspace notes or handovers.
  • They are not written into long-lived host environment files.
  • The console stores only sanitized repair results such as topic id, workspace readback, topicmap preservation, outcome, and error message.

Guarded execution path

The console does not invent a second mutation path. It threads explicit credentials into an ephemeral http-dmx-import-client and then calls execute-dmx-workspace-topic-workspace-assignment-repair. That is the same guarded repair semantics already used by the MCP surface.

Single-topic flow

  1. Open Operational definition: chunk, chunk note, manifest note, content topic.
  2. Launch the real object through (make-operational-definition-note-proxy).
  3. Read the Workspace diagnostics tab first.
  4. Switch to Repair console.
  5. Select a credential mode and enter credentials.
  6. Run Dry-run selected topic first if you want a no-mutation readiness check.
  7. Run Repair selected topic for the live mutation.
  8. Inspect the per-topic live result readback in the same console.

Backlog flow

  1. Open (make-dmx-shared-workspace-repair-triage).
  2. Review the read-only Repair triage tab first.
  3. Switch to Repair console.
  4. Select a credential mode and enter credentials.
  5. Use Dry-run selected topic or Repair selected topic for one backlog item.
  6. Use Dry-run backlog or Repair backlog for the whole current backlog.
  7. Inspect the per-topic live result readback table after the action.

Acceptance cases

  • 922464 is the canary repair candidate: it is HyperDoc-owned, in topicmap 919822, and missing workspace assignment before repair.
  • 922586 is the already-correct control: it should show workspace assignment 919815 and should not need repair.
  • 922451 is the foreign control: it should stay excluded from guarded workspace-assignment repair.

Current live boundary

This console removes the need to hunt for secrets in host service config just to backfill workspace assignment. It does not itself provide a general DMX login system, and it does not widen HyperDoc into a raw DMX mutation surface. Live repair still depends on the user supplying valid DMX credentials in the console at action time.
