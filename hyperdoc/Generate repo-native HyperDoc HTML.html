What makes the HTML repo-native

In this repository, a HyperDoc page is an authored HTML page inside the HyperDoc corpus. The page id is derived from the page title, so the title must be explicit and stable.

Use a first-level heading as the page title and keep that title aligned with the intended page identity: 

<h1>Generate repo-native HyperDoc HTML</h1>

Add the package declaration used by authored HyperDoc pages: 

<in-package>hyperdoc</in-package>

Keep the document structurally plain. Do not add an embedded <style> block unless styling is explicitly required.

How to link inside HyperDoc

Prefer authored HyperBook links over ad hoc relative URLs. For links to other HyperDoc pages, use the HyperBook/page form: 

<a hyperbook="hyperdoc" page="Exact Page Title">Visible text</a>

For topic pages, use the topics HyperBook and the exact topic page title: 

<a hyperbook="topics" page="Exact Topic Title">Visible text</a>

When the page refers to runtime objects such as ASDF systems, Lisp functions, or Lisp classes, use the corresponding HyperBook surface rather than faking a static local page.

Recommended authored structure

A repo-native HyperDoc page is usually easiest to navigate when it follows a small authored pattern:

  • page title in <h1>
  • <in-package>hyperdoc</in-package>
  • one short opening paragraph stating the page purpose
  • an Inspectable objects section with direct HyperBook links
  • one or more explanatory sections with narrow headings

How to write the content

Write the page as repository documentation, not as a self-contained public website. That means keeping the prose tightly scoped, using exact page titles in links, and leaning on existing HyperBook navigation surfaces instead of standalone web-navigation conventions.

When describing a maintenance or authoring procedure, prefer concrete rules, exact markup shapes, and explicit target titles over broad generic advice.

Rule of thumb

Generate authored HTML that fits naturally into the existing HyperDoc corpus: title-driven page identity, package declaration, HyperBook links, plain structure, and no ornamental standalone-page styling.
