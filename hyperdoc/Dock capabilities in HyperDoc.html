Dock capabilities in HyperDoc

hyperdoc

Inspector tabs are the durable base chrome. The Dock is now a pane-local coachmark layer that progressively enhances those tabs when a capability such as Lay route, Annotation, or Guide has become newly relevant, is currently active, or needs rediscovery.

The rule for this slice is explicit: degrade chrome, not capability. When the expanded Dock recedes, the capability remains available in lighter form.

The corrective decision for this slice is also explicit: inspection belongs to inspector tabs, not to the Dock. The Dock does not carry an Inspect action or a coachmark-side inspection button.

In this grammar, Connect remains the capability name, but the preferred user-facing action label is Lay route whenever the Touch-Fahrplan metaphor is legible. Topics read as stations, associations read as routes between stations, and the authored route is itself a first-class association topic/object rather than a disposable line.

For the compact route-as-retrieval reading behind that vocabulary, see Iconic route language in HyperDoc.

Base chrome and coachmark layer

The pane still keeps a compact capability row below the inspector tabs, but that row is no longer the whole conceptual model. It is the lighter access layer that remains when the coachmark is gone.

  • Lay route (Connect capability): the compact action stays available, while the coachmark expands only for teaching, active task state, or rediscovery. The first implementation mechanic may still be drag-to-connect, with two-tap route-laying as the non-drag fallback.
  • Annotation: when Lay route is waiting for a target station, tapping Annotation completes the relation against the generic Annotation topic; the canonical example in this slice is source Text pages -> target Annotation; when Connect is idle, the same control reopens the current-object annotation shortcut through that same relation model.

Inspection stays in the inspector tabs and other inspector chrome outside the Dock. The Dock is reserved for transient action-oriented capabilities.

Expert inspection contract

Expert inspection now lives on the existing capability controls through modifier clicks rather than through a separate visible Inspect capability:

  • plain click: keep the existing capability action
  • Shift-click: inspect the capability's current semantic or runtime object
  • Option/Alt-click: inspect the model, source, or evidence side behind that capability
  • Shift+Option/Alt-click: inspect that same model/evidence target while preserving trailing right-hand panes

In the current runtime this means Connect opens either the live session snapshot or the submit-path comparison object, Annotation opens either the current semantic relation or its claim/evidence surface, and Guide opens either the Dock presentation model or the claim that makes its runtime evidence inspectable.

Presentation grammar

The Dock no longer behaves like a permanent mixed toolbar/status/help strip. Instead it moves through a small inspectable state model:

  • latent: no expanded guidance is visible, but compact Lay route, Annotation, and Guide access remain.
  • introduction: the coachmark expands because a capability has become newly relevant and needs teaching.
  • active: the coachmark stays open because Lay route is mid-gesture and task-state controls matter.
  • degraded: the expanded Dock has receded after use or dismissal, while the same capability remains in compact form.
  • rediscovery: the user explicitly reopens the richer coachmark layer through Guide.

The runtime and the docs both point to the same inspectable object: (chunk-dock-presentation-model). Its claims link to implementation evidence in JS, CSS, pane snapshots, explorer views, and focused tests.

Lay route, Annotation, and route/traversal handoffs

Lay route and Annotation are sibling capabilities in the same system. Touch-Fahrplan and DMX are not competing permanent Dock identities. The coachmark may introduce route-laying or route-following possibilities, but the richer workflow belongs in the pane body:

  • Touch-Fahrplan: introduced from the coachmark as a station/route surface when the Zotero-backed workflow is available, while the richer route and report UI remain in the topic pane.
  • DMX: introduced from the coachmark only as a handoff to the richer traversal surface such as the External tab. The route object remains compatible with explicit DMX participant roles such as player1 and player2 when that extra structure matters.

The explicit annotation example for this slice is now: Lay route from Text pages to Annotation. Selecting the Text pages chunk in the HyperDoc Main page and then tapping Annotation while Lay route is active creates or reopens an inspectable annotation relation for Text pages.

Current boundary

This slice keeps the compact capability row visible in steady state and uses Guide for rediscovery. It does not yet move those lighter affordances directly into the tab strip itself.

The current Annotation path still keeps one narrow shortcut: when Lay route / Connect is idle, the compact Annotation action can reopen a current-object annotation relation for the pane’s primary object. The more general path is now the normal route-laying gesture, where a visible source station such as Text pages lays a route to the generic Annotation target.

This slice still does not provide a separate authoring UI for arbitrary DOM sub-anchor annotation outside the route-laying gesture itself. It keeps the generalization narrow by making Annotation a normal target endpoint in Connect first.
