Why topics are now a HyperBook

HyperDoc already has object-backed HyperBooks for runtime objects such as ASDF systems, Lisp functions, and Lisp classes. Topics now follow the same model: each topic object has its own page in HyperBook topics.

How this relates to DMX topic proxies

For a browser-first walkthrough, see Demonstrating DMX Topic Proxies in HyperDoc.

Topic-page navigation still uses authored links such as <a hyperbook="topics" page="Exact Topic Title"> and opens stable pages in HyperBook topics.

That is distinct from runtime wrapper functions such as (concept-operational-definition), (dmx-topic-operational-definition), and (prepare-aarch64-image-topic), which may return live DMX-backed hyperdoc::dmx-topic-proxy objects in the inspector.

The authored topic factories are still preserved internally so HyperDoc can rebuild the topic index and the topic-page surface even though the wrapper layer now resolves DMX proxies for selected runtime functions.

For the preserved authoring layer itself, see Authored topic factories.

For the repo-specific role of an authored topic factory as the durable reconstruction point for the topic-page surface, see Topic factory.

Curated page to topic links

Page to topic relations remain authored and explicit. HyperDoc pages link to topic pages using markup such as <a hyperbook="topics" page="Exact Topic Title">.

The page= value must equal the exact canonical topic title string. Visible text may vary, but the page target string must match the topic title exactly so that routing and backlink lookup stay aligned.

Automatic topic to page backlinks

Topic to page relations are no longer primarily curated in hyperdoc/topics.lisp. Instead, they are derived automatically via the existing HyperBook backlink machinery from authored page links that point into HyperBook topics.

In this model, the derived relation is the backlink set computed from authored incoming links.

When proximity matters without association, HyperDoc can also author arrangement pages such as Topic arrangement in HyperDoc. These preserve editorial neighborhood alongside the topic-page surface rather than replacing the backlink model.

Backlinks are not editorial references

Topic objects can still carry optional editorial references. These remain useful for external URLs, historical notes, or supplementary navigation, but they are distinct from automatic backlinks.

Backlinks answer “which pages point here?” Editorial references answer “which extra references should stay attached to this topic object?”

Canonical page id and stable topic key

  • Canonical topic page id: the topic title string.
  • Identity anchor: the stable topic key retained on the topic object for Lisp identity and migration safety.

This separation keeps authored title-style links compatible with current path and backlink behavior while preserving a stable Lisp-level identity if a title ever changes later.
