FedWiki-to-DMX importer workspace assignment bug

hyperdoc

This page is the shared bug-fix surface for the FedWiki-to-DMX importer refactor. It exists before the code change so the failure, invariant, planned repair, and verification route are inspectable in one place.

Bug summary

The FedWiki-to-DMX importer can create a DMX topic and receive a successful topic id without assigning the new topic to a workspace. The observed result is a live DMX topic whose Meta panel shows Workspace n/a.

The immediate observed example is topic 971853, Minimal viable DMX note writer, with URI hyperdoc:mcp/workspace-note/minimal-viable-dmx-note-writer. It was created during an MREPL demonstration and appeared in the topicmap view, but it was not assigned to a workspace.

Expected invariant

Importer-level topic creation must not be able to return an unassigned DMX topic. For HyperDoc importer workflows, the default workspace is the context-window workspace 919815, and the default visible topicmap placement is the context-window topicmap 919822. 

importer create topic
  - create DMX topic
  - assign topic to workspace 919815
  - place topic in topicmap 919822
  - report success only after assignment and placement

Related topic

DMX topic 961552 documents _assignToWorkspace as a private initial-assignment helper. This bug fix should respect that boundary: the importer needs an explicit initial-assignment workflow, not a broad public mutation surface.

Root cause hypothesis

dmx-import-create-topic is currently usable as an importer workflow primitive, but it behaves like a raw transport primitive. Raw topic creation can succeed before workspace assignment and topicmap placement happen. That makes an orphan topic representable as a successful import result.

Refactor target

  • Demote or rename dmx-import-create-topic to an explicitly raw primitive.
  • Add a guarded importer primitive such as dmx-import-create-workspace-topic.
  • Make FedWiki import execution call only the workspace-aware primitive.
  • Make raw creation signal or warn when called from importer workflows.
  • Add a regression test that no importer-visible create action returns an unassigned topic.

Working rule

The importer must treat topic creation and workspace assignment as one importer-level transaction. If workspace assignment or topicmap placement cannot be completed, the import operation must not report a successful topic creation.
