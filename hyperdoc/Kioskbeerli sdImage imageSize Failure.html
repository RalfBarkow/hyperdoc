Kioskbeerli sdImage imageSize Failure

hyperdoc

The current kioskbeerli build failure is specific: in the locked nixpkgs revision used by the project, the SD-image module set no longer accepts sdImage.imageSize.

This is not just a typo in kiosk.nix. It reflects a module-shape change in upstream NixOS.

Observed configuration

The current kiosk.nix contains: 

sdImage = {
  compressImage = true;
  imageSize = 4096; # MiB
};

Locked upstream revision

The kioskbeerli flake locks nixpkgs to revision:

cf59864ef8aa2e178cccedbe2c178185b0365705

The corresponding lock file is also available as an inspectable pathname: kioskbeerli/flake.lock

If one of these helper objects is reported as undefined at runtime, see Reloading HyperDoc After Adding Lisp Objects.

In the corresponding module sources, the relevant files are:

  • nixos/modules/installer/sd-card/sd-image-aarch64.nix
  • nixos/modules/installer/sd-card/sd-image.nix

The whole reference set is available as one inspectable object: kioskbeerli-sd-image-failure-context

What the module provides now

In this upstream version, the SD-image module still provides options such as:

  • sdImage.compressImage
  • sdImage.firmwareSize
  • sdImage.firmwarePartitionOffset
  • sdImage.populateFirmwareCommands
  • sdImage.populateRootCommands
  • sdImage.expandOnBoot

But it no longer defines an option named sdImage.imageSize.

What replaced it

There is no direct one-option replacement for total image size in this module set. Instead, the image size is computed internally from:

  • the apparent size of the root filesystem image
  • sdImage.firmwareSize
  • sdImage.firmwarePartitionOffset

The module then truncates the final image to exactly that computed size.

In other words, upstream moved from “configure total SD image size” to “derive image size from the generated partitions and expand the root partition on boot if needed”.

Why this matters for a credible maintenance story

The failure is useful because it shows that the declared kiosk build path has not yet been demonstrated on the current upstream module set. This is exactly the kind of boundary that a credible maintenance story should make visible.

  • The repository declares an image build target.
  • The actual module API has changed.
  • The kiosk configuration must now be updated before the build path is credible.

Current local status

The local kioskbeerli configuration has now been patched to remove sdImage.imageSize from kiosk.nix.

That correction path is complete. Rerunning the build now gets past the original SD-image module error.

Pragmatic next step

The next concrete failure is now different. It is no longer an obsolete option problem. It is a build-host problem: trying to realize an aarch64-linux image from an x86_64-darwin machine without a suitable Linux builder.

So this page should now be read as a completed correction topic:
