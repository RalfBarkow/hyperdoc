Assimilation verdict

Import the Whyline interaction pattern, not the Java implementation. HyperDoc should let a reader start from an observed runtime artifact: a value, error, rendered view, page artifact, snippet result, or missing expected output, then ask why-did / why-not questions that open inspectable evidence objects.

Why this belongs in HyperDoc

The paper makes debugging less speculative by deriving questions from observable output. HyperDoc can do the same for inspectable runtime objects: an output observation becomes a first-class question target, and the answer becomes a code-path graph plus source anchors.

Boundary

This slice does not claim full dynamic slicing, full static call graph recovery, or JVM-style instrumentation. It starts with authored, short, inspectable traces from the Playground / SLY / inspector path.
