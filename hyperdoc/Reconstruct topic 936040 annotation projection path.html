This page records the reconstruction path for DMX topic 936040, the workspace annotation titled Annotation: An active/alive pair is two agents connected by principal ports. Reconstruction narrative

The source side of the relation is the third list item under Lafont 1990 Interaction Nets / Core concepts from Lafont 1990. The DOM anchor strategy turns this into a list-item anchor with the path h1-lafont-1990-interaction-nets / h2-core-concepts-from-lafont-1990 / ul-2 / item-3 and the slugified label an-active-alive-pair-is-two-agents-connected-by-principal-ports. The target side is the Dock synthetic annotation target, dock-annotation. The relation key is therefore the source path plus to-dock-annotation.

The DMX workspace annotation URI is the workspace-annotation prefix plus that deterministic key. The repair rule is lookup-before-create: a write adapter must normalize annotationKey or runtimeRelationId, derive the URI, look up an existing topic by URI, then plan :UPDATE for topic 936040. Workspace assignment and topicmap placement remain separate checks.

(defun reconstruction-required-string (value fallback)
  (let ((text (cond
                ((stringp value) value)
                ((null value) nil)
                (t (princ-to-string value)))))
    (if (and text (plusp (length (string-trim '(#\Space #\Tab #\Newline #\Return) text))))
        text
        fallback)))

Repair interpretation

  • If :TOPIC-ACTION is :UPDATE and :EXISTING-TOPIC-ID is 936040, the deterministic URI resolver is working.
  • If :WORKSPACE-ACTION is :UNCHANGED, no workspace assignment repair is needed.
  • If :WORKSPACE-ACTION is :ASSIGN, run only the guarded workspace-assignment continuation after explicit operator approval.
  • If :TOPICMAP-ACTION is :ALREADY-PRESENT, no topicmap placement repair is needed.
  • If :TOPICMAP-ACTION is :ADD, run only the guarded topicmap placement continuation after explicit operator approval.

MCP write-side patch target

The MCP write adapter should preserve this sequence: normalize annotationKey or runtimeRelationId, derive hyperdoc:mcp/workspace-annotation/<key>, resolve the existing topic with dmx-import-find-existing-topic, plan :UPDATE rather than :CREATE, then evaluate workspace assignment and topicmap placement independently. Do not generate a fresh key from the title, a timestamp, or another local label for this route.
