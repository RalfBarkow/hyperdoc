Special HyperBook Collection Contracts

hyperdoc

If a special hyperbook overview says it “contains one page for each …” runtime object, that prose is a runtime and user-visible contract, not just descriptive background.

Direct lookup alone is not enough. If readers can reach the promised pages only by guessing ids, the collection claim is semantically true but not visibly true.

Rule

A special hyperbook with a collection promise must satisfy both halves of the contract:

  • real page materialization for valid ids
  • a visible live inventory or browse view of the promised collection

It must also keep a bounded negative path for ids that parse correctly but do not resolve to a real runtime object.

The browse surface should be derived from the same runtime source of truth as direct lookup, so the visible inventory and the open-by-id behavior cannot drift apart.

Checklist

  • overview text makes a collection claim
  • positive lookup opens real pages
  • browse view enumerates the live collection
  • browse entries link to canonical page ids
  • parsed-but-missing ids surface a bounded issue path

Proving cases

  • lisp-functions
  • lisp-classes

These two hyperbooks make the rule durable: both claim a collection in their overview text, and both now provide direct page materialization, a visible live inventory, and a bounded negative path.
