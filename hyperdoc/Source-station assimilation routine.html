Source-station assimilation routine

hyperdoc

This routine standardizes how HyperDoc assimilates a source artifact when one slice must produce both durable documentation and executable implementation/test artifacts.

Goal

Preserve source truth while producing a reviewable source-station page, a bounded implementation seed, and a replayable validation report.

Inspectable objects

  • Source-station assimilation routine
  • Intake boundary for source assimilation
  • Source-station page construction
  • Topic-factory assimilation pass
  • Implementation seed assimilation
  • Assimilation validation matrix
  • Assimilation handover report shape
  • Assimilation acceptance criteria

1) Intake boundary

  • Identify source artifacts and classify each as primary source, implementation seed, notes, or generated code.
  • Preserve source-truth boundaries explicitly: what is implemented, what is only documented, and what remains future work.
  • Do not overclaim equivalence between source theory and implementation seed.
  • Record concrete source identity (bibliography/path/hash where applicable).

2) Source-station page construction

  • Create a dedicated source-station page with bibliographic/source identity.
  • Add core concepts with concise source-faithful definitions.
  • Add related HyperDoc pages to preserve source lineage.
  • If code is involved, add an implementation crosswalk table.
  • Add an explicit Not yet implemented / Remaining gaps section.

3) Topic-factory assimilation pass

  • Run exact-title collision checks before appending to hyperdoc/topics.lisp.
  • Add durable topics for the source station, core concepts, implementation seam, and test/trace artifacts.
  • Keep summaries concise, reconstruction-oriented, and source-anchored.

4) Implementation seed handling

  • Place code in a repo-native ASDF/module location; avoid core-system pollution unless convention requires it.
  • Preserve inherited public API names when assimilating previous artifacts.
  • Harden the seed enough to load and test safely (validation, duplicate guards, bounded failure modes).
  • Mark incompleteness explicitly and keep bounded scope visible in docs/tests.

5) Test and validation matrix

Minimum validation sequence: 

tools/validate-documentation-slice.sh \
  --page "hyperdoc/<Source-station page>.html" \
  --topic <topic-fn> [--topic ...]

nix develop --command sbcl --noinform --non-interactive \
  --eval '(require :asdf)' \
  --eval '(asdf:load-system :<tests-system>)' \
  --eval '(<package>:run-<targeted-smoke-tests>)'

# optional but recommended
nix develop --command sbcl --noinform --non-interactive \
  --eval '(require :asdf)' \
  --eval '(asdf:load-system :hyperdoc/tests)' \
  --eval '(hyperdoc/tests:run-surface-smoke-tests)'
  • Run targeted smoke tests for the assimilated implementation seed.
  • Run page/doc validation via existing doc-slice validators.
  • Run broader smoke suites relevant to touched surfaces.
  • Run full suite if feasible; if it fails outside the slice, name the exact external blocker.

6) Codex handoff template (short, reusable)

Surface Answer
- One-paragraph outcome and source/implementation boundary.

Artifact Answer
- Changed files
- Implemented vs not implemented
- Validation matrix results
- Unrelated worktree state

Process Trace
- Inspected inputs, decisions, commands executed

HyperDoc Reconstruction
- New/updated pages and sections

Lisp Source Reconstruction
- New/updated systems/modules/APIs/tests

FedWiki Delta
- Changed pages or "none"

Replay Checks
- Exact commands and outcomes

Remaining blockers
- External failures explicitly bounded and named

7) Acceptance criteria

  • New source-station page renders.
  • New topics pass collision/coverage checks.
  • New code loads via ASDF.
  • Targeted tests pass.
  • External failures are bounded and named when present.
  • Source/implementation boundary remains explicit.

Worked example: Lafont 1990 Interaction Nets

The Lafont 1990 assimilation is a concrete instance of this routine:

  • Primary source station: Lafont 1990 Interaction Nets.
  • Implementation seam: standalone :interaction-net runtime seed in repository-native module paths.
  • Crosswalk and gaps documented on the Lafont page; tests added as focused smoke coverage.
  • Full-suite failures, when present, are reported as external blockers rather than mislabeled slice failures.
