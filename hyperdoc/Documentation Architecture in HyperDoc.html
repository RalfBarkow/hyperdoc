Why this cluster exists

The recent documentation pages establish one coherent model for reference platforms, documentation surfaces, and authoring practice. This index page makes that model discoverable from one place.

  7. Authoring Documentation in HyperDoc: apply the model as repeatable authoring workflow.

Relation model summary

  • Durable page: stable architectural or operational narrative in hyperdoc/*.html/hyperdoc/*.md.
  • Topic object: reusable semantic handle in hyperdoc/topics.lisp with a stable key, canonical title, summary, and optional editorial references.
  • Inspectable object: in-page explanatory affordance through explicit links to HyperBook topics for topics, and expr links for other runtime objects.
  • FedWiki twin: parallel collaboration artifact for journaling and iteration, aligned by intent rather than literal structure.

Symmetry stops at correspondence. The surfaces should stay linked and mutually interpretable, but they should not be forced into identical shape.

How to use this cluster when extending HyperDoc

  • Use the first four pages for conceptual background and boundary decisions.
  • Use Tectonopedia and Tectonopedia and HyperDoc when the comparison problem is source-authored documentation and publication architecture rather than moldable runtime inspection.
  • Use Authoring Documentation in HyperDoc when turning those concepts into concrete slice edits.
  • When adding a new slice, decide explicitly whether FedWiki twins are needed for collaborative traceability.
