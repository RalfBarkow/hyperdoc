Running Image Coherence Rebuild Workflow

hyperdoc

This page specifies the first SCXML runbook for rebuilding HyperDoc's long-running Lisp image back into a coherent state after source, page, or derived runtime state changes.

The workflow is based on Drew V. McDermott's running-image coherence problem: a Lisp image can keep executing while source files, loaded definitions, registries, indexes, page links, and derived tables drift out of freshness order. The workflow treats rebuild as a state-machine problem rather than as an ad hoc sequence of REPL commands.

Workflow artifact

  • hyperdoc/running-image-coherence-rebuild.scxml

SCXML intent

The SCXML machine expresses the rebuild path as a sequence of observable states and semantic events: 

source-changed
  -> reload-systems
  -> reload-text-pages
  -> refresh-derived-runtime-state
  -> scan-authored-links
  -> classify-page-lookup-issues
  -> verify-no-page-lookup-issues
  -> coherent

If page-lookup issues are found, the workflow moves through ranked repair candidates and explicit human review before applying an authored repair. 

classify-page-lookup-issues
  -> rank-repair-candidates
  -> review-repairs
  -> apply-authored-repair
  -> reload-text-pages

McDermott mapping

McDermott term HyperDoc rebuild interpretation
Chunk A page, source file, loaded definition, registry entry, topic materialization, lookup result, or derived inspector surface.
Basis The supporting source or runtime artifact whose freshness constrains a derived chunk.
Derived chunk Loaded pages, link indexes, lookup-issue objects, topic registries, and generated inspector surfaces.
Deriver The reload, rescan, repair, or materialization operation that brings a derived chunk up to date.
Coherence gate A deriver boundary that refuses a risky ASDF load until the selected runtime-support chunks are coherent.
Coherent image A Lisp image whose loaded systems, text pages, derived state, and authored links agree after rebuild.

Inspector startup gate

Browser inspector startup now uses the repo-native running-image gate before loading :clog-moldable-inspector. This matters when Emacs/SLY is attached to a Lisp process that was not born from HyperDoc's direnv/nix develop environment. The process may have a mixed ASDF source registry: one system missing from the repo/Nix universe, another resolving from ~/common-lisp.

The gate preserves the expectation as an artifact. It records the expected dev-shell source universe, current CL_SOURCE_REGISTRY, foreign contaminants, selected ASDF source files, live method-table coherence, and dependency-precompute safety. Only after those chunks are coherent should the inspector load proceed. 

(multiple-value-bind (repaired-p report repair-plan)
    (hyperdoc:repair-running-image-coherence
     :profile :clog-moldable-inspector)
  (declare (ignore repaired-p report))
  repair-plan)

(multiple-value-bind (loaded report)
    (hyperdoc:load-coherent-system :clog-moldable-inspector
                                   :profile :clog-moldable-inspector)
  (declare (ignore loaded))
  report)

Restarting inside the updated dev shell remains a fallback recommendation when the repair plan cannot derive a coherent ASDF basis. It is not the primary repair model. The primary behavior is an inspectable report, explicit derivation actions, or an inspectable repair-plan object.

Page-lookup gate

Exact HyperBook page lookup is the authority. The workflow should not treat near matches as success. A matcher such as the NOR matcher can rank repair candidates, but it must not silently rewrite authored links. 

exact lookup fails
  -> page-lookup issue
  -> rank near-miss repair candidates
  -> human review
  -> authored page or link correction
  -> rebuild and verify

Acceptance condition

The workflow reaches coherent only when the rebuild has completed and the page-lookup verification pass reports no remaining authored page targets that fail exact lookup.

REPL sketch

(asdf:load-system :hyperdoc) (defparameter *runtime-coherence* nil) (defparameter *runtime-repair-plan* nil) (multiple-value-bind (repaired-p report repair-plan) (hyperdoc:repair-running-image-coherence :profile :clog-moldable-inspector) (declare (ignore repaired-p)) (setf *runtime-coherence* report *runtime-repair-plan* repair-plan)) (multiple-value-bind (repaired-p report repair-plan) (hyperdoc:repair-running-image-coherence :profile :clog-moldable-inspector) (declare (ignore repaired-p repair-plan)) (hyperdoc:runtime-coherence-report-summary-of report)) (multiple-value-bind (loaded report) (hyperdoc:load-coherent-system :clog-moldable-inspector :profile :clog-moldable-inspector) (declare (ignore loaded)) report) (loop for page being the hash-values of (hyperdoc::pages-of hyperdoc::*hyperdoc*) append (hyperbook:lookup-issues-of page))
