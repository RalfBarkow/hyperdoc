DM6 AppEmbed HyperDoc Inline Proof

hyperdoc

This page verifies the stable dm6 embedding contract: Elm.AppEmbed.init({ node, flags: { slug, stored } }). It treats dm6-elm as an embedded application island and records evidence from boot, ports, stage snapshots, and semantic AppEmbed events.

Goal

Show that HyperDoc can host dm6-elm through AppEmbed without depending on internal dm6 modules, while making the embedded app's effects visible as an ordered evidence timeline.

Starting situation

The embedded bundle is loaded from /assets/dm6-elm/app.js. The page supplies a stable slug and a clear {} stored-model fallback so a stale native model cannot masquerade as valid dm6 state.

Page-local DM6 seed

The DM6 island below is seeded from this page's own Plump parse tree. Its hidden script.dm6-stored contains generated native AppEmbed JSON: topics, hierarchy associations, item sets, boxes, topic-map view props, topic-list view props, and tool state.

Regenerate the seed after editing this page with (materialize-dm6-inline-proof-page-topicmap-seed!). The generator deliberately excludes the generated script.dm6-stored node itself so rerunning it does not turn the previous JSON into another topic. This is a page-local topicmap seed, not DMX persistence and not an AppEmbed schema change.

Evaluation: elm-pages Effects as Data




  elm-pages' insight transfers well because dm6-elm's embedding boundary also
  turns effects into values. The dm6 equivalents of elm-pages framework state
  are AppEmbed flags, FedWiki stored JSON, decoded model state, ports, input
  events, semantic evidence records, and store snapshots.





  The immediate target is not a full elm-pages-style test runner. The immediate
  target is an inspectable evidence timeline in HyperDoc. A future replay,
  fork, or time-travel debugger becomes plausible after the event grammar and
  deterministic snapshot rules stabilize.




Expected result




  The proof succeeds when the page loads /assets/dm6-elm/app.js,
  exports Elm.AppEmbed, mounts with slug and
  stored as strings, and appends visible evidence records while
  dispatching hyperdoc:dm6-evidence custom events.




Boundary




  HyperDoc owns the host page, evidence adapter, and visible proof timeline.
  dm6-elm owns the product model, update function, view, and ports. The stable
  integration boundary is AppEmbed; this page must not depend on
  retired internal modules or create a second Elm app.
