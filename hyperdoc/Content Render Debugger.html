Content Render Debugger

hyperdoc

The Content render debugger is the browser-visible failure and progress surface for the first materialization of an html-page inspector Content view.

Its contract is narrow: the inspector may briefly show a diagnostic placeholder while an html-page Content view is materializing, but it must never leave a bare Loading content... string as the operator surface. The placeholder is a render debugger with an inspectable report object.

Inspectable objects

  • Content render debugger

Expectation

The page Lisp as Trep was expected to render real page content in the html-page Content pane. The attached page was small and valid HTML. It also contained a remote FedWiki HyperBook link to fedwiki:hyperdoc.dreyeck.ch/ page lisp-as-trep.

Observed reality

The visible text Loading content... was not page content. It was an inert placeholder injected by the inspector runtime in the html-page Content view path. When render materialization failed or stalled before replacement, the browser surface preserved neither the failing condition nor the last completed phase.

Why the expectation was plausible

A reader seeing Loading content... inside the Content pane reasonably reads it as a page-loading state. The remote FedWiki link in the small source page was a plausible suspect, but the placeholder came from the inspector runtime, not from the source HTML.

Classification

This was a disappointed expectation. The product surface promised a content state but did not expose the runtime evidence needed to distinguish page content, remote-link lookup, html materialization, DOM insertion, and render failure.

Resolution

The Content pane now creates an html-page-content-render-report before first materialization and renders a visible Content render debugger placeholder that links to that report. On successful render, the existing real Content output replaces the debugger. On error, the debugger remains visible and inspectable instead of silently leaving the stale loading placeholder.

Report contract

The render report records:

  • object summary
  • view title
  • render phase events
  • start timestamp
  • html-cache-hit?
  • html-ms when available
  • reference count when available
  • asset count when available
  • condition type and message when rendering fails
  • last completed phase

The report is inspectable through normal html-inspector-views views: Overview, Events, Condition, and Page / Object.

Runtime boundary

  • The debugger path applies only to first-render html-page Content views.
  • Non-Content views are not wrapped by the html-page Content debugger.
  • Non-html-page Content view errors are not swallowed by this path.
  • Existing *trace-output* inspector performance logging remains, but the browser-visible debugger is the authoritative operator surface.

SLY MREPL inspectability

(require :asdf)
(asdf:load-system :hyperdoc/server)

(defun i (object)
  "Safe inspector helper for SLY mREPL.
Prefer CLOG only if it is already loaded; otherwise use CL:INSPECT.
Never calls SLYNK:INSPECT-IN-EMACS directly."
  (let* ((clog-package (find-package "CLOG-MOLDABLE-INSPECTOR"))
         (clog-symbol
           (and clog-package
                (find-symbol "CLOG-INSPECT" clog-package))))
    (if (and clog-symbol (fboundp clog-symbol))
        (funcall (symbol-function clog-symbol) :object object)
        (cl:inspect object))))

(defparameter *example-page*
  (make-instance 'hyperdoc::html-page
                 :hyperbook (make-instance 'hyperbook:hyperbook
                                            :id "mrepl-render-debugger")
                 :id "Content render debugger MREPL fixture"
                 :file nil))

(defparameter *example-view*
  (html-inspector-views:make-html-view
   (html-inspector-views:thunk
    (html-inspector-views:html-and-references
     (:p "Rendered content from MREPL fixture")))
   :title "Content"
   :priority 1))

(defparameter *example-report*
  (clog-moldable-inspector::make-html-page-content-render-report
   *example-page*
   *example-view*))

(clog-moldable-inspector::record-html-page-content-render-event
 *example-report*
 :debugger-visible
 :message "MREPL report created.")

(setf (clog-moldable-inspector::html-page-content-render-report-html-cache-hit?-of
       *example-report*)
      nil
      (clog-moldable-inspector::html-page-content-render-report-html-ms-of
       *example-report*)
      1
      (clog-moldable-inspector::html-page-content-render-report-reference-count-of
       *example-report*)
      0
      (clog-moldable-inspector::html-page-content-render-report-asset-count-of
       *example-report*)
      0)

(clog-moldable-inspector::record-html-page-content-render-event
 *example-report*
 :html-materialized
 :message "MREPL HTML materialized.")

(format t "~&type=~S~%status=~S~%core-value=~A~%"
        (type-of *example-report*)
        (clog-moldable-inspector::html-page-content-render-report-last-completed-phase-of
         *example-report*)
        (html-inspector-views:view-title
         (first (html-inspector-views:all-views *example-report*))))

(i *example-report*)

Replay checks

  • The failure smoke test must leave a visible Content render debugger pane with an inspectable report link.
  • The placeholder path must not emit the literal bare string Loading content....
  • Playwright snapshot transport must accept the immediate debugging or final ready state.
