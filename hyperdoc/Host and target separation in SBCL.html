Host and target separation in SBCL

hyperdoc

SBCL bootstrapping needs an explicit distinction between the host Common Lisp used during bootstrap and the target SBCL being built. This separation is not just bookkeeping. It is what makes it possible to use a live host image during bootstrap without letting the final result depend on accidental host state.

Why host and target must stay distinct

The host Lisp is a tool. The target SBCL is the product. Without host/target separation, compile-time and load-time effects can drift across phases and make it hard to tell whether a behavior belongs to the host compiler image or to the target system being built.

Cross-compilation inside one language family

SBCL's bootstrap uses a cross-compiler running inside the host Lisp. That compiler emits target SBCL artifacts rather than merely extending the host image in place. The boundary is therefore not host machine versus target machine in the paper's main sense, but host Common Lisp semantics versus target SBCL semantics.

Devices that make the separation explicit

  • sb!xc provides a temporary shadow-CL namespace for target-side compilation concerns.
  • Target-specific #!+ and #!- reader conditionals distinguish target build concerns from ordinary host read-time behavior.
  • Phase-sensitive forms such as eval-when and make-load-form matter because host-time and target-time behavior can diverge if not managed carefully.

These devices are valuable because they turn a fuzzy bootstrap boundary into an inspectable one. They make it clearer which effects belong to the host, which belong to the target, and which must survive into later build stages.
