First Protocol Seams for dreyeck extraction

hyperdoc

This page turns the current manual conflict resolution proposals into the first real extension seams. The durable objects are typed git-protocol-seam objects, not only prose about future hooks.

The current seam surface is intentionally small:

  • a startup-hook seam in hyperbook/server so downstream runtime behavior installs after core startup
  • a link-redirection and target-rewrite seam in shared HyperBook rendering so dreyeck routing stays downstream

These seams materially realize the current proposal outcomes without running git merge and without moving the larger dreyeck buckets yet.

  • 👀summary on a single seam shows the core call surface, downstream behavior, related proposals, and the concrete symbol boundary.
  • 👀dreyeck-executable-scaffold on the linked scaffold object shows the minimal downstream system that consumes these seams.

Why these seams matter

The startup hook realizes the one-way ASDF direction proposed for hyperbook.asd: dreyeck loads after HyperDoc core and installs its behavior through a hook. The link seams realize the package/export proposals for hyperbook/package.lisp and hyperbook-explorer/package.lisp by keeping shared hook exports in core while letting downstream dreyeck own the branch-specific routing logic.
