Restart dreyeck release service

Use this narrow task when the right build is already deployed and the remaining follow-up is to restart the packaged service and verify that it comes back with the intended load set.

Inspectable objects

  • Restart dreyeck release service
  • HyperBook server vs HyperDoc server load set
  • Live parity evidence
  • dreyeck HTTP smoke probes

Purpose

Restart the release service safely and verify that it returns with the intended HyperDoc-specific load set.

Prerequisites

  • The desired generation is already deployed.
  • You know the service name; in this repo the default is hyperdoc.
  • You have root or sudo access on dreyeck.ch.

Steps

  1. Inspect the service if needed: 
    systemctl status hyperdoc
  2. Restart the release service: 
    sudo systemctl restart hyperdoc
  3. Check that it came back: 
    systemctl status hyperdoc
journalctl -u hyperdoc -n 100 --no-pager
  4. Then continue with: Verify HyperDoc on dreyeck.ch and Confirm scoped example parity on dreyeck.

Expected results

  • The unit is active again.
  • Public routes respond.
  • The intended example scopes are available without rescue loads.

Failure interpretation

  • If the unit restarts but parity still fails, suspect stale or wrong startup wiring.
  • If the unit fails immediately, treat the restart as unsuccessful and continue to rollback or redeploy.
