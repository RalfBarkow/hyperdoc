Target validation

hyperdoc

Target validation is the pre-strike review process that checks whether the nominated coordinates, target description, site status, and collateral-risk assumptions are still current enough to justify action. HyperDoc uses this page to separate data quality problems from review and accountability problems.

Inspectable objects

  • Target validation
  • Stale target coordinates
  • Civilian harm accountability

What validation is checking

  • whether the coordinates still map to the intended target
  • whether the site's present use matches the strike assumption
  • whether adjacency or dual-use context increases civilian risk
  • whether the available evidence is recent enough for the decision window

How stale data becomes a process failure

Old intelligence by itself does not yet explain a strike. The operational failure happens when outdated information survives handoff, enters the strike package, and is not challenged by later reviewers or authorizing officers.

Why this is more than operator error

Target validation is a system responsibility, not only a last-click operator responsibility. Intelligence production, target-package maintenance, review doctrine, timing pressure, staffing, and command expectations all shape how much real validation occurs.

Boundary

This page does not assume that every bad strike reflects a validation failure. The narrower claim is that when a strike is alleged to have followed stale coordinates or stale classification, target validation is the process layer that should have caught the mismatch.
