What transfers cleanly from Ward's model

Ward's survey suggests a reusable sequence: inventory recurring structures, drill into usages, inspect enclosing context, compare similar shapes, and only then decide whether a repeated form deserves explanation or refactoring. That transfer is conceptual rather than tool-specific.

  • Inventory: count recurring operator heads, special forms, macros, and function-designator patterns.
  • Usage: show every occurrence with file, top-level owner, and local snippet.
  • Context: show enclosing definitions and nearby control, binding, or mapping forms.
  • Similarity: normalize forms structurally and cluster repeated shapes.

Why Lisp changes the implementation surface

JavaScript needed an explicit Acorn-based AST inventory and a custom walker. Lisp source often makes the structural layer more direct because forms, operator heads, and macro-bearing top-level definitions are already visible as data. That makes a Lisp source-form survey plausible without claiming that HyperDoc already has a finished AST-survey runtime.

The important distinction is between surveying source forms and inspecting runtime objects. HyperDoc already has strong runtime inspection, but that is not the same thing as a corpus survey over recurring source shapes.

Proposed first survey surfaces for HyperDoc

A first Lisp adaptation could keep Ward's survey shape while using Lisp's source-form strengths more directly. This is a proposal, not a statement of current HyperDoc implementation.

  1. Inventory view: count recurring operator heads, special operators, macros, and common designator patterns such as lambda wrappers or repeated mapping skeletons.
  2. Usage view: list each occurrence with file, enclosing defun/defmethod/defview, snippet, and owning ASDF system where available.
  3. Nesting/context view: show enclosing top-level definition, local binding layer, branch or loop form, and nearby helper calls.
  4. Similar forms view: normalize forms structurally and cluster repeated shapes so minor local remarks can become codebase-level observations.

What remains hypothetical in HyperDoc

HyperDoc does not yet expose a real code-shape survey with inventory, clustering, or similarity computation. These pages document the survey idea and method boundary first so later tooling can adopt the same terms instead of inventing a second language for the idea.
