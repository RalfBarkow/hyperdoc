Merge Readiness and Blockers for upstream main into hauptsache

hyperdoc

This page captures the preparation slice for merging upstream/main into hauptsache without executing the merge. The durable object for this slice is a computed git-merge-forecast anchored to the same merge-intent relation and commit objects as the previous history surface.

The forecast computes a merge base from the explicit anchor commits and then classifies changed paths into three sets:

  1. paths changed only on upstream/main,
  2. paths changed only on hauptsache,
  3. paths touched on both sides and therefore worth reviewing as blockers.

Why attach dreyeck notes to the relation

The notes are not generic commentary. They are attached to the concrete merge-intent relation so that merge preparation can point to likely extraction seams in the same object graph that already stores the review anchors, conflict policy, and success criteria.

Blocker interpretation

In this slice, a blocker does not mean "merge impossible." It means "inspect this overlapping path set before running any merge command." The goal remains preparation and explicit review, not execution.
