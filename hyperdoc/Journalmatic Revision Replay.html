Journalmatic Revision Replay

hyperdoc

The replay logic in client/modules/revision.js is the basis for both checking and repair. It applies journal actions in order and reconstructs the page state at a chosen revision index.

Why replay matters

The strongest journal integrity test is not “does the JSON look plausible?” It is “does replay produce the current page?” If replay fails, the journal is no longer a trustworthy history of the page.

Supported action shapes

  • create
  • add
  • edit
  • move
  • remove

Journalmatic's revision function is small enough to serve as an implementation sketch for a Lisp-side replay function.

HyperBook implication

A Lisp journal object should expose replay directly. Repair tools such as a chronology fixer or compactor should be validated by replaying the result and comparing it to the visible page state.
