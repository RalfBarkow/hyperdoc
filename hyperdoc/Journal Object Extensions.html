Journal Object Extensions

hyperdoc

A Lisp journal object in HyperBook should be more than a slot containing raw FedWiki actions. It should carry operations that make journal integrity and repair inspectable.

Core idea

Instead of treating a journal as opaque JSON, treat it as a first-class object with operations comparable to the tools exposed by Journalmatic.

Possible extensions

  • journal-revision: replay actions up to a given point and produce a page state
  • journal-check: return a set of findings such as creation, chronology, malformed, or revision
  • journal-rectify-chronology: reorder actions by date when that is a defensible repair
  • journal-gentle-compact: collapse runs of adjacent edits while preserving visible page state
  • journal-diff: compare current page state with replayed page state

These need not all be generic functions on day one, but they define the right conceptual boundary. HyperBook should ask journals what can be checked or repaired, rather than scattering journal logic through ad hoc page tools.

Why this belongs in the object model

The current failures on pages such as find and walk are not UI problems. They are failures of journal reconstruction. If the journal is a first-class object, a page can expose its own health, replay behavior, and repair affordances in the inspector.

A minimal Lisp shape

(defclass journal ()
  ((actions :initarg :actions :reader actions-of)))

(defgeneric journal-revision (journal &key rev-index title))
(defgeneric journal-check (journal page))
(defgeneric journal-rectify-chronology (journal))
(defgeneric journal-gentle-compact (journal &key entry-time-span))

The point is not the exact names. The point is to establish a stable place in the model where these operations live.
