Kioskbeerli Planner and Trace

hyperdoc

This page is the durable reference for the Kioskbeerli operational objects behind Kioskbeerli Dashboard. Kioskbeerli remains the physical Raspberry Pi kiosk target for the Hauptsache salon.

The canonical implementation is the :kioskbeerli ASDF system and :kioskbeerli package. The older dreyeck/kioskbeerli package name remains a nickname after load, not a HyperDoc-side ASDF system.

Planner boundary

The planner is SHOP3-like: it preserves named tasks, dependencies, preconditions, effects, task status, and evidence paths. It is plan-only by default and does not execute Nix builds, flash SD cards, mutate devices, open SSH sessions, call HTTP endpoints, or write to DMX.

The obsolete sdImage.imageSize problem is recorded as corrected. The current blocker is still cross-host aarch64-linux image realization unless a suitable Linux builder exists. The first boot of the physical Raspberry Pi is now recorded from the operator report "logged in as nixos on the booted Raspberry Pi"; that evidence is scoped to the boot-pi task only.

Task lookup boundary

Individual plan tasks are navigable objects. Inspecting a task such as (kioskbeerli:kioskbeerli-lookup-plan-task :boot-pi) shows its parent plan/run, dependencies and dependents, progress records, evidence status, and SCXML link. The boot-pi task maps to event PI_BOOTED and state first-boot-observed.

The current lifecycle interpretation is exposed by kioskbeerli:kioskbeerli-current-scxml-state. The remaining next tasks that are still blocked or missing evidence are inspectable through kioskbeerli:kioskbeerli-next-missing-evidence-tasks.

Behavior boundary

The behavior chart is stored in kioskbeerli/kioskbeerli.scxml. It starts in declared and models the route through source review, obsolete-option correction, cross-host build blocking, Linux builder requirement, image build, flash, boot, network, kiosk session, landing page, maintenance, and failure-with-evidence states.

FedWiki asset boundary

FedWiki assets are generated distribution artifacts, not the source of truth. Materialization writes the reloadable ASDF tree under http://localhost:3000/assets/pages/kioskbeerli/, with kioskbeerli.asd directly in that page asset directory.

Trace boundary

The trace records progress entries with task id, from-state, to-state, status, evidence paths, and a note. Missing evidence is a first-class status, not an aside. The dashboard should therefore say missing-evidence or missing evidence when build, flash, network, kiosk-session, or landing-page proof is absent.

First boot is the current exception to that missing-evidence wording: kioskbeerli:kioskbeerli-record-boot-observed records boot-pi as verified and applies PI_BOOTED to first-boot-observed. It does not infer verify-network, verify-kiosk-session, verify-landing-page, record-evidence, or mark-dashboard-status.
