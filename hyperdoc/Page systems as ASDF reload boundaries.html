Page systems as ASDF reload boundaries

hyperdoc

A page system treats a page as a reloadable presentation system. Loading its ASDF system re-provides the code, descriptors, runtime providers, inspection targets, and validation checks needed to display and inspect that page.

Page systems are display, inspection, and reload boundaries. They are not automatically implementation ownership boundaries: the runtime behavior may still belong to the main HyperDoc, FedWiki, AppEmbed, or external adapter systems.

Protocol

The page-system protocol starts with page-system objects and page-runtime-provider objects. A page system records the page locator, ASDF system name, runtime systems, display contract, inspection entry points, validation entry points, source files, artifacts, and reload operation.

The reload operation is explicit: (page-system-reload system :force t) delegates to asdf:load-system for the page system name and then checks the page display contract. Loading a page system should not silently start a server; server startup remains an explicit runtime operation unless a surrounding system already documents a different convention.

Naming convention

  • hyperdoc/page/<slug> for HyperDoc pages
  • fedwiki/page/<domain>/<slug> for FedWiki pages
  • external/page/<adapter>/<slug> for later external adapters

If an external locator is too long or unstable for an ASDF system name, the page system can use a deterministic short ASDF id and keep the full locator in page-system-page-locator.

Mobile chrome generalization

hyperdoc/mobile-progressive-chrome remains the feature-slice system for the mobile chrome behavior and its SCXML/plan artifacts. hyperdoc/page/mobile-progressive-chrome is the page-system reload boundary for the page Mobile progressive chrome in HyperDoc.

The same protocol now covers the DM6 AppEmbed inline proof page and the localhost FedWiki twin mobile-progressive-chrome-in-hyperdoc.

Reload examples

nix develop -c sbcl --noinform --disable-debugger \
  --eval '(require :asdf)' \
  --eval '(asdf:load-system :hyperdoc/page/mobile-progressive-chrome :force t)' \
  --eval '(hyperdoc:find-page-system :hyperdoc/page/mobile-progressive-chrome)' \
  --eval '(quit)'

Boundary

This architecture registers selected page systems. It does not generate one committed ASDF file per page, does not embed large page content in system definitions, and does not make page-system loading start long-running servers. Future page kinds should add providers and descriptors without bypassing the same reload/report protocol.
