Fix Nix SSL Certificate Path on macOS

hyperdoc

This page documents the post-install SSL error in which Nix still tries to use /etc/ssl/certs/ca-certificates.crt even though the working CA bundle is already present under /nix/var/nix/profiles/default.

Inspectable objects

  • Fix Nix SSL Certificate Path on macOS
  • Reinstall Upstream Nix on macOS
  • Inspect Nix Install State on macOS

Observed failure pattern

  • nix profile add nixpkgs#direnv failed with SSL error 77 and referenced /etc/ssl/certs/ca-certificates.crt.
  • The Nix-managed CA bundle already existed at /nix/var/nix/profiles/default/etc/ssl/certs/ca-bundle.crt.
  • Shell-only overrides such as NIX_SSL_CERT_FILE and SSL_CERT_FILE were not sufficient on their own.
  • nix config show | grep '^ssl-cert-file' reported the correct path only after the setting was written into /etc/nix/nix.conf.

Persistent fix

sudo sh -c 'printf "build-users-group = nixbld\nssl-cert-file = /nix/var/nix/profiles/default/etc/ssl/certs/ca-bundle.crt\n" > /etc/nix/nix.conf'
sudo launchctl kickstart -k system/org.nixos.nix-daemon
nix config show | grep '^ssl-cert-file'
nix profile add nixpkgs#direnv

The successful fix was not a shell-only environment override. It was a persistent daemon-visible Nix configuration change. Once ssl-cert-file was written into /etc/nix/nix.conf and the daemon was restarted, Nix stopped trying to use the broken /etc/ssl/certs/ca-certificates.crt path and profile installation succeeded.

Caution about launchctl setenv

  • sudo launchctl setenv NIX_SSL_CERT_FILE ... may fail under System Integrity Protection.
  • sudo launchctl setenv SSL_CERT_FILE ... may fail under System Integrity Protection.
  • On the observed machine, those failures were not fatal.
  • Prefer the persistent /etc/nix/nix.conf fix over relying on launchctl setenv.

Verification

After the profile install succeeds, verify that the tool is actually present in the active shell: 

type -a direnv
direnv --version
