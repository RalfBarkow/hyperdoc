Official Tutorial: NixOS SD Image on Raspberry Pi 4/400

hyperdoc

This page captures the official Raspberry Pi SD-image workflow described on nix.dev. It is the preinstalled SD-image model, not the classic installer model.

Official Workflow

  1. Download a prebuilt nixos-sd-image-*-aarch64-linux.img.zst.
  2. Flash it to an SD card.
  3. Boot the Raspberry Pi 4 or Pi 400 from that card.
  4. Connect to the machine and edit /etc/nixos/configuration.nix.
  5. Run nixos-rebuild boot.
  6. Reboot into the new generation.
  7. Only later use nixos-rebuild switch once the system is known to reboot safely.

The decisive point in the tutorial is that NixOS is already installed in the SD image. The first task after flashing is configuration and rebuild, not installation.

Representative Configuration

The official path assumes a configuration shaped roughly like this: 

{ config, pkgs, ... }:
{
  boot.kernelPackages = pkgs.linuxKernel.packages.linux_rpi4;
  boot.loader.generic-extlinux-compatible.enable = true;

  fileSystems."/" = {
    device = "/dev/disk/by-label/NIXOS_SD";
    fsType = "ext4";
  };

  fileSystems."/boot" = {
    device = "/dev/disk/by-label/FIRMWARE";
    fsType = "vfat";
  };

  networking.networkmanager.enable = true;
  networking.wireless.enable = false;

  services.openssh.enable = true;

  users.users.kiosk = {
    isNormalUser = true;
    extraGroups = [ "wheel" ];
  };

  hardware.enableRedistributableFirmware = true;

  system.stateVersion = "24.11";
}

Secrets such as Wi-Fi credentials and SSH keys should be added locally, not copied from documentation.

Implicit Invariants

  • The flashed image must actually be an official SD image, not an arbitrary installer or reused card layout.
  • /boot must be large enough for kernel, initrd, and extlinux state to be written safely.
  • The labels FIRMWARE and NIXOS_SD must match the mounted partitions.
  • The correct first rebuild mode is boot, not switch.

Failure Modes That Matter Early

  • /boot too small for a new generation
  • missing or truncated /boot/extlinux/extlinux.conf
  • wrong partition labels or reused non-NixOS image layout
  • mixing SD-image workflow commands with installer workflow commands
