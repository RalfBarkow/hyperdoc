Bug statement

Earlier manual page generation used hardcoded future timestamps. After a later remote fork, wiki-client appended a real-time fork action with a smaller date, causing chronology errors.

Workflow rules

  1. Build story and journal from reproducible inputs (title + ordered story items).
  2. Use deterministic ordering for create then add actions.
  3. Date source must be runtime epoch milliseconds.
  4. For every appended action, assign date as max(now, last-date + 1).
  5. Never use hardcoded fixed date constants in generated journals.

Rule (canonical wording): action dates use runtime epoch millis with monotonic rule: max(now, last-date + 1).

Monotonic normalization rule: when chronology is already broken (for example after cross-instance fork/import), rewrite action dates in existing action order until dates are monotonic again.
