Boundary between AGENTS and the task prompt

The prompt should stay slice-local: the current task, the file boundary, the done-when state, the validation command, any inventory target, and the completion contract.

Repo truths to preserve

  • HyperBook is the abstract page-and-link substrate; HyperDoc is the documentation-oriented realization layered on top of it.
  • Keep authored pages, stable topic objects, and live runtime objects distinct unless the slice explicitly bridges them.
  • When a slice touches Connect, Dock, Annotation, Touch-Fahrplan, or DMX association authoring, keep the Touch-Fahrplan-first route metaphor durable: topics are stations, associations are routes between stations, the route is itself first-class, and Lay route is the preferred user-facing label.
  • Use drag-to-connect only for low-level mechanics and two-tap route-laying for the non-drag fallback; do not use plain swipe as the canonical term.
  • Preserve the distinction between laying a route and following a route, and keep richer route/traversal UI in the pane body or another dedicated surface while the Dock remains the capability-introduction layer.
  • For touch-first McCLIM slices, treat the gesture grammar as the operational form of Touch-Fahrplan route language: gestures are the input language, stations/routes are the conceptual layer, presentation-backed semantic objects are the nouns, CLIM commands are the verbs, and command execution is the only way application state changes.
  • Keep Browse mode safe by default: plain drag previews or reveals a route, while Lay route requires explicit press-then-drag or Author mode. Use drag-to-connect only for the underlying mechanic.
  • Interactive targets in this area should be presentation-backed doc-node, doc-link, doc-collection, doc-view, doc-anchor, doc-tool, doc-selection, or doc-blank-area objects, with dispatch handled through translators and command objects rather than hidden widget mutation.
  • Keep core :hyperdoc loadable without Zotero; optional Zotero behavior belongs in :hyperdoc/zotero and :hyperdoc/inspector/zotero.
  • HYPERDOC_ENABLE_ZOTERO is the authoritative runtime seam for Zotero; disabled mode should surface explicit unavailable objects rather than crashing or pretending live behavior exists.
  • Bibliography authoring is review-first: live/import objects and generated plans may propose materialization, but they must not silently rewrite authored pages or topics.lisp.
  • Keep deployment-aware seams explicit around public origin, reverse-proxy domain, data directory, git repository root, and optional Zotero enablement.

Stable handover rules

  • Use one Codex thread for one slice only.
  • Do not send placeholders when the task is already concrete enough to fill in.
  • Prefer an explicit file boundary over a broad subsystem request.
  • Keep AGENTS.md authoritative for repo-wide execution, validation, and environment-triage rules; do not restate long host-vs-repo-shell guidance in slice prompts.
  • When present, read repomix-output-hyperdoc.md first and treat it as the authoritative packed snapshot of the repo.
  • Prefer named validation surfaces and smoke checks over ad hoc success claims.
  • When authoritative repo-shell validation uses sbcl --eval, require ASDF before any asdf:load-system form: use --eval '(require :asdf)' first instead of making bare asdf: the first package read.
  • Prefer nix develop --command git ... when a prompt asks Codex to show repo diff or status.
  • Prefer fewer authored HyperDoc guidance files over preserving prompt iteration history as durable pages.
  • Keep adjacent documentation edits tightly coupled to the slice that justified them.
  • Ask for exact validation outcomes rather than generic success language.
  • When prompts describe route authoring, prefer Touch-Fahrplan route-laying language over generic connect/swipe/provider-first wording.

Touch-first prompt-local rule

When a slice touches touch-first McCLIM interaction, keep the prompt-local form shorter than AGENTS.md but preserve the same route-language primacy: Touch-Fahrplan stations/routes first, gesture grammar second, command dispatch as the semantic authority, safe Browse-mode defaults, and explicit distinction between route preview, Lay route, and Follow route.

  • Prefer Touch-Fahrplan wording first: stations, routes, Lay route, Follow route, route preview. Use drag-to-connect only as the mechanic term and two-tap route-laying as the non-drag fallback.
  • Use doc-node, doc-link, doc-collection, doc-view, doc-anchor, doc-tool, doc-selection, and doc-blank-area as the semantic target vocabulary.
  • Use the normalized gesture names from AGENTS.md, including hd-tap, hd-double-tap, hd-press, hd-drag, hd-swipe-*, hd-pinch-*, hd-two-finger-tap, hd-lasso, and hd-scrub.
  • Map gestures to CLIM commands rather than direct UI mutation: tap focuses, double-tap opens, press shows actions, plain drag previews or reveals a route, press-then-drag lays routes, tap on a route follows it, and blank-area gestures handle safe navigation and clearing.
  • Keep destructive or authoring semantics off plain tap; relation creation requires explicit arm state or Author mode.
  • Frame implementation in McCLIM terms: presentation-backed output, translators, gesture names, pointer tracking, command objects, and redisplay.
