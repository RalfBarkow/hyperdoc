Source claim

The life cycle of collective knowledge does not stop at preservation. It also requires forms of software publication that remain intelligible and reusable across time.

This page anchors Konrad Hinsen's FedWiki note on how collective knowledge is published, reviewed, cited, combined, and eventually detached from its original representation. The central claim is that collective knowledge depends on representations that stay usable long enough to be reviewed, recombined, and carried forward. Natural-language documents often degrade gracefully across decades, but software source code is much more fragile because it depends on machines, runtimes, toolchains, and surrounding environments. Archiving old environments improves reproducibility, but the stronger demand for collective knowledge is interoperability across time: later work must be able to inspect, compare, and reuse earlier software components instead of only freezing them as historical snapshots. This is the point at which the FedWiki note connects directly to HyperDoc's long-term interest in Common Lisp. The note presents Common Lisp as an example of a stable, standardized, multi-implementation language whose software can remain usable over long spans of time.   • Refinement of information into knowledge: Information becomes knowledge when communities can inspect, cite, compare, refine, and recombine it through durable representations.
  • Digital fragility of software source code: Software source code is digitally fragile because its intelligibility and execution depend on machines, runtimes, toolchains, and surrounding environments.
  • Computational reproducibility is not enough: Archiving old environments preserves rerun capability, but collective knowledge needs more than frozen reproducibility snapshots.
  • Software interoperability across time: Long-lived software knowledge requires later systems to inspect, compare, and reuse earlier components across time instead of only preserving them as inert artifacts.
  • Stable software environments: Stable software environments provide the language, standards, and implementation continuity that let software remain usable across long spans of time.
