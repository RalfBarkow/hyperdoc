Source claim

The life cycle of collective knowledge does not stop at preservation. It also requires forms of software publication that remain intelligible and reusable across time.

This slice anchors Konrad Hinsen's note about how collective knowledge is published, reviewed, cited, combined, and eventually detached from any single original representation. For HyperDoc, the key consequence is that software publication must support later inspection and reuse rather than only archival preservation.

Reusable topic chunks

  • The Life Cycle of Collective Knowledge: Collective knowledge remains alive only when its representations stay usable long enough to be reviewed, recombined, and reused across time.
  • Collective knowledge: Collective knowledge is information that has been published, reviewed, cited, recombined, and carried forward beyond any single contributor or file format.
  • Refinement of information into knowledge: Information becomes knowledge when communities can inspect, cite, compare, refine, and recombine it through durable representations.
  • Digital fragility of software source code: Software source code is digitally fragile because its intelligibility and execution depend on machines, runtimes, toolchains, and surrounding environments.
  • Computational reproducibility is not enough: Archiving old environments preserves rerun capability, but collective knowledge needs more than frozen reproducibility snapshots.
  • Software interoperability across time: Long-lived software knowledge requires later systems to inspect, compare, and reuse earlier components across time instead of only preserving them as inert artifacts.
  • Stable software environments: Stable software environments provide the language, standards, and implementation continuity that let software remain usable across long spans of time.
