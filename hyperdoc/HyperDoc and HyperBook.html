Short answer

A HyperBook is the general framework: a collection of interlinked pages with a unique HyperBook id and page ids that are unique inside that HyperBook. HyperDoc is one specific kind of HyperBook used for this repository's documentation work.

The simplest way to say it is:

  • HyperBook is the abstraction.
  • HyperDoc is a concrete documentation-oriented realization of that abstraction.

What a HyperBook is

In the core HyperBook model, each HyperBook has a unique id and each page in that HyperBook also has a unique id. Links can point to pages in the same HyperBook or to pages in other HyperBooks, and the catalog ties those books together for cross-book navigation and backlink-style discovery.

That means HyperBook is not tied to one storage format, one authoring style, or one subject domain. It is the common model underneath many possible page collections.

What HyperDoc is

HyperDoc is a HyperBook whose authored pages live in the HyperDoc corpus and carry stronger documentation conventions. In the repository's own summary: HyperDoc uses page titles as page ids. That is the key simplification that makes authored documentation pages easy to write and link.

HyperDoc pages are durable architecture and guidance pages written in hyperdoc/*.html or hyperdoc/*.md. Markdown pages are converted to HTML and then processed like HTML pages. Authored pages can use HyperDoc's custom tags and link forms.

What HyperDoc adds beyond the generic HyperBook model

HyperDoc is not just "a bunch of pages". It adds several surface distinctions on top of the generic HyperBook mechanism.

  • Durable authored pages carry narrative explanation and operational guidance.
  • Topic objects in topics.lisp provide stable inspectable concept identities.
  • Inspectable runtime objects can be linked from pages without pretending they are the same thing as durable pages.
  • Parallel FedWiki twins can correspond to HyperDoc material without being literal HTML copies.

So HyperDoc uses the HyperBook mechanism, but it also defines editorial and runtime disciplines for how documentation, topic identity, and inspectable objects relate to one another.

Page versus topic versus runtime object

One source of confusion is that HyperDoc contains more than one kind of thing.

A HyperDoc page is an authored narrative surface. A topic object is a stable semantic handle exposed through the separate topics HyperBook. A runtime object is an inspectable live object reached through a suitable runtime link surface. These are intentionally related, but they are not the same layer.

Put differently: HyperBook gives the network shape, while HyperDoc defines a documentation architecture inside that network.

Why the distinction matters

If everything were treated as just "pages", HyperDoc would lose important distinctions between explanatory writing, stable topic identity, and live inspectable behavior. The repository explicitly treats those as separate surfaces so that navigation stays honest and contributors can see what kind of artifact they are looking at.

This is also why HyperDoc compares well to systems such as HyperCard: not because they are identical, but because the comparison clarifies HyperDoc's particular strengths. HyperDoc is especially strong at inspectability, cross-linking, and relating heterogeneous systems, whereas HyperBook by itself only names the general page-and-link architecture.

Rule of thumb

When you ask "is this HyperBook or HyperDoc?", use this test:

  • If you mean the abstract collection-of-pages model with ids, links, and a catalog, you mean HyperBook.
  • If you mean this repository's documentation system with authored pages, topic objects, inspectable runtime links, and related surfaces, you mean HyperDoc.
