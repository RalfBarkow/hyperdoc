Touch-Fahrplan view for Zotero topic enrichment

hyperdoc

This slice adds a Touch-Fahrplan topic view that treats the current HyperDoc topic as one station and a read-only Zotero source designator as another. In this metaphor, associations are routes between stations, and the route is itself a first-class topic/object rather than a disposable edge. The durable model is not a hidden pane-side live query. It is an explicit chain of inspectable objects: topic -> topic-source-route -> topic-enrichment-query-plan -> Zotero title query evidence -> topic-enrichment-report -> Touch-Fahrplan topic view.

Metaphor and action label

The preferred user-facing action label in this surface is Lay route. When one sentence needs both conceptual and mechanical layers, say Touch-Fahrplan route-laying gesture (implemented initially as drag-to-connect). A non-drag surface may instead use two-tap route-laying.

The resulting route remains compatible with DMX-style explicit participants. When role labels matter, the current topic station can be treated as player1, the source station as player2, and the route itself remains the first-class association object.

Model boundary

No hidden expr-style evaluation happens at render time. The Touch-Fahrplan topic pane renders a source palette and first lays a durable route to a selected source station. That action opens a durable topic-source-route object first. From that route, the user opens an inspectable topic-enrichment-query-plan that shows:

  • the source station / source designator
  • the Zotero source designator
  • the proposed query text
  • the match mode
  • the intended bridge and backend seam
  • the expected functions and inspectable objects on the execution path
  • execution readiness plus failure classification and repair hint when blocked

Only the explicit Run plan action crosses the live read-only Zotero boundary.

Durable route object

Each topic-to-Zotero route now authors a first-class route/association object through the general Connect instrumentation. The new Durable Touch-Fahrplan routes section on the pane lists every durable route that points from the current topic station to a Zotero source station, and the table keeps a stable identity for that route every time the pane renders.

  • The route object itself remains inspectable in the left column.
  • The center column opens the dom-relation-annotation handled by the Connect inspector, so you can treat the route like any other association topic/object.
  • The right column surfaces the authored note, giving you a place to attach future defects, patch-target cues, or review comments.

This keeps the durable association available even after reloads. The source palette now offers a visible Lay route control for sources that are not yet authored. A narrow compatibility shell may still surface this as Create durable route until runtime copy is updated, but the durable conceptual label is Lay route. That control persists the route definition through the same authored-data boundary and then opens the resulting route object. The Touch-Fahrplan pane therefore remains the normal Dock-level route-laying / Connect surface with extra behavior that exposes the enrichment plan before touching Zotero.

In the current slice, the authored durability lives in hyperdoc/topic-enrichment-route-data.lisp as *topic-enrichment-route-definitions*. Reload reifies that durable authored data into a topic-enrichment-route-definition, a topic-source-route, and the corresponding dom-relation-annotation. The runtime objects are therefore reconstructable from durable authored route data rather than persisted as heap objects.

Runtime authoring writes back into that same Lisp data file by replacing the *topic-enrichment-route-definitions* form. This is honest durable authoring, but it also means the working tree becomes dirty until the new authored route definition is committed.

First-slice source palette

The first slice keeps the source palette intentionally small. It exposes one inspectable source designator: Local Zotero library. That tile resolves through the existing make-default-zotero-library-bridge wrapper and therefore inherits the current optional-runtime and bounded-failure behavior.

Conservative matching rule

The default query text is the current topic title. The default plan uses :exact title matching first. A broader :loose follow-up plan is available only as a separate explicit inspectable object.

This keeps the topic view from overclaiming semantic equivalence from weak Zotero matches.

Report structure

The resulting topic-enrichment-report keeps evidence and editorial consequence separate:

  • Evidence: Zotero title-query evidence, selected-attempt or missing-attempt normalization, and matched Zotero item objects.
  • Candidate signals: derived cues such as title, DOI, citation key, date, or item type from a single matched Zotero item.
  • Editorial consequences: explicit inspectable suggestions about what Zotero could add to the topic surface, without treating Zotero as editorial truth.

Bounded failure style

Zotero remains read-only and bounded. Unavailable backends, missing selected attempts, zero matches, and ambiguous matches become inspectable route, plan, or report surfaces rather than pane crashes.

Chunk walkthrough

  1. Open the topic page Chunk.
  2. Open the Touch-Fahrplan pane view.
  3. In Source palette, find Local Zotero library and click Lay route (or the current compatibility label Create durable route where that copy has not yet been renamed).
  4. Inspect the returned topic-source-route, then inspect its Route definition row if you want the durable authored entry itself.
  5. Click Open exact plan and inspect the execution path.
  6. Use Run exact plan or the plan inspector's Run plan action to execute the read-only title lookup.
  7. Inspect the resulting report and the inline latest-successful summary on the topic pane.
  8. Reload or restart HyperDoc, reopen Chunk, reopen Touch-Fahrplan, and reopen the same durable route from Durable Touch-Fahrplan routes. It reappears because the authored route-definition entry is read back from hyperdoc/topic-enrichment-route-data.lisp.
