Zotero attachment path resolution

hyperdoc

Attachment path resolution is the boundary where HyperDoc turns Zotero attachment metadata into a concrete local path or a typed failure. This slice supports only two path kinds: stored attachments under the Zotero storage root and linked file attachments that already point at a local path.

Stored attachments

Stored attachments use Zotero's own storage tree. HyperDoc resolves them by combining:

  • the configured Zotero storage root
  • the bibliographic item and child attachment row
  • the attachment key
  • the path suffix carried after the storage: prefix
  • the normalized local pathname and existence check

If any part of that chain is missing, the result is a typed failure such as :missing-storage-root, :missing-attachment-key, or :stored-file-missing.

Linked file attachments

Linked file attachments are normalized directly from their recorded local paths. HyperDoc checks existence, but it does not invent replacements when the file is gone.

No fabricated paths

The bridge never guesses a location from title alone. A resolved path exists only when the Zotero attachment metadata plus the configured local roots are sufficient to derive one concretely.
