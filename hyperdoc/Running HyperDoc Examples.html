Running HyperDoc Examples

hyperdoc

HyperDoc examples are not run by clicking on source code text. They are run by clicking the small ► button that HyperDoc inserts before a top-level defexample form.

Examples should be understood as belonging to a scope object. In HyperDoc, that scope should be the ASDF system that owns the code and pages being explained. The current ► mechanism is therefore best read as the run action for one scoped example, not as a root-level global console.

In ASDF terms, this is not only editorial placement. The example is present because the source-file component that defines its defexample form was loaded as part of a system's load-op plan. That makes the system, not the HyperDoc root object, the natural owning scope for the example.

This repo also uses a layered example structure. Base examples belong to :hyperdoc, portable examples belong to :hyperdoc/examples, and ops-specific examples belong to :hyperdoc/examples/ops. That lazy example discovery boundary matters: a system-scoped Examples surface should only show the examples for layers that have actually been loaded into the current image. See Portable examples in HyperDoc for the boundary in repo-local terms.

For the ASDF model behind that placement, see Understanding ASDF Systems in HyperDoc. For the resulting examples/tests architecture, see ASDF Systems, Examples, and Tests in HyperDoc. Together, those pages explain why examples belong on system surfaces and why batch tests remain separate from single-example running.

The low-level rendering mechanism still lives in hyperdoc-explorer/examples.lisp, which extends html-inspector-views/standard:render-toplevel-cst for defexample.

In other words, the ► button is attached to a top-level form in the rendered source, but architecturally it belongs to the ASDF system whose load plan brought that form into the image.

What happens

  1. A HyperDoc page contains <source-of-function>...</source-of-function>.
  2. HyperDoc transcludes the source view for that function.
  3. If the transcluded top-level form is a defexample, HyperDoc adds a ► play button.
  4. Clicking ► runs the example and opens its result in a new pane.

Clicking the code itself does not run the example. The runnable affordance is the play button, not the source text.

For batch-oriented test running, see HyperDoc Test Runner. That page documents the HyperDoc test runner surface, which adds scoped test workflows without replacing the per-example run action.

For one focused terminal procedure around a narrow smoke-test entry point, see Running DMX Topic Proxy Smoke Tests.

Reloading the running image

If a page shows an example as undefined, the usual cause is that the running image was started before the new example function existed. In that case reload the system and reopen the page.

(progn (asdf:load-system :hyperdoc) nil)
