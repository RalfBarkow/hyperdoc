Topic arrangement in HyperDoc

hyperdoc

HyperDoc sometimes needs to preserve arrangement, grouping, or neighborhood among topics even when no semantic association should be claimed. An arrangement page is an authored documentation surface for capturing that editorial neighborhood explicitly.

What arrangement captures

  • centrality around one topic
  • adjacency among nearby topics
  • grouping into editorial clusters
  • ordered neighborhood
  • supporting external anchors that belong near the cluster

What arrangement does not claim

  • It is not a semantic association.
  • It is not a DMX runtime edge.
  • It is not a synchronization contract.
  • It is not automatic graph geometry.

How to represent arrangement in HyperDoc

The preferred authored forms are simple and explicit: ordered sections, grouped lists, central topic / nearby topics / external anchors blocks, and short editorial notes that explain why items are near each other.

This keeps the arrangement readable without pretending that every nearby item needs a typed relation.

When to use this

  • when screenshot or map geometry carries meaning
  • when topics belong together editorially
  • when proximity matters more than relation type

When not to use this

  • when a real semantic association should be modeled instead
  • when adjacency is accidental
  • when the page would become a noisy link dump
