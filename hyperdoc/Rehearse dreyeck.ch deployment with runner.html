Rehearse dreyeck.ch deployment with runner

Use the HyperDoc Lisp runner to print and rehearse the cautious deployment path before a real switch.

Inspectable objects

  • dreyeck runner rehearsal
  • Deployment command locality
  • Cautious nixos-rebuild activation sequence

Purpose

Make the first live deployment rehearsal explicit and reproducible from one operator-facing runner.

Prerequisites

  • Verify HyperDoc locally before deployment completed.
  • SBCL with :hyperdoc loaded (for example from nix develop).
  • Build/target host values available.

Context

Start in print-only mode, then run the non-destructive rehearsal path. Keep switch and rollback as explicit actions.

  • Run on local controller: :verify-dreyeck-local-flake, :dry-activate-dreyeck, :test-dreyeck, :verify-dreyeck-http, :switch-dreyeck, :rollback-dreyeck.
  • Run on dreyeck.ch via SSH from controller: :backup-dreyeck, :record-dreyeck-generation.
  • Public URL probes: :verify-dreyeck-http.

Steps

  1. Print the full cautious sequence first: 
    (hyperdoc::run-dreyeck-deploy-sequence
 :build-host "<linux-builder>"
 :target-host "<ssh-target>"
 :print-only t)
  2. Run the non-destructive rehearsal wrapper action (no switch): 
    (hyperdoc::run-dreyeck-deploy-action
 :rehearse-dreyeck
 :build-host "<linux-builder>"
 :target-host "<ssh-target>"
 :print-only nil)
  3. If rehearsal checks are good, run persistent activation explicitly: 
    (hyperdoc::run-dreyeck-deploy-action
 :switch-dreyeck
 :build-host "<linux-builder>"
 :target-host "<ssh-target>"
 :print-only nil)
  4. Rollback stays explicit: 
    (hyperdoc::run-dreyeck-deploy-action
 :rollback-dreyeck
 :print-only nil)

Result

You have a runner-driven rehearsal path that covers backup, generation recording, local verification, dry-activate, test, and HTTP checks without an implicit switch.
