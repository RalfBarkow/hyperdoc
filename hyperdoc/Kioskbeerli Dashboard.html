Current status

Overall status: blocked. The current blocker is Kioskbeerli Cross-Host Build Failure: the declared aarch64-linux SD-image target still needs a valid Linux builder or remote Linux builder.

The previous blocker, Kioskbeerli sdImage imageSize Failure, is corrected. Removing the obsolete sdImage.imageSize option moved the work forward, but it did not prove that the kiosk image builds, flashes, boots, or displays the landing page.

Dashboard status vocabulary: declared, blocked, corrected, missing evidence, verified, unknown.

Build evidence

Flash / boot evidence

Flash evidence is missing evidence. Boot evidence is verified for first boot only: the operator reported being logged in as nixos on the booted Raspberry Pi. This does not prove network reachability, kiosk-session startup, or landing-page display.

The next evidence to record separately is network reachability, kiosk-session startup, landing-page display after reboot, and any missing flash/build provenance.

Planner run

The Kioskbeerli planner is a SHOP3-like local plan object with named tasks, dependencies, preconditions, effects, status, and evidence paths. It is plan-only by default in kioskbeerli:kioskbeerli-planner-run. Individual tasks are inspectable objects such as (kioskbeerli:kioskbeerli-lookup-plan-task :boot-pi), which links to its plan/run, dependencies, dependents, progress records, and SCXML state link.

The plan records the corrected obsolete sdImage.imageSize problem and keeps the current blocker explicit: a suitable Linux builder is still required before the aarch64-linux image can be realized.

Behavioral state machine

The lifecycle chart is stored as kioskbeerli/kioskbeerli.scxml and parsed as the standalone inspectable object kioskbeerli:kioskbeerli-behavior-chart.

The chart distinguishes declared, corrected, blocked, image-built, flashed, boot-observed, network-verified, kiosk-running, visible, maintenance-ready, failed-with-evidence, and unknown states.

Project trace / record progress

The project trace records evidence and missing evidence explicitly in kioskbeerli:kioskbeerli-project-trace. The latest progress entry is available through kioskbeerli:kioskbeerli-latest-progress. The current lifecycle state after recorded progress is kioskbeerli:kioskbeerli-current-scxml-state.

Recording progress is an in-memory local operation. It records a trace entry; it does not run Nix, flash devices, open SSH sessions, mutate HTTP state, or write to DMX. In the standalone system the corresponding operators are kioskbeerli:record-kioskbeerli-progress and kioskbeerli:kioskbeerli-record-boot-observed. First-boot evidence is recorded narrowly; it applies PI_BOOTED and first-boot-observed without verifying the later network, kiosk-session, landing-page, record-evidence, or dashboard-status tasks.
