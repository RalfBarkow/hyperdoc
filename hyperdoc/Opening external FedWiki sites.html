Opening external FedWiki sites

The FedWiki inspector adds an “open external” title-bar action for wiki objects via views:title-bar-action-buttons. It used to pass (wiki-url ...) directly to clog:open-browser.

Chromium-class browsers are stricter about missing or implicit schemes than a Lisp-side URL helper. We also want to avoid scheme-relative URLs such as //host/..., which can behave badly across mixed-content or secure-context boundaries.

What we changed

The FedWiki method on views:title-bar-action-buttons now normalizes the URL before calling clog:open-browser.

  • Ensure there is an explicit scheme before parsing.
  • Accept only http and https.
  • Never emit a scheme-relative URL.
  • Guard against quri parsing a schemeless host/path as a path-only URI with host NIL.

That last point is the subtle one: (quri:uri "wiki.ralfbarkow.ch/") is treated as a path-only URI, not as a host, so quri:uri-host becomes NIL. The fix is to prepend http:// before parsing when the string has no scheme.

Code

Before:

(defmethod views:title-bar-action-buttons ((wiki fedwiki))
  (views:action-button html-inspector-views/standard:*icon-open-external*
    (views:thunk
      (clog:open-browser :url (wiki-url (domain-name-of wiki) "/")))
    nil))

After:

(defmethod views:title-bar-action-buttons ((wiki fedwiki))
  (views:action-button html-inspector-views/standard:*icon-open-external*
    (views:thunk
      (let* ((raw (wiki-url (domain-name-of wiki) "/"))
             (normalized
               (if (or (str:starts-with? "http://" raw)
                       (str:starts-with? "https://" raw))
                   raw
                   (format nil "http://~A" raw)))
             (uri (quri:uri normalized))
             (scheme (quri:uri-scheme uri))
             (host (quri:uri-host uri))
             (path (or (quri:uri-path uri) "/")))
        (when (and host
                   (member scheme '("http" "https") :test #'string=))
          (clog:open-browser
           :url (format nil "~A://~A~A" scheme host path)))))
    nil))

The helper wiki-url in hyperbook-fedwiki/utilities.lisp has historically returned http://... URLs. The inspector still needs to be defensive because title-bar actions are a browser boundary, and browser-safe URL handling is stricter than simple string concatenation.
