Opening external FedWiki sites

HyperDoc federates with Wiki sites that are not uniform about transport: some support HTTPS, some only HTTP. A fixed scheme breaks interoperability.

Upstream change: a07b7db (Konrad Hinsen, 2026-03-06).

Problem

  • Mixed HTTP/HTTPS deployments in the FedWiki neighborhood.
  • Choosing one scheme globally can fail for specific sites.

Previous behavior

  • URL construction used a fixed scheme path in core access points.
  • Behavior effectively assumed one scheme instead of site capability detection.

New behavior

On first contact (during sitemap loading), HyperDoc probes port 443.
If HTTPS is available, protocol stays "https".
If connection is refused, protocol is set to "http".

All later Wiki requests use (protocol-of wiki), including:
- /system/sitemap.json
- /system/plugins.json
- page .json/.html loads
- external browser links from inspector views

This maximizes interoperability while keeping a per-site stable protocol choice after initial detection.

JSON init fallback

A site can still fail after that first protocol choice if a supposed JSON endpoint such as /system/sitemap.json or /system/plugins.json returns HTML instead. HyperDoc now treats that as a recoverable FedWiki init boundary: it logs the original protocol/path context and retries JSON site-data discovery once over HTTP.
