Demonstrating DMX Topic Proxies in HyperDoc

hyperdoc

This page is the main walkthrough for demonstrating the new DMX topic proxy behavior directly inside HyperDoc. Use it to show both surfaces without collapsing them: authored topic pages in HyperBook topics and live DMX-backed runtime objects opened through expr links.

Demo 1: Live DMX runtime object

Open Concepts, DMX Topics, and Topic Maps, then click the runtime handle (dmx-topic-operational-definition). The same handle is also present on that page in its live DMX-backed runtime section.

In the inspector, explicitly show these tabs:

  • Overview: HyperBook, base URL, topicmap id, topic id, and the DMX webclient URL.
  • Raw fetched data: Topic JSON, Topicmap JSON, and Related topics JSON fetched for the proxy.
  • Relations: the related-topics table rendered from the fetched DMX data.

This click path is supposed to open a live DMX-backed hyperdoc::dmx-topic-proxy runtime object.

Demo 2: Topic page surface

Click the HyperBook topics link Prepare the AArch64 image. That opens a stable authored topic page in the separate Topics HyperBook surface, not the DMX runtime proxy inspector.

The topic page is still useful in the demo because it shows the documentary surface: the page title, summary, references, and backlinks remain stable authored material.

Demo 3: Compare both surfaces

Compare the topic-page link Prepare the AArch64 image with the runtime-object link (prepare-aarch64-image-topic).

  • Topic page: stable authored/documentary concept page in HyperBook topics.
  • Runtime object: live DMX proxy returned by the wrapper function and inspected through dedicated runtime views.

HyperDoc keeps both surfaces on purpose. The topic-page surface remains curated and rebuildable from authored topic factories; the runtime-object surface exposes live DMX-backed state and relations through the inspector.

Optional terminal verification

The browser demo is primary. If you also want a narrow terminal check, run the DMX topic proxy smoke test: 

nix develop --command sbcl --no-userinit --non-interactive \
  --eval '(require :asdf)' \
  --eval '(asdf:load-system :hyperdoc :force t)' \
  --eval '(load "tests/dmx-topic-proxy-smoke.lisp")' \
  --eval '(hyperdoc/tests:run-dmx-topic-proxy-smoke-tests)' \
  --eval '(uiop:quit 0)'
