What 919822 is for

Topicmap 919822 is the visible context-window shared blackboard for shared work. It is where operators and tools inspect current shared state, post guarded notes and handovers, continue saved workspace annotations, and route the next action. It is not a generic DMX mutation playground.

Stable rules

  • Keep writes on the guarded shared-workspace boundary documented in Using guarded workspace topic lifecycle tools.
  • Keep workspace assignment distinct from topicmap placement, as documented in Diagnosing DMX workspace assignment and topicmap placement.
  • Keep dry-run-first behavior wherever the live mutation contract is still uncertain.
  • Do not treat topicmap visibility as ownership.
  • Do not treat the workspace as a raw transcript archive; durable explanation belongs in HyperDoc pages.

Safe operating loop

  1. Read the current shared state first through DMX MCP server for shared workspace or the canonical routes in DMX machine-readable read paths.
  2. Choose the narrow path for the actual task instead of improvising a raw DMX write.
  3. After any live step, reread the topic or topicmap and keep durable conclusions in HyperDoc rather than only in the shared blackboard.

Which path to use

  • Read or inspect current shared state: use DMX MCP server for shared workspace and DMX machine-readable read paths.
  • Add or update guarded workspace notes or handovers: use Using guarded workspace topic lifecycle tools.
  • Continue a saved annotation after pending-auth: use continue_workspace_annotation from Using guarded workspace topic lifecycle tools; for storage and reopen semantics, see Workspace-native annotations in a DMX workspace.
  • Inspect one suspicious object: use Diagnosing DMX workspace assignment and topicmap placement.
  • Inspect the current repair set: use Diagnosing DMX workspace repair triage.
  • Backfill missing workspace assignment with explicit auth: use Using authenticated workspace assignment repair console or the guarded repair_workspace_topic_assignment path it documents.
  • Understand annotation storage and compatibility behavior: use Workspace-native annotations in a DMX workspace.
  • Understand auth modes and what they do not promise: use HyperDoc three-mode DMX auth crosswalk.

Do not confuse these

  • Topicmap placement vs workspace assignment: placement in 919822 is shared-blackboard visibility, while assignment to 919815 is workspace ownership.
  • Diagnosis vs mutation: diagnosis stays read-only; repair is the separate explicit-auth mutation path and not a general DMX login system.
  • Native annotation semantics vs current compatibility-carrier persistence: the save and reopen contract stays annotation-native even though current live persistence normally uses a dmx.notes.note compatibility carrier.
  • Shared blackboard vs durable HyperDoc documentation: topicmap 919822 routes current shared work, while stable explanations stay in HyperDoc pages.
