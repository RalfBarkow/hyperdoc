Canonical Route Discovery for Runtime Smoke Tests

HyperDoc runtime smoke tests should use discovered canonical routes instead of guessed paths. The server already owns the slug and path rules, so the smoke test boundary should ask the runtime for the page URL it actually serves.

What this slice distinguishes

  • In-process render: the object exists and renders in the current Lisp image.
  • Canonical HyperDoc page URL: the runtime has a stable routed page URL for a HyperBook page.
  • Canonical inspector object URL: some inspectable objects are directly addressable, but nested relation objects are not yet guaranteed their own stable route.

Inspectable objects

  • Canonical route discovery for Git history surface
  • Git History Surface for HyperDoc
  • Merge upstream/main into hauptsache via dreyeck fallback

Smoke-test procedure

  1. Resolve the route-discovery object in-process.
  2. Read the canonical page path or canonical page URL from that surface.
  3. Use that discovered URL for the HTTP smoke check.
  4. Treat a missing canonical inspector URL for a nested relation object as an explicit routing boundary, not as a guessed-path failure.
