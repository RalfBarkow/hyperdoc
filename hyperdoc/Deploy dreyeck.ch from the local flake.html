Deploy dreyeck.ch from the local flake

Use a cautious activation path: dry-activate, test, verify, then switch.

Inspectable objects

  • Cautious nixos-rebuild activation sequence
  • dreyeck supported deployment model
  • dreyeck local verification gate
  • dreyeck HTTP smoke probes

Purpose

Reduce deployment risk by validating activation behavior before making the target generation permanent.

Prerequisites

  • Verify HyperDoc locally before deployment has passed.
  • SSH access to the target host.
  • Linux build host available when controlling from macOS/non-Linux.

Context

hauptsache should be verified locally and deployed from the local flake; the server should not be repaired by checking out that branch directly. Run these commands on the local controller; they activate configuration on dreyeck.ch.

Steps

  1. Run cautious rebuild sequence: 
    nixos-rebuild dry-activate --flake .#dreyeck-ch --build-host <linux-builder> --target-host <ssh-target>
nixos-rebuild test --flake .#dreyeck-ch --build-host <linux-builder> --target-host <ssh-target>
  2. Verify service and key routes after test activation: 
    curl -I https://dreyeck.ch/boot.html
curl -I "https://dreyeck.ch/584FD-hyperdoc/Official%20Tutorial%3A%20NixOS%20SD%20Image%20on%20Raspberry%20Pi%204%2F400"
curl -I https://dreyeck.ch/hyperbook-server/js/url.js
  3. If checks are good, make activation persistent: 
    nixos-rebuild switch --flake .#dreyeck-ch --build-host <linux-builder> --target-host <ssh-target>

Operator command bundle

git status --short
nix flake check
nix run .#release-smoke

Result

The host is only switched after successful dry/test activation and HTTP verification.

Rollback/next step

If any step fails, follow Roll back HyperDoc on dreyeck.ch.
