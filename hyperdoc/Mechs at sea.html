Mechs at Sea

We consider how large Federated Wiki sites could be cached and synchronized over short messages on slow or even intermittent connections. The motivating case is ocean sailing, but the same approach could apply in other low-bandwidth environments.

Discussion context: matrix discussion

An admin-savvy sailor could cache whole sites onboard and proxy DNS to browse them while at sea. Public sites owned by the sailor could then be updated from cache when they return to port.

One proposed direction is to design Mech blocks that synchronize the cache over ham radio by sending only journal actions. That same pattern could also support server-side Mechs for other low-bandwidth applications.

How Mechs talk

A specific Mech is identified by site, slug, and item id. A Mech that includes GET or PUT blocks can both send and handle those requests. The sender runs client-side, while the handler runs server-side.

A Mech is connected to its twin when forked from the serving site. When the Mech runs GET client-side, the nested blocks run server-side on the remote site. Similarly for PUT.

One example is an additional block named DELTA that collects changes when run client-side and distributes changes server-side.

Example: sending changes

CLICK
 NEIGHBORS self
 DELTA daily actions
 PUT
  DELTA expand
  APPLY

The reverse direction uses GET and moves the two versions of DELTA around.

Example: receiving changes

CLICK
 GET
  NEIGHBORS self
  DELTA daily actions
 DELTA expand
 APPLY

The server-side handlers could also be implemented by other applications, such as DATALOG, as long as they match the protocol requirements. In that case, the client-side run of the Mech acts as a test that the endpoint works as intended.

This implementation would stay inside the Mech plugin itself. The existing server-side routing is already sufficient to support this pattern. Other protocols have already been implemented as server-side plugins, notably RSS.

The ham-radio connection suggested above would first be implemented on the live internet and then bridged to Winlink Global Radio Email for operation at sea. Wikipedia: Winlink
