Current live local evidence

On the current machine, the live Zotero collection lookup resolves coachmark to the collection path A – B – C – D – E / C / coachmark. That is machine-local runtime evidence from the current Zotero library, not a repo-global truth. The inspectable subcollection object remains the authoritative surface.

What the plan distinguishes

  • Collection-name evidence: the Zotero collection/subcollection name coachmark is preserved as provenance and can seed a candidate topic cue.
  • Entry-derived evidence: titles, tags, notes, venues, and other parsed bibliography-entry fields can independently support or weaken candidate topics.
  • Editorial outcome: the plan records whether each candidate should merge into an existing topic, become a new topic/page scaffold, or remain only as arrangement or continuity-shell mention.

That separation prevents an accidental rule such as “every Zotero collection name becomes a topic.” Instead, the collection name is one inspectable cue among others.

In inspector terms, collection-name evidence and entry-derived evidence stay visible as separate supporting surfaces before any final authoring decision.

Coachmark-specific first-slice outcome

In the fixture-backed smoke path, the plan can justify candidates such as Coach marks, Onboarding, User onboarding, Help overlays, Guided tours, and Mobile onboarding. The resulting decisions deliberately differ:

  • some candidates become proposed new topic/page scaffolds
  • some merge or normalize against existing Topics HyperBook titles
  • some remain arrangement-only mentions because they are scoped variants of a broader candidate

This keeps the slice narrow and reviewable rather than turning one Zotero subcollection into a giant automatic page dump.

How to inspect the distinction

  1. Open (coachmark-bibliography-subcollection) and inspect the collection summary, entries, and candidate topics.
  2. Open (coachmark-bibliography-authoring-plan).
  3. In the Page write/update plan view, read each decision as a compact record: decision kind, matched existing topic/page if any, grouped evidence, rationale, and materialization consequence.
  4. In the Materialization preview view, compare the bundle target path against the proposed later repo touch, such as hyperdoc/topics.lisp or a specific hyperdoc/<Title>.html page.

Relation to the Topics model

The comparison step stays title-first. It checks the current Topics HyperBook and hyperdoc/topics.lisp for exact existing titles first, then alias or near-duplicate normalization, then broader-topic review. Only after those checks fail does the plan treat a candidate as genuinely new.
