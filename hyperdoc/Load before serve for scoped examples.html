Load before serve for scoped examples

The rule in this repo is simple: Portable examples and ops-specific examples are only discoverable if their ASDF systems are loaded before the service begins serving HyperDoc.

Inspectable objects

  • Load before serve for scoped examples
  • Portable examples
  • Example system boundary
  • Lazy example discovery
  • HyperBook server vs HyperDoc server load set

Why this rule exists

HyperDoc models examples as system-scoped, load-dependent exploratory slices. That means service parity depends on the startup load set, not only on serving the same URL routes.

Operational reading

If a deployed image should expose portable and ops examples, the startup path must load the systems that own those examples before calling serve-catalog.

What this avoids

  • manual rescue loads after startup
  • misdiagnosing under-loading as a discovery bug
  • overbroad root-level example ownership
