Tree of Closures in Magma2

hyperdoc

Turini's Magma2 backtracking environment makes control state explicit. A suspended computation is represented by a closure; a context is represented by a node that points to such a closure; and the active control state is a tree of those nodes plus a stack of re-entry nodes.

“a tree of closure is actually implemented as a tree, whose nodes are pointers to closures.”

The point is not merely that the implementation happens to use pointers. The pointer structure is the control abstraction. Returning, choosing, retrying, and failing can be expressed by moving among nodes and by selecting the closure stored at a node.

Source context

In the backtracking control environment, closures that have performed a recursive call are not simply popped when executed. They can still belong to an older saved context. That is why the control structure grows from a stack into a tree. The backtracking stack then contains nodes in that tree, not copied computations.

Vocabulary for the examples

  • closure: an executable suspended computation that remembers an agent, local store, and continuation point.
  • node: a heap object whose payload is a pointer to a closure.
  • FTREE: the tree of closure nodes.
  • CURNODE: the current node in the active recursive stack.
  • BSTACK: a stack of nodes that can be re-entered after failure.

1. A node points to a closure object

Click: run the pointer example. Observe: two distinct nodes can refer to the same closure object. Why this matters: a tree node is not the computation itself; it is an addressable control object whose payload is an executable closure.

2. A recursive stack is a path in the tree

Click: run the recursive-path example. Observe: the active recursive stack is represented as a path from the current node back through its fathers. Why this matters: a stack is a special case of the closure tree. Once choices introduce saved contexts, several stack paths can share earlier nodes.

magma2-closure-tree-recursive-path-example

3. A failure resumes a node from the backtracking stack

Click: run the backtracking example. Observe: FAIL chooses a node from BSTACK, restores its father as CURNODE, and returns the closure stored in the chosen node. Why this matters: the control environment resumes by following object identity in the tree, not by reinterpreting the source program from scratch.

magma2-closure-tree-backtracking-example

4. Context sharing

Click: run the sharing example. Observe: two saved contexts share their prefix node. Why this matters: the tree lets the control environment preserve several possible futures without duplicating the whole recursive stack for every future.

Teaching choreography

  1. Start with the pointer example: a node contains a reference to executable state.
  2. Show the recursive path: a stack is a path through parent links.
  3. Add a second branch: saved contexts share prefix nodes.
  4. Finish with failure: backtracking selects a node and re-enters its closure.
