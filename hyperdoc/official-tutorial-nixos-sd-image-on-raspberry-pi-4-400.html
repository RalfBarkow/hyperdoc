Official Workflow

  1. Download a prebuilt nixos-sd-image-*-aarch64-linux.img.zst.
  2. Decompress the downloaded .zstd artifact to a raw .img artifact.
  3. Flash the .img artifact to an SD card.
  4. Boot the Raspberry Pi 4 or Pi 400 from that card.
  5. Connect to the machine and edit /etc/nixos/configuration.nix.
  6. Run nixos-rebuild boot.
  7. Reboot into the new generation.
  8. Only later use nixos-rebuild switch once the system is known to reboot safely.

Missing-step diagnosis (resolved)

A decompression step is missing between the download step and the flashing step. This is a relation defect: step 1 produces .zstd while step 2 requires .img. The patch target is therefore the handoff between these steps, not either step in isolation.

Filename-preservation handoff diagnosis (resolved)

For Hydra latest/download/1, plain wget "$LATEST_URL" can produce a file named 1. The decompression step expects a named .img.zst artifact. The download/decompress handoff therefore needs an explicit filename-preservation guarantee.

  • Historical broken download state: plain wget on the indirect latest URL may save as 1.
  • Corrected current download state: use wget --trust-server-names "$LATEST_URL" so wget adopts the redirected URL filename and saves a named .img.zst artifact.
  • Mechanism in this path: the redirect target URL ends with nixos-image-sd-card-*.img.zst; filename preservation comes from trusting redirected server names.
  • Postcondition after download: local directory contains nixos-image-sd-card-26.05pre958961.aca4d95fce49-aarch64-linux.img.zst (1377718373 bytes) and does not require manual rename from 1.
  • Post-decompression state: unzstd -d nixos-image-sd-card-*.img.zst produces nixos-image-sd-card-26.05pre958961.aca4d95fce49-aarch64-linux.img (3490607104 bytes), and both .img.zst and .img may be present.
  • Operational distinction: .img.zst is preserved download artifact identity; .img is the flash input.
  • Defect object: official-hydra-latest-filename-handoff-defect
  • Patch target object: official-hydra-latest-filename-handoff-patch-target

The decisive point in the tutorial is that NixOS is already installed in the SD image. The first task after flashing is configuration and rebuild, not installation.

Representative Configuration

The official path assumes a configuration shaped roughly like this: 

{ config, pkgs, ... }:
{
  boot.kernelPackages = pkgs.linuxKernel.packages.linux_rpi4;
  boot.loader.generic-extlinux-compatible.enable = true;

  fileSystems."/" = {
    device = "/dev/disk/by-label/NIXOS_SD";
    fsType = "ext4";
  };

  fileSystems."/boot" = {
    device = "/dev/disk/by-label/FIRMWARE";
    fsType = "vfat";
  };

  networking.networkmanager.enable = true;
  networking.wireless.enable = false;

  services.openssh.enable = true;

  users.users.kiosk = {
    isNormalUser = true;
    extraGroups = [ "wheel" ];
  };

  hardware.enableRedistributableFirmware = true;

  system.stateVersion = "24.11";
}

Secrets such as Wi-Fi credentials and SSH keys should be added locally, not copied from documentation.

Implicit Invariants

  • The flashed image must actually be an official SD image, not an arbitrary installer or reused card layout.
  • /boot must be large enough for kernel, initrd, and extlinux state to be written safely.
  • The labels FIRMWARE and NIXOS_SD must match the mounted partitions.
  • The correct first rebuild mode is boot, not switch.

Failure Modes That Matter Early

  • /boot too small for a new generation
  • missing or truncated /boot/extlinux/extlinux.conf
  • wrong partition labels or reused non-NixOS image layout
  • mixing SD-image workflow commands with installer workflow commands
