Why this matters for HyperDoc

HyperDoc is aligned with moldable development and explainable tooling. GT is already acknowledged in HyperDoc as a reference platform in that space. Installation guidance here keeps the durable distinction clear: use GT from packaged binaries, or install from source when developing GT itself.

Two acquisition modes

  1. Ready-made distribution (default for using GT).
  2. Clone and install latest code (for developing GT itself).

Ready-made distribution

The packaged distribution is the normal way to start using GT. Use the official download page as the entry point: https://gtoolkit.com/download/.

Clone and install latest code

Upstream describes this as the path that installs the VM, clones GT from GitHub, and builds an image. It is useful when developing Glamorous Toolkit itself.

Current upstream source-install commands: 

Mac:
curl https://dl.feenk.com/scripts/mac.sh | bash

Linux:
curl https://dl.feenk.com/scripts/linux.sh | bash

Windows:
wget https://dl.feenk.com/scripts/windows.ps1 -OutFile windows.ps1; ./windows.ps1

When to choose which path

  • Choose ready-made distribution when you want to use GT now with minimal setup.
  • Choose source install when you need latest code and contributor/developer workflow for GT itself.

Relation to Moldable Development

The GT GitHub repository describes GT as the Moldable Development Environment and states that it is built in Pharo and Rust. This fits HyperDoc's own focus on explainable, contextual tools.
