Paper Vocabulary Now Named Locally

Chunk

The paper page now imports chunk directly as a piece of information in a particular state, form, or location. That matters in HyperDoc because a source file, an in-image registry entry, and a loaded handler subset are not interchangeable just because they concern the same code.

Basis / Update Basis / Deriver

The local operational notes now use the paper's dependency vocabulary explicitly: basis, update basis, and deriver / derive. The relevant local anchors are Core Chunk Classes and Make the issue repair function disappear as the primary abstraction.

Managed vs Dormant

The paper's distinction between managed and dormant chunks is a good fit for HyperDoc's long-lived runtime. Some state is under active maintenance and must stay coherent; other state may exist locally but is not currently being kept current by the coherence machinery.

Up-to-date / Freshness

The imported freshness claim is that up-to-date is a dependency relation, not mere continued existence. A derived chunk can survive in the image and still be stale if a supporting chunk is fresher. That is the bridge from McDermott's paper into HyperDoc's runtime reload and repair discussions.

Where the Vocabulary Lands in HyperDoc

  • A framework for maintaining the coherence of a running Lisp: narrow paper-based import of chunk definition, given/derived chunks, and freshness semantics
  • Core Chunk Classes: local kernel for chunk, basis, update basis, derive, derive-date, and up-to-date logic
  • Make the issue repair function disappear as the primary abstraction: application of the same model to issue repair and runtime registration
  • Source-oriented and image-oriented development in Common Lisp: separate boundary page for rebuild authority and durable source

Boundary To Preserve

The crosswalk should sharpen one distinction, not blur it. Running image coherence is about internal consistency and freshness inside an evolving live Lisp. Live image versus durable source is about which artifacts remain authoritative for rebuild and audit. The paper contributes vocabulary for the first problem. It does not erase the second.
