Using SHOP3 Planning in HyperDoc

hyperdoc

This page explains how to use the optional SHOP3 planning slice in HyperDoc. The slice is intentionally plan-only: it asks SHOP3 to propose ordered maintenance plans and then projects those plans into inspectable HyperDoc objects. It does not edit files, run shell commands, mutate DMX, run tests, or commit changes.

Loading boundary

The root :hyperdoc system must remain independent of SHOP3: 

(asdf:load-system :hyperdoc)

The optional planning layer is loaded explicitly: 

(asdf:load-system :hyperdoc/shop3)

In this local development image, SHOP3 is registered narrowly. The important rule is to expose only the planner source and PDDL tools, not the whole checkout as an ASDF tree. 

(asdf:initialize-source-registry
 `(:source-registry
   (:tree "/Users/rgb/workspace/hyperdoc/")
   (:directory "/Users/rgb/workspace/shop3/shop3/")
   (:directory "/Users/rgb/workspace/shop3/jenkins/ext/pddl-tools/")
   (:directory "/Users/rgb/workspace/shop3/jenkins/ext/fiveam-asdf/")
   :inherit-configuration))

Basic use

The central entry point is run-hyperdoc-asdf-refactor-plan-object. It returns a hyperdoc-htn-plan-result object. The checklist projection turns the SHOP3 plan into a HyperDoc-friendly manual runbook. 

(defparameter *plan*
  (hyperdoc/shop3:run-hyperdoc-asdf-refactor-plan-object))

(hyperdoc/shop3:hyperdoc-plan-checklist *plan*)

The result is a nine-item checklist. Every item includes :manual? t, making the non-execution boundary explicit.
