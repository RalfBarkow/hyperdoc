What it is

The Tectonopedia repository describes itself as the Tectonic reference encyclopedia. Its content is primarily technical documentation authored in TeX and published as a web application rather than a print-oriented manual.

Build / publication pipeline

The documented structure separates authoring, compilation, and frontend publication. Rust code in src builds the tectonopedia program. That program compiles TeX source in txt into raw HTML, CSS, and related outputs in build. Parcel then combines those outputs with frontend code in web into the published web application. The repository also documents a local development command: cargo run --release -- serve --open.

Why it is relevant to HyperDoc

  • It treats documentation as authored source material rather than plain prose.
  • It turns that source into a navigable published artifact instead of a static PDF.
  • It shows one way to build a documentation system with encyclopedic ambitions.
  • It keeps computation-adjacent structure in the authoring and build pipeline, even though the result is a web publication surface.

Boundaries: where it overlaps and where it differs

  • Overlap: both HyperDoc and Tectonopedia treat documentation as structured source that can be transformed into a navigable web surface.
  • Overlap: both care about reference-style knowledge systems rather than only linear manuals.
  • Boundary: Tectonopedia is centered on a TeX-to-HTML publication pipeline, not on live in-image object inspection.
  • Boundary: Tectonic maintainers describe the HTML machinery as still in development and requiring TeX authored for HTML processing.
  • Boundary: Tectonopedia is not a moldable inspector environment or a live object browser in the GT/HyperDoc sense.
