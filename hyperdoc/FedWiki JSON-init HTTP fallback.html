FedWiki JSON-init HTTP fallback

Some FedWiki sites expose a page over HTTPS well enough to answer a request, but their supposed JSON discovery endpoints can still return HTML. When HyperDoc asks for /system/sitemap.json or /system/plugins.json and gets leading < instead of JSON, shasht raises shasht-invalid-char.

Inspectable objects

  • FedWiki JSON-init HTTP fallback

Old divergence

Before commit 97b1ce7, the normal FedWiki browsing path and the DMX importer did not share one recovery rule. Normal make-fedwiki initialization only logged the format failure and left the wiki status unusable, while the importer had its own HTTP retry path.

Current rule

FedWiki site-data initialization now has one shared recovery seam. When sitemap or plugin JSON discovery fails with a network-init/read-format condition such as shasht-invalid-char, HyperDoc logs the original protocol, path, and stage, then retries site-data discovery once over http.

If the HTTP retry succeeds, the wiki remains usable and keeps the recovered final protocol http. If both attempts fail, the status remains the captured error condition.

Explicit exception

Manually constructed or explicit test wiki objects are not silently pushed through automatic network fallback. That exception keeps in-memory fixtures and explicit importer tests stable instead of turning them into accidental live-network probes.
