Mobile progressive chrome in HyperDoc

hyperdoc

Mobile HyperDoc chrome follows the existing Dock rule: degrade chrome, not capability. On narrow viewports, the capabilities layer starts collapsed behind )(, and the inspector tabs layer starts collapsed behind a rotated )(.

Operational contract

  • Capabilities closed: only )( is visible. Connect, Annotation, Guide, and route guidance are hidden, and page-body taps are normal document actions.
  • Capabilities open: Connect, Annotation, and Guide are visible, but route capture is still inactive.
  • Route capture: only choosing Connect enters route-introduction. Then Tap a station can latch a source and From: appears.
  • Ordinary links: links remain ordinary links until route capture is active. In route mode, an anchor can be treated as a route endpoint because the user explicitly chose Connect.
  • Inspector tabs: the rotated )( opens the existing tab row. Selecting a tab changes the active tab, then collapses again on narrow viewports to restore vertical space.

State composition

The high-level Dock states remain latent, introduction, active, degraded, and rediscovery. They now compose with two mobile layers: capabilities-collapsed/open and tabs-collapsed/open/tab-selected. The route substates start only after CONNECT_CHOSEN.

The state model answers why chrome is visible, whether page-body taps are document actions or route-laying station taps, which transition started route capture, and how to return to normal document interaction.

SCXML and plan artifacts

(mobile-progressive-chrome-scxml-artifact) exposes the SCXML-like behavior model at hyperdoc/mobile-progressive-chrome.scxml. It records the events, guards, and invariants for capabilities, inspector tabs, and route capture.

(mobile-progressive-chrome-plan) exposes the SHOP3-like implementation plan with task status, implementation evidence paths, validation evidence paths, and dependency ids.

Proof page boundary

The DM6 inline proof page remains readable and navigable with JavaScript disabled. With JavaScript enabled, the mobile chrome is progressively enhanced; it does not change the DM6 AppEmbed schema, DMX persistence, or the page-local DM6 seed.
