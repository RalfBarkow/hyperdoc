s-graphviz Dependency Boundary

hyperdoc

The current s-graphviz problem is not a generic ASDF registry issue. It is a real dependency boundary in the HyperDoc stack.

What is required

html-inspector-views/standard depends on s-graphviz.

This is visible in the local source tree:

  • html-inspector-views.asd declares #:s-graphviz
  • s-graphviz.lisp provides the integration layer
  • system and dependency views call Graphviz-related support functions

So s-graphviz is not an optional shell extra in the current design.

What went wrong

The packaged Nix version of s-graphviz currently fails with a circular dependency involving literate-lisp.

Removing s-graphviz from the HyperDoc dev shell was therefore the wrong fix. It only changed the failure mode from:

  • broken s-graphviz load

to:

  • missing dependency for html-inspector-views/standard

In other words, the system did not become healthier. The dependency simply became absent instead of broken.

Why this matters

This is a useful example of a credible maintenance boundary. The problem is not “some shell package is inconvenient”. The problem is that the current runtime design really expects Graphviz support to be present.

That means any fix must address the dependency boundary itself.

Current boundary

  • s-graphviz must remain in the dev environment as long as html-inspector-views/standard requires it.
  • The packaged Nix s-graphviz is currently broken in this environment.
  • No local checkout of s-graphviz or literate-lisp is currently available for override.

Real next options

  • Provide a working source checkout of s-graphviz and likely literate-lisp, then override it in the ASDF source registry.
  • Patch html-inspector-views so Graphviz support becomes optional instead of a hard ASDF dependency.

The first option is operationally smaller. The second option is the cleaner architectural change, but it reaches into a dependency boundary rather than only the local dev shell.

Pragmatic conclusion

The immediate local correction is simple: keep s-graphviz in the dev shell. The actual repair still remains open.
