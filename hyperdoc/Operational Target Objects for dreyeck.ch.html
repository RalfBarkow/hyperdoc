Operational Target Objects for dreyeck.ch

hyperdoc

This first slice turns a live NixOS server target and two Git remote operations into inspectable objects. The goal is narrow: model the target and materialize the exact shell blocks to run, without implementing remote execution yet.

The live target here is dreyeck.ch with the HyperDoc checkout rooted at /home/rgb/workspace/hyperdoc/. The two first operations are the ones needed for the current missing-upstream-history problem on the Dreyeck Extraction page: add Konrad's remote if missing, then fetch upstream/main.

  • dreyeck-ch-add-konrad-upstream-remote-operation

What this first slice models

  • a nixos-host-target with host identity, checkout root, service name, and deployment mode,
  • a git-remote-operation with remote name, remote URL, branch, and operation kind,
  • a materialization view that renders the exact shell block to run on the host.

Intentional limits

  • No SSH execution from HyperDoc yet.
  • No automatic remote discovery or mutation.
  • No host-state capture yet; this slice only models and materializes the commands.
