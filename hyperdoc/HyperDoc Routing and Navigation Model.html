Why a routing model matters

HyperDoc navigation spans local pages, linked hyperbooks, and remote page stores. Explicit routing rules reduce ambiguity and prevent category mistakes when the same visible title can map to different storage keys or contexts.

Slugs, pages, and navigation targets

A navigation target is resolved from an explicit page key in a specific context. In FedWiki-linked contexts, slug/file keys are the stable routing target. Titles are display labels and may not be unique routing identifiers.

Local navigation vs remote navigation

  • Local navigation: opens pages in the local HyperDoc catalog using local page keys.
  • Remote navigation: opens pages through a named hyperbook context where key resolution belongs to that source.
  • Cross-context rule: keep source context explicit so local and remote lookup semantics do not collapse.

Pane and context behavior

Navigation occurs in pane/context structures where each pane keeps object state and view context. Opening a target in the same pane or a new pane is an interaction decision, but target resolution still depends on explicit source context and page key.

Opening local HyperDoc pages

  • Use local page keys for deterministic lookup in the HyperDoc catalog.
  • Prefer explicit links between architecture pages to keep routes stable.
  • Use inspectable objects when navigation should also expose runtime handles.

Opening remote FedWiki pages

  • Use explicit hyperbook context plus slug-based page key for lookup.
  • Do not rely on visible title text as a routing key when a slug exists.
  • Treat remote page access as linked context traversal, not local page substitution.

Routing boundaries and responsibilities

  • Page authoring layer: chooses explicit navigation targets and context.
  • Routing layer: resolves target keys in the correct local/remote source.
  • Inspector/UI layer: controls pane behavior after resolution.
  • Boundary rule: routing semantics and display labels remain distinct concerns.

Known confusion points and historical failure modes

  • Title/slug ambiguity: title links can fail where slug keys are required.
  • Context collapse: local and remote targets treated as if they shared one lookup namespace.
  • Pane confusion: interaction behavior mistaken for routing failure when resolution context is wrong.
