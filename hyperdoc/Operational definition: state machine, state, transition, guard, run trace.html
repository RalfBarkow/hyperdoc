Operational definition: state machine, state, transition, guard, run trace

hyperdoc

A state machine is a bounded transition object that defines a finite set of named states, the admissible transitions among them, the events or predicates that trigger those transitions, and the evidence-bearing trace of any concrete traversal through the machine.

In HyperDoc, a state machine must exist at two levels:

  1. a reusable definition object
  2. a concrete run object

Required object split

  • state-machine-definition: id, title, summary, states, transitions, initial state, terminal states, guards, events, invariants, failure states, source evidence, notes
  • state-machine-run: machine, input, current state, visited states, transition trace, evidence trace, start time, end time, status, failure classification, notes

Rules

  • Distinguish definition objects from run objects.
  • Every transition must reference known states.
  • Initial state must be exactly one unless the machine explicitly allows multi-initial behavior.
  • Terminal and failure states must be typed explicitly.
  • Evidence must be attachable at state-entry and transition points.
  • Visualization must be derived from the object, not hard-coded page prose.

Worked example boundary

The DMX auth crosswalk is a worked example instance of this abstraction. It remains a bounded auth-path teaching object, but it no longer defines the machine model itself.
