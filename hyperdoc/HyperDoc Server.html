HyperDoc Server

hyperbook/server

This page explains the practical path for serving HyperDoc from the local web server used in this repository.

What runs

The runtime entry point is hyperbook/server:serve-catalog. The compatibility system hyperdoc/server depends on hyperbook/server, so loading :hyperdoc/server or :hyperbook/server reaches the same server implementation.

The server exposes a HyperBook catalog at the root path and assigns one URL path per registered HyperBook.

Fast path

For normal local use, start the development launcher from the repository root: 

./dev.sh

Then open: 

http://127.0.0.1:8080/boot.html

The launcher enters the Nix development shell first, so the Common Lisp source registry and other runtime dependencies are configured before SBCL is started.

Manual start

If you want to start the server directly, load the server system and call serve-catalog yourself: 

sbcl --no-userinit \
  --eval '(require :asdf)' \
  --eval '(asdf:load-system :hyperbook/server)' \
  --eval '(hyperbook/server:serve-catalog)'

The default server URL is still http://localhost:8080/boot.html.

Development mode

The server supports a development flag via HYPERDOC_DEVELOPMENT or the :development argument to serve-catalog and hyperbook/server:serve-hyperbooks.

In development mode, the Playground is executable and additional debugging tools are enabled. The view remains visible outside development mode, but code evaluation is disabled.

What appears in the catalog

On startup, the server now ensures the core built-in HyperBooks needed for a useful local session:

  • HyperDoc
  • HyperDoc Explorer
  • Moldable inspector
  • Wikipedia (English edition)

Additional external books can be loaded from the known-wikis configuration file: 

~/.config/hyperbook/known-wikis.sexp

Example: 

(("fedwiki:wiki.ralfbarkow.ch")
 ("fedwiki:hyperdoc.dreyeck.ch"))

Each configured id is resolved through hyperbook:find-hyperbook during startup.

URL structure

Each registered HyperBook gets a slug-based URL. The catalog is the root, and individual books and pages appear below their slug. The URL view in the inspector shows the exact generated path for a HyperBook or page.
