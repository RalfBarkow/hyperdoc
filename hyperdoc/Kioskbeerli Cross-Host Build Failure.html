Kioskbeerli Cross-Host Build Failure

The next concrete failure after removing sdImage.imageSize is not another NixOS option mismatch. It is a host/build-platform mismatch.

The relevant error is: 

Required system: 'aarch64-linux'
Current system: 'x86_64-darwin'

In other words, the project is trying to build an aarch64-linux NixOS image from a Mac host that cannot realize the required Linux derivations locally.

Why this is a separate correction topic

The earlier sdImage.imageSize problem was a source-level configuration error in kiosk.nix. This new failure is different. The source edit is already applied. The remaining blocker is the environment in which the build is attempted.

That means the maintenance story has advanced one step: 

obsolete option removed
  ->
module error disappears
  ->
next boundary becomes visible

What the error means

The flake target is explicitly for aarch64-linux. The current workstation is x86_64-darwin. Without an appropriate Linux builder, Nix cannot realize the image derivations.

So the build is now blocked by platform availability, not by a false statement in the kiosk configuration.

Credible next steps

  1. Build on an aarch64-linux or x86_64-linux Nix machine with suitable builders.
  2. Or configure a remote Linux builder from the current Mac and rerun the same build.
  3. Only after that verification succeeds should the kiosk correction be committed in the hauptsache repo.

This keeps the maintenance story honest: source fixes are not declared complete until the build succeeds in a valid build environment.
