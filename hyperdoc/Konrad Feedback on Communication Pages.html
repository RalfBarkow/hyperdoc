Konrad Feedback on Communication Pages

Feedback summary from Konrad (matrix: @khinsen:matrix.org), integrated from the 2026-03-05 thread.

Konrad's framing: HyperDoc should support graph-based discovery/traversal, with the HyperBook interface enabling this without media discontinuity. He explicitly highlighted uniform robot access, but with human-written processing code that lives inside HyperDoc and remains browsable/runnable/inspectable.

He also connected this to topic-map work and asked whether these pages are best read as leaves in a graph of concepts/pages for both humans and robots, i.e. a second-order hypertext pattern.

Inspectable objects

  • Graph-based discovery and traversal
  • HyperBook interface without media discontinuity
  • Uniform robot access
  • Human-written robot code
  • Processing code inside HyperDoc
  • Topic-map work alignment
  • Concept-graph leaf for humans and robots
  • Second-order hypertext

Interpretation and decision

  • Keep focused pages when they are useful for active collaboration and feedback exchange.
  • Extract stable parts into broader architecture/reference pages over time.
  • Treat robot assistants as part of the interaction system around this communication.
  • Keep processing code in HyperDoc and expose it as inspectable runtime objects.
