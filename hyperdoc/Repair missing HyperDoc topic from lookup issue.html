Repair missing HyperDoc topic from lookup issue

hyperdoc

This page records the current bounded page/topic repair flow for a missing Topics target such as Running image coherence.

Current architecture boundary

  • Shared issue mechanics: the bounded lookup-issue protocol lives in hyperbook-explorer/lookup-failures.lisp.
  • Separate specializations: page-lookup-issue and function-lookup-issue share that protocol but keep different runtime truth.
  • HyperDoc-specific topic repair: hyperdoc-explorer/lookup-repairs.lisp derives the current page/topic status from chunk-backed state in hyperdoc/page-lookup-chunks.lisp.
  • Generic presentation: the shared Overview and Repair tabs render runtime-owned state; the explorer does not invent policy on its own.

When this repair path applies

  • The issue is a page-lookup-issue targeting HyperBook topics.
  • The issue can compute a topic-page-availability-chunk for the expected title.
  • The current chunk state is not :fixed.

Current diagnosis logic

The diagnosis model stays chunk-first and unchanged:

  • No authored topic factory: :needs-topic-creation
  • Authored factory exists but the Topics page is unresolved or stale: :needs-local-materialization
  • Topics page resolves: :fixed

The chunk also carries the status reason, repair hint, freshness mode, and the authored versus materialized signature evidence that supports the current diagnosis.

Repair procedure

  1. Open the page-lookup-issue and confirm the expected topic title.
  2. Use the issue-level Repair flow to inspect the target chunk rather than following a hand-maintained scaffold string.
  3. Inspect the chunk's current state, status reason, and freshness evidence.
  4. If the chunk says :needs-topic-creation, ensure the authored-topic-factory basis first.
  5. If the chunk says :needs-local-materialization, keep the authored factory and refresh only the running Topics materialization.
  6. If the chunk already resolves as :fixed, do not invent extra authoring work.
  7. Use repair-lookup-issue-via-chunks when you need the bounded mutation helper to ensure the target chunk directly.
  8. Re-open the source page or retry the link lookup and confirm that the issue now resolves as Fixed.

What gets materialized

  • If the authored factory is missing, HyperDoc can materialize a placeholder topic factory in hyperdoc/topics.lisp for this bounded repair path.
  • If the authored factory already exists, HyperDoc reloads the topic source and rebuilds the runtime topic indexes instead of inventing a new page file.
  • If the Topics page resolves again, the issue is fixed because the running lookup proposition is true again.

What this repair path does not mean

  • It does not mean Topics pages are repaired by creating standalone topic HTML files.
  • It does not mean the generic explorer owns page-repair policy.
  • It does not apply to function-lookup-issue; function lookup keeps its own fboundp-based correction path.

How the visible labels fit together

  • Open: unresolved lookup issue.
  • Needs topic: missing authored topic factory.
  • Needs materialization: authored factory exists but runtime Topics materialization is not current enough to resolve the page.
  • Fixed: the Topics page resolves again in the running system.
