DITA-like task topic

Repair a missing HyperDoc topic from a page-lookup issue

Purpose

Restore coherence when a page-lookup issue reports that a HyperDoc topic page is missing. This is the case shown in the screenshot for the missing topic page Running image coherence.

When to use this task

  • Issue state includes Open.
  • Failure classification is a missing HyperDoc topic page.
  • Suggested repair is to scaffold a HyperDoc topic.

Prerequisites

  • The missing link text has been inspected.
  • The target HyperBook is known to be topics.
  • You have write access to the HyperDoc source tree.

Steps

  1. Open the lookup issue and confirm the expected page id / slug.
  2. Confirm whether the concept is absent entirely or only lacks materialization.
  3. If the concept is absent entirely, add a new topic constructor in topics.lisp.
  4. Create the corresponding HyperDoc page file with the canonical title.
  5. Add minimal explanatory prose so the page is a durable topic anchor, not an empty stub.
  6. If your workflow requires it, create or refresh the FedWiki twin counterpart.
  7. Reload HyperDoc so the new topic constructor and page become available in the running image.
  8. Re-run lookup or reload the source page containing the broken link.
  9. Verify that the issue no longer reports as open.
  10. Mark the issue fixed only after link resolution succeeds in the running system.

Results

  • The previously missing topic page exists.
  • The link resolves in HyperDoc.
  • The issue can move from Open to Fixed.

Troubleshooting

  • If the topic constructor exists but the page does not, treat this as Needs materialization rather than Needs topic.
  • If the page exists but lookup still fails, inspect title, page id mapping, and target HyperBook selection.
  • If the page resolves only after a cold restart, the running image likely had a load-set mismatch.

Lisp repair function sketch

(defun repair-missing-topic-from-lookup-issue (issue &key create-fedwiki-twin-p)
  "Repair a page-lookup issue whose target kind is a missing HyperDoc topic page.
Returns a plist describing the performed work and verification result."

  (labels ((issue-value (key)
             (slot-value issue key))
           (canonical-title ()
             ;; prefer explicit expected page id / slug, fall back to link text
             (or (issue-value 'expected-page-id)
                 (issue-value 'link-text)))
           (topic-handle-from-title (title)
             ;; sketch only; adapt to your existing naming convention
             (string-downcase
              (substitute #\- #\Space title)))
           (topic-page-path (title)
             (merge-pathnames
              (format nil "hyperdoc/~A.html" title)
              (uiop:getcwd)))
           (topic-constructor-present-p (title)
             ;; replace with your real lookup against topics.lisp registrations
             (declare (ignore title))
             nil)
           (page-present-p (title)
             (probe-file (topic-page-path title)))
           (write-topic-page (title)
             (with-open-file (out (topic-page-path title)
                                  :direction :output
                                  :if-exists :supersede
                                  :if-does-not-exist :create)
               (format out "<h1>~A</h1>~%~%<in-package>hyperdoc</in-package>~%~%<p>Topic anchor.</p>~%"
                       title)))
           (append-topic-constructor (title)
             ;; sketch only; in the real system, edit topics.lisp structurally
             (let ((handle (topic-handle-from-title title)))
               (values handle t)))
           (reload-hyperdoc ()
             ;; replace with the exact load/reload operation you use
             (asdf:load-system :hyperdoc))
           (verify-repair (title)
             ;; replace with real issue re-resolution / lookup check
             (and (topic-constructor-present-p title)
                  (page-present-p title))))

    (let* ((title (canonical-title))
           (had-constructor (topic-constructor-present-p title))
           (had-page (page-present-p title))
           (created-constructor nil)
           (created-page nil)
           (fedwiki-twin-created nil))

      (unless had-constructor
        (append-topic-constructor title)
        (setf created-constructor t))

      (unless had-page
        (write-topic-page title)
        (setf created-page t))

      (when create-fedwiki-twin-p
        ;; hook your FedWiki twin generation here
        (setf fedwiki-twin-created t))

      (reload-hyperdoc)

      (let ((verified (verify-repair title)))
        (list :title title
              :created-constructor created-constructor
              :created-page created-page
              :created-fedwiki-twin fedwiki-twin-created
              :verified verified
              :next-status (if verified :fixed :open))))))

How the labels fit together

  • Open: the issue is unresolved.
  • Publication: the issue affects reader-facing published material.
  • Needs topic: the concept node itself is missing.
  • Needs materialization: the concept may exist, but its concrete page artifact is missing.
  • Fixed: the link resolves again after repair and reload.
