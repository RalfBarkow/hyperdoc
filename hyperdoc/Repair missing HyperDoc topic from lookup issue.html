DITA-like task topic

Repair a missing HyperDoc topic from a page-lookup issue

Purpose

Restore coherence when a page-lookup issue reports that a HyperDoc topic page is missing. This is the case shown in the screenshot for the missing topic page Running image coherence.

When to use this task

  • Issue state includes Open.
  • Failure classification is a missing HyperDoc topic page.
  • The issue points to a target chunk for the expected Topics page.

Prerequisites

  • The missing link text has been inspected.
  • The target HyperBook is known to be topics.
  • You have write access to the HyperDoc source tree.

Steps

  1. Open the lookup issue and confirm the expected page id / slug.
  2. Inspect the target chunk for the expected Topics page.
  3. Use chunk state plus the chunk's freshness evidence to distinguish Needs topic from Needs materialization.
  4. Repair the issue by ensuring that chunk rather than by following a hand-maintained scaffold hint.
  5. If the authored topic factory is missing, ensure the authored-factory basis chunk first.
  6. If the authored factory exists but the page still does not resolve, or its per-topic authored signature is newer than the current Topics materialization, materialize the running Topics state by rebuilding topic indexes.
  7. Re-run lookup or reload the source page containing the broken link.
  8. Verify that the target chunk now resolves as Fixed.
  9. Mark the issue fixed only after link resolution succeeds in the running system.

Results

  • The previously missing topic page exists.
  • The link resolves in HyperDoc.
  • The issue can move from Open to Fixed.

Troubleshooting

  • If the authored topic factory exists but the Topics page still does not resolve, or the materialized per-topic signature no longer matches the authored topic factory, treat this as Needs materialization rather than Needs topic.
  • If the page exists but lookup still fails, inspect title, page id mapping, and target HyperBook selection.
  • If the page resolves only after a cold restart, the running image likely had a load-set mismatch.

Lisp chunk sketch

(defmethod issue-target-chunk ((issue hyperbook:lookup-issue))
  (when (string= (hyperbook:lookup-issue-target-hyperbook-id-of issue)
                 "topics")
    (make-topic-page-availability-chunk
     (or (hyperbook:lookup-issue-expected-page-id-of issue)
         (hyperbook:lookup-issue-link-text-of issue)))))

(defun topic-page-lookup-chunk-state (chunk)
  (cond
    ((not (authored-topic-factory-defined-in-source-p
           (page-lookup-topic-title-of chunk)))
     :needs-topic-creation)
    ((chunk-up-to-date-p chunk)
     :fixed)
    (t
     :needs-local-materialization)))

(defun repair-lookup-issue-via-chunks (issue)
  (ensure-chunk (issue-target-chunk issue)))

In the current runtime, the inspected chunk also exposes a status reason, a repair hint, and both authored and materialized per-topic freshness evidence. The issue-level Repair flow stays inspect-first: it hands you the target chunk rather than a hand-maintained scaffold plan.

How the labels fit together

  • Open: the issue is unresolved.
  • Publication: the issue affects reader-facing published material.
  • Needs topic: the concept node itself is missing.
  • Needs materialization: the concept may exist, but its concrete page artifact is missing.
  • Fixed: the link resolves again after repair and reload.
