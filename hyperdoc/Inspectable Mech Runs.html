Inspectable Mech Runs

This page is a forward-looking HyperDoc design note. Current Mech can already publish output and structured findings, but it does not yet expose a persistent, inspectable run object model. The proposal here is that one Mech execution should become a first-class run record rather than only a transient browser action.

Inspectable objects

  • First-class run record
  • Execution evidence object
  • Execution step object
  • State delta
  • Artifact provenance
  • Boundary report
  • Findings ledger
  • Replay trail

Why a run should become an inspectable object

The current seam already has the right ingredients: source command, normalized operation and arguments, body, element, state, emitted artifacts, and findings. If those are preserved as objects instead of disappearing after execution, HyperDoc can inspect one run as a structured chronology rather than only as console traces or generated text.

This is the practical alternative to a retrospective explanation pass. The run should keep the evidence generated at execution time instead of asking a later layer to infer what must have happened from output alone. In HyperDoc terms, that is a concrete case of persistence of investigation context.

Proposed execution step object

Each executed block step should be representable as an execution step object carrying:

  • the original source command
  • normalized operation and arguments
  • parent/child body relation
  • state deltas
  • emitted artifacts
  • warnings, errors, and findings
  • source references where available

Proposed run-level views

A first-class run record could then support several inspectable views:

  • chronology view for step order and timing
  • tree or scene view for parent/child body nesting
  • findings view for warnings, losses, and runtime errors
  • provenance view for emitted artifacts and their producing steps

Why this matters for publication

HyperDoc already prefers inspectable runtime objects and graph-rooted publication. Mech runs fit that model well. A run object could publish a findings ledger, a boundary report, and artifact trail as live inspection surfaces instead of hiding them in one output artifact.

Current limit

This page proposes an object model; it does not claim that Mech already has one. The point is to make the missing execution ledger explicit and to connect it to the already existing emit seam.
