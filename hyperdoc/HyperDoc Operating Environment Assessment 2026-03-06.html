Current read

  • The repository now encodes its own operating policy in AGENTS.md.
  • The runtime stack and entry paths are explicit: dev.sh for iteration and start.sh for stricter launch.
  • The two-surface rule is explicit: durable architecture in HyperDoc, fast-moving collaboration in localhost FedWiki, linked by counterparts.
  • Inspectable topic objects are now first-class documentation primitives via hyperdoc/topics.lisp.
  • The playground/debugger line is now a subsystem surface (eval, reports, stepper, diagramming, web debugger) documented and wired on the HyperDoc side.

Main risk

The bottleneck has shifted from architecture capability to discoverability and synchronization discipline across three surfaces (HyperDoc page, Lisp topic object, FedWiki twin).

Recommendations

  1. Treat topics.lisp as canonical semantic index and keep extending inspectable coverage for operational pages.
  2. Consolidate the playground/debugger narrative so eval/restarts/reports/stepper/diagramming/web-debugger read as one toolchain.
  3. Automate lightweight smoke checks already defined by policy: asdf:load-system :hyperdoc, topic fboundp, slug-based FedWiki links, and launcher bring-up.
