DMX machine-readable read paths

hyperdoc

DMX machine-readable read paths records the explicit DMX HTTP routes that HyperDoc and the MCP server should treat as canonical. The key rule is simple: read through tool-facing JSON endpoints, not through browser hash routes or UI state assumptions.

Canonical topic read path

Use: 

/core/topic/<id>?children=true&assocChildren=true

This is the canonical machine-readable path for full topic reads, including the note topics used in the context-window workspace.

Canonical topicmap read path

Use: 

/topicmaps/<id>?children=true

This is the machine-readable topicmap projection used for workspace and topicmap reads.

What not to treat as a machine contract

  • DMX webclient hash routes.
  • Browser-visible SPA state.
  • Topicmap membership effects inferred only from UI placement.

Those are valid navigation surfaces for a person, but not the durable read boundary for tools or proof-oriented diagnostics.

MCP projection

The HyperDoc MCP server projects the same canonical boundary as workspace/context-window, topic/<id>, and topicmap/<id>. That projection exists to make the same DMX state readable by Codex, ChatGPT, and the operator without requiring each client to rediscover raw DMX routes independently.
