Inspectable operational targets

hyperdoc

Inspectable operational targets is the reusable skill for treating a live host and a host-aware operation as inspectable objects before any remote command is executed. This skill is about modeling + materialization, not remote execution.

The current implementation anchor is the dreyeck.ch HyperDoc host: user rgb, checkout /home/rgb/workspace/hyperdoc/, and Git operations for adding or fetching Konrad's upstream remote.

What the skill makes explicit

  • a nixos-host-target can carry hostname, SSH user, checkout root, service name, and deployment mode,
  • a git-remote-operation can carry remote name, remote URL, branch, and operation kind,
  • the Materialization view renders the exact shell block to run, while leaving execution to the operator.

Worked example from this repo

The dreyeck.ch example exists because the live HyperDoc checkout needed a durable representation of "add Konrad's remote if missing, then fetch upstream/main" without hiding those commands inside prose-only notes. The existing page Operational Target Objects for dreyeck.ch shows the concrete host object and the two operation objects.
