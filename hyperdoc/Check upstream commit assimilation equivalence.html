Check upstream commit assimilation equivalence

hyperdoc

Check upstream commit assimilation equivalence is the higher-layer task skill for a narrower operational question than graph/history proof alone:

  • Should this upstream commit be cherry-picked?
  • Does the target already need manual assimilation instead of a straight cherry-pick?
  • Is the upstream payload already present in effect on the target branch?

This skill wraps the existing read-only commit-equivalence proof object. It keeps the object graph explicit instead of flattening everything into one report:

  1. graph/history proof,
  2. payload scope,
  3. semantic evidence,
  4. focused validation,
  5. final decision rationale.

Boundary rule

The final decision view may summarize the result, but the object graph must still let a reader inspect the graph/history proof without passing through semantic claims, and inspect the semantic claims without pretending they came from git cherry or git range-diff.

Corpus/page evidence is optional and bounded. A page lookup can resolve to a live page object, degrade to a structured lookup issue when the target is missing, or report that the current image cannot support that lookup seam at all. The assimilation object stays inspectable in each case.

Procedure

  1. Open Graph/History proof first and inspect ancestry, patch equivalence, and any replayed equivalent commit.
  2. Open Payload scope to make the exact upstream file scope explicit.
  3. Open Semantic evidence to inspect constructor, corpus, runtime-shape notes, and any candidate superseding local commit.
  4. Open Validation to see the narrowest focused check that backed the classification.
  5. Read Decision rationale only after those earlier surfaces.

Worked example

The current worked example uses the static-route-observability skill commit. The original 4fd5e78... remains on the preserved source branch, the preserved pre-merge target branch already contains replay-equivalent f7dd554..., and later local 1f8f285... preserves the same live effect under the current operational-targets-backed static asset resolution surface. The higher-layer semantic evidence plus focused validation therefore classify the payload as :already-assimilated rather than something that still needs a cherry-pick.
