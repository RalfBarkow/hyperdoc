Dreyeck Executable Scaffold for upstream main into hauptsache

hyperdoc

This page turns the future-facing dreyeck transition plan into a minimal executable downstream boundary. The durable object is a git-dreyeck-executable-scaffold that records the real systems, package boundary, component paths, realized proposal links, and validation commands for the first loadable dreyeck slice.

The scaffold in this slice stays intentionally small:

  • dreyeck.asd defines :dreyeck/server and the :dreyeck alias system.
  • dreyeck/package.lisp defines the new downstream package boundary.
  • dreyeck/server.lisp installs the first downstream behavior through core seams instead of moving large path buckets.

This proves the future split direction from the transition plan is executable now: dreyeck depends on HyperDoc core, not the reverse.

That proof does not absorb the promoted shared-core raw conflicts into dreyeck. It only establishes the downstream boundary that the remaining manual core merges can target.
