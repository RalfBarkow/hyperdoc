Materialize a host-aware operation without executing it

hyperdoc

Materialize a host-aware operation without executing it is the task skill for turning an inspectable host or Git remote operation object into the exact shell block an operator should run manually.

This skill is intentionally bounded: HyperDoc computes and displays the command block, but it does not SSH into the host or execute the remote action itself.

Procedure

  1. Inspect the host or operation object and open its Materialization view.
  2. Read the rendered shell block in full, including the target host, checkout root, and Git arguments.
  3. Run the block manually in a terminal only if the target host and action are the ones you intend.
  4. Keep the difference explicit between "HyperDoc rendered the command" and "the operator executed the command".

Worked example boundary

For dreyeck.ch, the two first operational materializations are: add upstream if missing, and fetch upstream main from the live checkout at /home/rgb/workspace/hyperdoc/. The same modeling pattern should be reusable for other NixOS hosts without implying remote execution inside HyperDoc.
