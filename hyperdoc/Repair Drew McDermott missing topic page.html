Repair Drew McDermott missing topic page

This note captures the immediate repair for the missing topic page Drew McDermott plus the runtime path that produced the page-lookup-issue object we inspected.

Immediate repair

The missing topic page is not a separate durable HTML file. In the current Topics HyperBook model, that page is rebuilt from an authored topic factory in hyperdoc/topics.lisp.

Add this function to hyperdoc/topics.lisp: 

(defun drew-mcdermott-topic ()
  (make-topic
   :id "drew-mcdermott"
   :title "Drew McDermott"
   :summary "AI researcher whose public site is a useful HyperDoc anchor for Common Lisp software distribution, planning-language design, and the running-image versus durable-source boundary."
   :references '("Drew McDermott Lisp, Planning, and Software"
                 "A framework for maintaining the coherence of a running Lisp"
                 "YTools, Nisp, Nity, Opt, and Optop"
                 "PDDL and Opt in Drew McDermott's work"
                 "Litlisp as experimental literate programming")))

Then reload HyperDoc and verify that topics/Drew McDermott resolves.

Why the repair currently stops at inspection

Our current repair flow attaches a repair thunk that returns a hyperdoc-authoring-scaffold-plan. For topic repairs this plan is in :topic mode, so it provides a template and metadata, but no direct write action. The existing direct write operation only handles :page mode.

Code path to the page-lookup-issue view

  1. The inspected HTML page exposes a Lookup issues tab.
  2. That tab calls lookup-issues-of on the page object.
  3. The html-page specialization walks page links and evaluates each link thunk.
  4. When a link evaluation returns a lookup failure, HyperBook wraps it in a page-lookup-issue.
  5. enrich-lookup-issue sees target HyperBook topics and classifies the issue as a missing HyperDoc topic page.
  6. The issue gets a repair thunk that calls plan-hyperdoc-authoring-scaffold.
  7. The issue inspector then shows Overview, Details, Repair, and Condition.
