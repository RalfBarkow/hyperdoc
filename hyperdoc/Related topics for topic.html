Related topics for topic

related-topics-for-topic is a FedWiki-attached ASDF page asset for read-only topic-neighborhood discovery. It asks one narrow question: which topic-like objects does the local HyperDoc working context already know about a selected topic?

The asset is intentionally a discovery tool, not a synchronization tool. It reads local text and local mirror data, returns a structured report, and leaves all source systems unchanged.

Implementation Shape

The page asset defines the ASDF system related-topics-for-topic. Its public package exports a report object, hit objects, the general query function, a DMX-topic convenience wrapper, an ssh-copy-id convenience fixture, and a printer for SLY/MREPL inspection.

  • related-topic-hit: one discovered relation-like hit.
  • related-topic-report: the topic query, warnings, timestamp, and deduplicated hits.
  • related-topics-for-topic: general read-only query entry point.
  • related-topics-for-dmx-topic: wrapper for a DMX topic id and title.
  • ssh-copy-id-related-topics: motivating Kioskbeerli maintenance-access example, not the general contract.
  • print-related-topic-report: compact text rendering for inspection sessions.

Discovery Surfaces

The current asset searches local, read-only surfaces that already exist on disk:

  • HyperDoc source tree: text matches in the current checkout, excluding runtime outputs such as var/, SQLite files, FASLs, and build results.
  • FedWiki-attached ASDF systems/assets: page asset directories under /Users/rgb/.wiki/wiki.ralfbarkow.ch/assets/pages/.
  • DMX associative SQL mirrors: local SQLite mirror rows, when var/dmx-associative-mirror.sqlite exists.
  • Future guarded DMX Neo4j reads: planned local or remote read adapters, not implemented by this asset slice.

This is broader than the Kioskbeerli ssh-copy-id maintenance trace. That trace is one useful topic for proving the workflow. The general asset is about any topic designator that can be represented as an id, title, URI, and optional search terms.

Read-only Contract

  • It does not write DMX topics or associations.
  • It does not write Neo4j.
  • It does not synchronize FedWiki, HyperDoc, SQL, or DMX stores.
  • It does not unzip or materialize page assets during a query.
  • It reports missing local inputs as warnings instead of turning discovery into setup.

Load and Inspect

The following SLY/MREPL sequence matches the current page-asset layout. It loads the local FedWiki-attached ASDF system, runs the motivating ssh-copy-id query, prints a compact report, and leaves the report inspectable. 

(require :asdf)

(asdf:load-asd
 #P"/Users/rgb/.wiki/wiki.ralfbarkow.ch/assets/pages/related-topics-for-topic/related-topics-for-topic.asd"
 :name "related-topics-for-topic")

(asdf:load-system :related-topics-for-topic)

(defparameter *related-topics-report*
  (related-topics-for-topic:related-topics-for-topic
   :topic-id 983869
   :title "ssh-copy-id"
   :uri "dmx://dreyeck/topic/983869"
   :hyperdoc-root #P"/Users/rgb/workspace/hyperdoc/"
   :fedwiki-site-root #P"/Users/rgb/.wiki/wiki.ralfbarkow.ch/"
   :dmx-sql-db #P"/Users/rgb/workspace/hyperdoc/var/dmx-associative-mirror.sqlite"
   :include-sql-neighborhood t))

(related-topics-for-topic:print-related-topic-report *related-topics-report*)

(i *related-topics-report*)

Boundary

The durable HyperDoc concern is the workflow boundary: related-topic discovery can span HyperDoc source, FedWiki-attached page assets, and local SQL mirror evidence without implying live DMX or Neo4j integration. A future adapter may add guarded local or remote DMX Neo4j reads, but that would be another slice with its own inspection, authorization, and validation contract.
