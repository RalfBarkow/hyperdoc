Page as Topicmap

Page-as-topicmap is the local HyperDoc projection that turns an authored page into a DM6/AppEmbed Topicmap seed. It reads the page's Plump DOM, keeps meaningful document nodes, writes native DM6 model JSON, and can materialize that JSON as a script.dm6-stored seed inside a DM6 island.

What is implemented

  • hyperdoc/dm6-page-topicmap.lisp contains the DOM traversal, native DM6 model construction, JSON generation, script insertion, and inspectable seed report.
  • hyperdoc/dm6-page-topicmap-api.lisp keeps narrow public entry points available when only the core HyperDoc system is loaded.
  • tests/dm6-page-topicmap-smoke.lisp covers native model shape, self-exclusion of generated seed scripts, deterministic hierarchy associations, nextId, and proof-page materialization.
  • DM6 AppEmbed HyperDoc Inline Proof is the committed proof page seeded from its own parse tree.

Projection model

The generator creates one root topic for the page and one topic for each kept DOM node. Kept nodes include headings, paragraphs, lists, code blocks, tables, structural elements, anchors, and HyperDoc custom elements. Ordinary script and style nodes are skipped, and generated script.dm6-stored seeds are explicitly excluded so regeneration does not fold the previous seed back into the topicmap.

Parent-child DOM structure becomes deterministic Hierarchy associations. Topic ids, association ids, topic order, and positions are derived from traversal order rather than random layout. The exported JSON uses the current native AppEmbed shape with topics, assocs, itemSets, boxes, topicMap, topicList, and tool.

Relation to DM6/AppEmbed

AppEmbed reads the materialized script.dm6-stored JSON and decodes it as a native model. The page-as-topicmap generator is therefore a source-side seed generator, not a change to the compiled Elm bundle and not a new AppEmbed schema. The current proof page uses the TopicMap renderer.

Relation to the Kioskbeerli SQL mirror

Page-as-topicmap and the Kioskbeerli DMX SQL topicmap projection share the same broad goal of rendering structured source material as a topicmap, but they have different sources and persistence boundaries.

  • Page-as-topicmap derives topics from a HyperDoc page DOM and may rewrite that page's local script.dm6-stored seed.
  • The Kioskbeerli SQL mirror projection derives topics and edges from a generated SQLite mirror and renders an inspected projection object.
  • Page-as-topicmap is not DMX persistence, not Neo4j synchronization, and not a Kioskbeerli trace mirror.

Inspect without rewriting

This MREPL path creates an inspectable report and does not change any page file. 

(require :asdf)
(asdf:load-system :hyperdoc/explorer)

(defparameter *page-topicmap-report*
  (hyperdoc:dm6-page-topicmap-seed-report
   :pathname (hyperdoc:dm6-inline-proof-page-pathname)))

(i *page-topicmap-report*)

Regenerate the proof seed

This MREPL path rewrites only hyperdoc/DM6 AppEmbed HyperDoc Inline Proof.html. Use it after editing that page when the embedded DM6 seed should be refreshed from the page's current DOM. 

(require :asdf)
(asdf:load-system :hyperdoc/explorer)

(defparameter *materialized-page-topicmap-report*
  (hyperdoc:materialize-dm6-inline-proof-page-topicmap-seed!))

(i *materialized-page-topicmap-report*)

Boundary

  • This is a page-local topicmap seed generator.
  • It does not write to DMX or Neo4j.
  • It does not run NixOS deployment commands or activate flakes.
  • It does not modify assets/dm6-elm/app.js.
  • It does not claim a general HyperDoc-to-DM6 command port; it currently materializes native seed JSON for AppEmbed to load.
