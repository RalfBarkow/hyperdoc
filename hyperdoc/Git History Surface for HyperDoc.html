Git History Surface for HyperDoc

hyperdoc

This page introduces a first narrow Git history surface inside HyperDoc. The surface stays deliberately small: it exposes explicit branch anchors, commit targets, and typed merge-intent relations as inspectable objects instead of trying to become a full interactive Git client.

The main object is a git-history-surface. It owns two branch lanes for the HyperDoc repository, one local and one upstream, plus a list of typed relations that turn merge planning into a durable object graph rather than a prose-only note.

The next narrow slice turns that same surface into a merge-preparation surface. Each relation can now materialize a computed merge forecast with upstream-only paths, hauptsache-only paths, overlapping paths, and attached dreyeck extraction notes.

Why this first slice is lane-based

A Sublime-Merge-like surface does not require a full DAG renderer on day one. For this first slice, lane columns are enough to make three things inspectable:

  1. the anchored local and upstream branch positions,
  2. the merge-intent relation between those anchors,
  3. the branch-only backlog on either side.

That keeps the durable fact in the relation object while still giving the repository a history/worklist surface that can be replayed from the current source tree.

What the surface shows

  • 👀git-history shows the two lane anchors, the active merge-intent relation, and recent branch-only commits.
  • 👀merge-worklist filters the relation list by target branch and expands the validation checklist kept on each relation object.
  • 👀merge-forecast renders the computed merge base, path-set counts, and blockers without executing the merge.
  • 👀upstream-only-files, 👀hauptsache-only-files, and 👀overlapping-paths expose the concrete path lists on the forecast object.

Intentional limits

  • No staging, checkout, cherry-pick, or rebase UI.
  • No free-form relation editing.
  • No attempt yet to draw the full commit DAG or collapse shared ancestors.
