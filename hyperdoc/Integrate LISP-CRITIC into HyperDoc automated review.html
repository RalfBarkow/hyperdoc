Integrate LISP-CRITIC into HyperDoc automated review

hyperdoc

This page is the durable plan surface for integrating the local FedWiki LISP-CRITIC asset into HyperDoc automated code review. The scope here is a plan, task, relation, and inspector-view surface. It does not load, execute, vendor, copy, or normalize the critic.

Goal

The concrete plan is integrate-lisp-critic-in-review. Its goal is to use the FedWiki-sourced LISP-CRITIC asset as an inspectable critic engine under HyperDoc review contracts.

Source station

LISP-CRITIC is treated as a source-station-backed local asset: 

(:fedwiki-asset
 :site "wiki.ralfbarkow.ch"
 :page "a-critic-for-lisp"
 :asset-root "~/.wiki/wiki.ralfbarkow.ch/assets/pages/a-critic-for-lisp/")

The plan records that path as data. Smoke tests may report whether the local checkout exists, but the model and tests do not require a FedWiki server, DMX server, network access, or the physical asset path to exist.

Contracts

The plan reuses the existing review vocabulary rather than creating a parallel review language. Its contract list is:

  • :review-contract
  • :critic-contract
  • :source-station-contract
  • :view-contract

Plan status

The current status is :draft. The plan has first-class task relations and inspector views, but the actual execution adapter remains a deferred follow-up. No LISP-CRITIC invocation, source manifest checksum policy, or finding normalization is implemented on this page.

Reading surfaces

Inspect the plan with the Summary view to see the goal, status, source station, contracts, and ordered task decomposition. Inspect the Goldberg coverage view to see which DITA-like task topics answer Programmer-as-Reader questions and which artifacts those relations produce.

The prompt question id :does-system-do-this is normalized to the local Goldberg slice id :does-any-part-do-this. The mapping is explicit in lisp-critic-review-normalize-goldberg-question-id.

Boundary

This slice is descriptive and inspectable only. It does not perform live builds, HTTP requests, SSH sessions, DMX writes, FedWiki writes, or LISP-CRITIC execution. Later work should implement the execution adapter, source manifest/checksum policy, invocation boundary, and finding normalization as separate inspectable artifacts.
