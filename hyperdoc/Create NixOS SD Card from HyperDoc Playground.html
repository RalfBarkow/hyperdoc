Create NixOS SD Card from HyperDoc Playground

hyperdoc

Task topic: create and flash a Raspberry Pi aarch64 NixOS SD card using a runbook-aligned command plan generated from HyperDoc Playground.

Primary actions

  • Open semantic runbook
  • Open sdImage.imageSize correction path

These are the two intended semantic entry points. Both open semantic objects with Summary as the default tab.

Inspectable objects

  • Create NixOS SD card from HyperDoc Playground task
  • SD card command plan in Playground
  • Semantic navigation visible and clickable
  • Semantic object-ref renderer
  • Runbook: Build and Flash NixOS SD Image for Kioskberrli

Navigation rule

Key rule: make semantic navigation visible and clickable, without falling back to raw structure as the primary path.

Renderer confirmation

Confirmed for this surface: the renderer path uses semantic object-ref links for primary navigation. Raw-structure views remain available only for diagnostics.

Raw structure (diagnostics only)

  • Open raw section list
  • Open raw structure (runbook view)
  • Open raw structure (correction-step view)

Prerequisites

  • Run inside the Nix development shell.
  • HyperDoc server and Playground are available.
  • A target SD card is inserted and identifiable on the host.

Context

This task does not replace the runbook. It provides Playground functions that emit the same command sequence as the existing runbook so execution can be prepared and reviewed in one inspectable place.

Procedure

  1. Open Playground and evaluate the semantic runbook object:
sd-card-creation-command-plan-example

Direct semantic object: sd-card-creation-command-plan. This opens Summary first; raw list data is available in Raw Structure.

  1. Generate a human-readable dry-run transcript (no shell execution):
sd-card-creation-dry-run-example
  1. Choose exactly one artifact source path: Path A (official prebuilt image) or Path B (project build).
  2. Execute the selected commands in the host shell, preserving runbook order.
  3. Before flashing, replace diskN with the verified SD-card device identifier.

Correction path from visible error to integration

When the build fails on sdImage.imageSize, inspect this semantic correction step: sdimage-imagesize-correction.

  • Failure capsule: kioskberrli-sd-image-failure-context
  • Source/edit target: suggested-patch
  • Verification command: repro-build-command
  • Integration note: correction-path

Result

  • A verified .img artifact is available.
  • The SD card is flashed and ejected safely.
  • The command sequence used is reconstructible from HyperDoc functions and runbook text.

Safety and quality checks

  • Never run dd until the target disk id has been verified twice.
  • Use checksum and size checks before flashing.
  • Keep the runbook as source of truth; update Playground helpers only when runbook changes.
