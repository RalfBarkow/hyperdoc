FedWiki Video Snippet Plugin for HyperDoc

HyperDoc needs a principled way to represent FedWiki video snippets such as: 

video

YOUTUBE UjPxDOEdsX8
Published Dec 1, 2007.

The right model is not to paste arbitrary HTML into a page. The right model is to treat the snippet as a typed FedWiki story item and adapt it into a HyperDoc-visible object.

Idea 1: a video snippet is a typed story item

A FedWiki video item should be represented explicitly, just like a paragraph, markdown block, or reference.

The minimal information is:

  • provider
  • video id
  • caption or body text
  • source item metadata

Idea 2: convert the snippet before rendering

The adapter should parse the FedWiki item first and only then decide how to render it in HyperDoc.

For the example above, the conversion result is conceptually: 

provider = youtube
video-id = UjPxDOEdsX8
caption = Published Dec 1, 2007.

Idea 3: rendering should have a safe fallback

The preferred rendering is an embedded video player plus caption. The fallback rendering is a canonical external link to the video plus the same caption text.

That keeps the page useful even when embedding is not possible or not desired.

Idea 4: make this a plugin boundary, not a one-off special case

The video snippet should be the first example of a more general adapter layer for FedWiki snippet types. That same layer can later handle other plugin-like story items such as frame, graphviz, or html.

So the implementation should start from a generic conversion hook, then add a single concrete adapter for video.

Idea 5: keep the page copy faithful

The HyperDoc page should remain a faithful copy of the FedWiki page's meaning. The plugin should improve the affordances, not rewrite the content model.
