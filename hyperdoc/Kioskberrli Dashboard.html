Current status

Overall status: blocked. The current blocker is Kioskberrli Cross-Host Build Failure: the declared aarch64-linux SD-image target still needs a valid Linux builder or remote Linux builder.

The previous blocker, Kioskberrli sdImage imageSize Failure, is corrected. Removing the obsolete sdImage.imageSize option moved the work forward, but it did not prove that the kiosk image builds, flashes, boots, or displays the landing page.

Dashboard status vocabulary: declared, blocked, corrected, missing evidence, verified, unknown.

Build evidence

Build evidence is still missing evidence because the project SD-image build has not been recorded as successful on a valid Linux builder. Do not read this dashboard as a claim that a build succeeded. 

nix build .#nixosConfigurations.kioskberrli.config.system.build.sdImage

The runbook keeps the command sequence: Runbook - Build and Flash NixOS SD Image for Kioskberrli. The current blocker page explains why the same target is blocked on the present host.

Flash / boot evidence

Flash evidence is missing evidence. Boot evidence is missing evidence. The real hardware workflow has not yet been proven on the physical Raspberry Pi 4 with the selected SD card.

After a valid image artifact exists, the next evidence to record is SD-card flashing, first boot on the Pi, network reachability, kiosk-session startup, and landing-page display after reboot.

Public-display layout state

The passive display target is declared: https://hauptsache.dreyeck.ch/assets/home/index.html. The station board can describe a maintenance or failure view conceptually, but this slice does not add a runtime public-display framework.

The public-display boundary remains the one described by Hauptsache Entry Model: landing page, FedWiki workspace, and physical kiosk device stay distinct.
