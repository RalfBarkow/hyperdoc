  • In ~/P/R/wiki with fish shell, ./dev.sh failed with Unknown command, indicating no executable dev.sh at that location.
  • git fetch --all succeeded; origin/dreyeck.ch advanced from 3a06e87 to 548ee4c.

Build and startup findings

  • nix build #.wiki completed successfully.
  • ./result/bin/wiki --port 3000 started the wiki in farm mode.
  • Runtime confirms data paths under /Users/rgb/.wiki/localhost, including: db=/Users/rgb/.wiki/localhost/pages, assets=/Users/rgb/.wiki/localhost/assets, status=/Users/rgb/.wiki/localhost/status.
  • Site served startup and core resources successfully (HTML, CSS, JS, system JSON endpoints).

Proxy error findings

  • Repeated proxy requests for https://localhost/favicon.png and fallback http://localhost/favicon.png failed.
  • Failure mode: TypeError: fetch failed with ECONNREFUSED from Node/undici.
  • Client-facing effect: repeated GET /proxy/localhost/favicon.png?... 502.
  • Despite proxy errors, primary wiki endpoints remained available (e.g. /welcome-visitors.json, /system/sitemap.json, /system/site-index.json).

Interpretation

Core localhost wiki service on port 3000 is up and serving content. The observed failures are specific to proxying localhost favicon URLs, not a full server startup failure.

More explicitly, the failing path is the proxy endpoint /proxy/localhost/favicon.png?... , where the server attempts outgoing fetches to https://localhost/favicon.png and http://localhost/favicon.png and receives ECONNREFUSED. In contrast, direct non-proxy requests to the same wiki process continue to succeed (startup page, page JSON, sitemap, and site index).

This narrows the problem scope to localhost self-proxy/reachability for that asset path (or its protocol/host resolution assumptions), rather than database loading, plugin initialization, page serving, or overall farm startup.
