Time Machine Backup Troubleshooting

hyperdoc

This page provides an operational diagnostic path for cases where a Time Machine destination is configured, visible, or partially reachable, but the first backup does not really start or fails to complete.

Symptom matrix

  • Destination not shown: the server or share is not discoverable or not exposed correctly.
  • Destination shown but backup does not start: credentials, mountability, or server-side Time Machine support may be wrong.
  • Password rejected: saved credentials are stale or the server account settings changed.
  • First backup appears stuck: distinguish very slow transfer from no progress at all.
  • Backup fails after some progress: inspect network stability, server settings, antivirus, or firewall interference.

Step-by-step diagnostic sequence

  1. Confirm the server is reachable: in Finder, open Network and check that the NAS or SMB server appears.
  2. Confirm the share is visible: mount the share manually in Finder and make sure it opens.
  3. Confirm write access: verify that the chosen account can write to the intended backup location.
  4. Reselect the backup disk: open System Settings -> General -> Time Machine, remove or reselect the destination if it may be stale.
  5. Retry the backup: trigger the backup again and watch whether progress indicators change.
  6. Inspect server-side settings: confirm that Time Machine support is enabled on the server and still bound to the intended share.

Apple documents checking Finder network visibility, current password, server/network availability, and server-side Time Machine support when the backup disk cannot be found or mounted reliably.

Destination shown but backup does not start

  1. Open the destination manually in Finder before reopening Time Machine.
  2. Verify that the destination is not merely listed, but actually mountable.
  3. Remove the destination from Time Machine settings and select it again if the entry may be stale.
  4. If the server password changed, re-enter credentials during reselection.
  5. If the server is a NAS, confirm that its Time Machine support is enabled for SMB, not only generic file sharing.

Troubleshoot slow or failed first backup

  • Slow but progressing: transfer size, status text, or remaining-data indicators continue changing.
  • Not progressing at all: preparing or waiting state repeats without visible movement, or the share drops out of Finder.

Apple documents that the first backup can take much longer than later ones. Apple also documents that third-party antivirus or firewall software can interfere with backup completion or network backup connectivity.

What success looks like

  • The server remains reachable in Finder while Time Machine is active.
  • The backup moves past initial preparation into real transfer activity.
  • After retry or reselection, Time Machine records a new successful backup instead of remaining perpetually pending.
