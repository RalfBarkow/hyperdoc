Merge upstream main into hauptsache via dreyeck fallback

hyperdoc

This page captures one concrete merge-intent relation for the HyperDoc repository. The point is not just to remember that a merge should happen. The point is to keep the review anchors, the prompt, and the conflict policy inspectable as one durable object that the history surface can render.

The preparation slice adds a computed forecast object for the same relation. That forecast classifies path overlap from the anchored commits back to their merge base, so readiness and blockers can be inspected before any merge is attempted.

Conflict policy

If conflicts arise while merging upstream/main into hauptsache, do not force a coarse overwrite in either direction. Instead, refactor the hauptsache-specific local delta into a new ASDF subsystem named dreyeck so that the upstream HyperDoc core can stay close to upstream/main while the local deployment-specific behavior remains loadable and inspectable.
