Topic factory

hyperdoc

A topic factory is an authored Lisp function currently living under hyperdoc/topics/ that returns a topic object, typically through make-topic. Its role is not only construction in one moment, but durable reconstruction of the topic-page surface used by HyperBook topics.

This is the current Common Lisp code layout, not the final production topic store. Durable project topics should be persisted as first-class Dreyeck/DMX SQLite topics and associations; Markdown notes and HyperDoc pages are seeds, exports, handover artifacts, or human-readable projections unless a slice explicitly says otherwise.

Minimal shape

The normal authored pattern is short and explicit: 

(defun some-topic ()
  (make-topic
   :id "stable-key"
   :title "Canonical Topic Title"
   :summary "..."
   :references '("Some Page")))

The important part is not only that the function returns a topic object. The function itself is the durable authored reconstruction point for that concept in this repository.

What a topic factory produces

A topic factory normally produces a topic object with four authored fields:

  • stable id: a durable Lisp-side key for concept identity
  • canonical title: the exact topic-page title used by HyperBook topics
  • summary: the short explanatory synopsis for the topic page
  • editorial references: durable references kept with the topic object

The title is what the Topics HyperBook resolves as a page id. The stable key preserves concept identity separately so title maintenance and Lisp identity are not collapsed into one string.

How topic factories become topic pages

HyperDoc discovers authored topic constructor symbols in package :hyperdoc, rebuilds the topic index from those authored factories, and then resolves topic pages in HyperBook topics by the canonical topic title.

This is why the factory matters even when the page content is shown later as a topic page: the topic-page surface is rebuilt from authored factories, not from accidental page text alone.

Why this is not just make-topic

make-topic is the helper that constructs or refreshes a topic object. A topic factory is the authored function that names a reusable concept entry point and decides which stable key, canonical title, summary, and references belong to that concept.

In this repository, the factory is the durable authoring unit. The helper is the constructor used inside it.

Topic factory vs topic-page link

A topic factory is the Lisp-side authored concept constructor. A link such as <a hyperbook="topics" page="Exact Topic Title"> is the page-side authored navigation to the corresponding topic page.

The factory defines inspectable concept identity. The page link points to it from narrative pages.

Topic factory vs DMX runtime wrapper

Some functions with topic-shaped names may later resolve live DMX-backed runtime proxies in the inspector. HyperDoc still preserves the original authored topic factory internally so the topic-page surface can be rebuilt from authored topic definitions.

For the preserved authoring layer across many concepts, see Authored topic factories.

This is why the authored topic-page surface and the live runtime-object surface remain intentionally separate. The topic factory belongs to the authored topic-page surface even when selected wrapper functions are redirected to DMX-backed runtime objects.

When to add a topic factory

  • add one when a concept needs reusable inspectable identity
  • add one when multiple pages should point to the same canonical topic title
  • do not add one for every transient workflow step or every page-local phrase

Failure modes

  • confusing authored topic factories with runtime wrappers
  • changing canonical title strings carelessly and breaking topic-page links
  • treating editorial references as if they were automatic backlinks
  • creating topic factories for concepts that do not need reusable identity
