Snapshot transport

hyperdoc

Snapshot transport is the submit-boundary carrier seam by which browser-captured Connect snapshot JSON crosses from pane UI state into the server-side payload, so later request evidence or direct snapshot inspection can reconstruct the exact browser-side Connect state at handoff time.

Snapshot construction is not snapshot transport. The browser may successfully build a snapshot with debugSnapshot(), yet later evidence still lacks a reconstructed dom-connect-session-snapshot unless snapshot JSON was actually carried across the submit boundary.

Carrier seam

The browser-side producers differ. writeSubmitPayload() prepares the normal association submit path, while prepareEvidenceButton() prepares the request-evidence path. Those paths do not merely differ in intent; they differ in which submit-boundary carrier is authoritative for snapshot JSON.

On the normal association path, the payload-bearing button carries button-payload-v2 and authoritatively transports source and target JSON. Snapshot JSON is only a fallback mirror through the hidden control named by data-dom-connect-snapshot-field-id.

On the evidence path, the payload-bearing button carries connect-request-evidence-v1 and also carries data-dom-connect-snapshot-json directly. The hidden inspect field is only a secondary mirror there.

Server parse order

The server parse seam is shared. dom-association-submit-payload reads data-dom-connect-snapshot-json from the payload-bearing element first and only then falls back to the hidden control referenced by data-dom-connect-snapshot-field-id. Transport authority is therefore path-dependent:

  • authoritative inline carrier on the evidence path
  • fallback hidden-field dependency on the normal association path

Absence interpretation

When later evidence says No submit-boundary session snapshot was captured., that message means the reconstruction seam lacked transported, parseable snapshot JSON. It does not necessarily mean that the original Connect request failed or that snapshot construction in the browser never happened.
