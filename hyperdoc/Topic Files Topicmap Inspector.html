Topic Files Topicmap Inspector

hyperdoc

This reference page records the inspector slice that turns the topic registry diagnostic's loaded source paths into inspectable source-file objects and a persisted SQLite-backed topicmap projection.

Inspectable objects

  • Topic Files Topicmap Inspector
  • Topic files topicmap
  • Topic source file
  • Topic factory source record
  • (make-topic-registry-diagnostic)
  • (make-topic-files-topicmap)
  • (topic-files-topicmap-payload ...)

Runtime contract

topic-source-file represents one loaded topic file as a source artifact. It carries the pathname, parse status, top-level form count, observed in-package forms, parser failures, and discovered factory records.

topic-factory-source-record represents a defun whose body contains a make-topic form. When keyword values are statically available, the record preserves :id, :title, :summary, and :references.

topic-files-topicmap is the projection owner. It parses the loaded files, materializes rows into SQLite, and exposes topic-files-topicmap-payload as a renderer-neutral plist with :nodes and :edges, following the projection/payload separation used by kioskbeerli.dmx-sql-topicmap.

SQLite persistence

The default database path is var/topics.sqlite. Tests and replay snippets should pass a temporary :db-path so local validation does not depend on the durable working database.

The materializer owns these tables:

  • topic_source_file
  • topic_factory
  • topic_node
  • topic_reference
  • topic_file_edge

Parsing boundary

Source files are read with *read-eval* bound to nil. Top-level in-package forms are recorded and used for subsequent reads when the package exists. Read failures, missing packages, and missing files are stored as file diagnostics and SQLite rows rather than surfacing as hard CLOG browser failures.

Inspector views

The topic registry diagnostic keeps its existing diagnostic role but gains an inspectable Loaded topic files table and a Topicmap view. Each loaded path is now rendered as an object reference to a topic-source-file.

topic-files-topicmap provides Overview, Files, Factories, Topics, References, Topicmap, and SQLite views. The Topicmap view renders from the persisted payload, not directly from transient parser records.

SLY MREPL replay

(require :asdf)
(asdf:load-system :hyperdoc)
(asdf:load-system :hyperdoc/inspector)

(defun i (object)
  "Safe inspector helper for SLY mREPL.
Prefer CLOG only if it is already loaded; otherwise use CL:INSPECT.
Never calls SLYNK:INSPECT-IN-EMACS directly."
  (let* ((clog-package (find-package "CLOG-MOLDABLE-INSPECTOR"))
         (clog-symbol
           (and clog-package
                (find-symbol "CLOG-INSPECT" clog-package))))
    (cond
      ((and clog-symbol (fboundp clog-symbol))
       (handler-case
           (progn
             (funcall (symbol-function clog-symbol) :object object)
             object)
         (condition (condition)
           (format t "~&CLOG inspector failed; falling back to CL:INSPECT: ~A~%"
                   condition)
           (inspect object)
           object)))
      (t
       (inspect object)
       object))))

(defparameter *topic-registry-diagnostic*
  (hyperdoc:make-topic-registry-diagnostic))

(defparameter *topic-files-topicmap-db*
  (merge-pathnames "topic-files-topicmap-mrepl/topics.sqlite"
                   (uiop:temporary-directory)))

(defparameter *topic-files-topicmap*
  (hyperdoc:make-topic-files-topicmap
   :source-files
   (hyperdoc:topic-registry-diagnostic-loaded-topic-files-of
    *topic-registry-diagnostic*)
   :db-path *topic-files-topicmap-db*))

(defparameter *topic-files-topicmap-result*
  (hyperdoc:materialize-topic-files-topicmap *topic-files-topicmap*))

(defparameter *topic-files-topicmap-payload*
  (hyperdoc:topic-files-topicmap-payload *topic-files-topicmap*))

(format t "~&topicmap type: ~S~%" (type-of *topic-files-topicmap*))
(format t "status: ~S~%"
        (hyperdoc::topic-files-topicmap-materialization-status-of
         *topic-files-topicmap*))
(format t "source files: ~D~%"
        (length
         (hyperdoc::topic-files-topicmap-source-files-of
          *topic-files-topicmap*)))
(format t "payload nodes: ~D edges: ~D~%"
        (length (getf *topic-files-topicmap-payload* :nodes))
        (length (getf *topic-files-topicmap-payload* :edges)))

Replay checks

  • Load :hyperdoc and :hyperdoc/inspector.
  • Construct (make-topic-registry-diagnostic).
  • Construct a topic-files-topicmap with a temporary SQLite path.
  • Run materialize-topic-files-topicmap.
  • Assert source files, topic_factory rows, and topic_node rows are non-empty.
  • Assert topic-files-topicmap-payload contains :nodes and :edges.
  • Assert inspector views include Overview, Files, Factories, Topicmap, and SQLite.
