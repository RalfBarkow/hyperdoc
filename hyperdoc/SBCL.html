  • Hosts Playground evaluation and debug surfaces.

Why SBCL matters beyond runtime use

SBCL is also interesting as a build architecture case. Christophe Rhodes's 2008 paper on sanely bootstrappable Common Lisp describes SBCL as a system that uses a host Common Lisp image during bootstrap while deliberately containing that image dependence so the final target build does not depend on accidental host-image state.

That makes SBCL useful to HyperDoc for more than server/runtime reasons. It clarifies the boundary between image-oriented development during live exploration or implementation work and source-oriented development as the durable rebuild path that contributors can verify from scratch.

The same paper also frames bootstrappability as social architecture: reducing special bootstrap knowledge lowers contributor friction and makes it easier for newcomers to work on the implementation.
