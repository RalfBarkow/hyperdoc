Why documentation surfaces matter

HyperDoc work spans multiple media. Explicit surface definitions keep structure stable: they prevent category mistakes such as treating all artifacts as interchangeable or assuming one representation can substitute for all others.

Durable HyperDoc pages

Durable pages in hyperdoc/*.html and hyperdoc/*.md capture architectural distinctions, stable operational guidance, and reference links. They are intended to remain readable and reusable across iterations.

Topic objects in topics.lisp

Topic objects in hyperdoc/topics.lisp are explicit inspectable semantic handles with :id, :title, :summary, and :references. A HyperDoc page is not the same thing as a topic object: pages carry narrative structure; topics carry inspectable concept identity.

Inspectable objects embedded in pages

Inspectable objects in pages are embedded explanatory handles, typically via expr links. They are not only navigation links; they expose runtime objects that can be inspected with views and used as semantic anchors in explanation.

FedWiki twins as parallel knowledge artifacts

FedWiki twins are parallel artifacts for journaling, iteration, and collaborative editing. They are not literal serialization targets for every HTML detail in HyperDoc pages. Correspondence should preserve topic-level intent, not enforce markup identity.

Cross-linking and correspondence rules

  • Cross-link surfaces by stable topic/page intent, not by requiring identical structure.
  • Use explicit links between HyperDoc pages, topic objects, and FedWiki twins where useful.
  • Prefer additive updates to twins; avoid destructive overwrite workflows.

What belongs on which surface

  • Durable HyperDoc pages: stable distinctions, architecture, and guidance.
  • Topic objects: inspectable concept handles and curated reference lists.
  • Inspectable objects in pages: runtime explanatory entry points for concepts/workflows/examples.
  • FedWiki twins: parallel working/journaling artifacts with topic correspondence.

Failure modes and drift risks

  • False symmetry: assuming page, topic object, and twin are equivalent artifacts.
  • Structure drift: moving concept ownership into whatever surface is easiest to edit.
  • Link drift: missing correspondence links between durable and working surfaces.

Practical authoring guidance

  1. Write or update a durable page when a distinction should guide future work.
  2. Add or update topic objects when a concept needs explicit inspectable identity.
  3. Add Inspectable objects entries when page claims should be tied to inspectable runtime handles.
  4. Create or update FedWiki twins when collaborative iteration/journaling is needed.
  5. Check correspondence links, but do not force identical shape across surfaces.
