Layering visible on the site

  • YTools: a base utility layer for Lisp, including iteration aids, formatted I/O, file management, and a rewritten file manager.
  • Lexiparse: a precedence-grammar parser with lexer and translation framework; it depends on YTools.
  • Nisp / YNisp: a strongly typed Lisp dialect implemented as macros; the newer form is described as YTools + ydecl.
  • Nity: a polymorphic type system used by Opt and intended as a future typing substrate for Nisp.
  • Opt: a knowledge-representation language based on type theory and positioned as a successor to PDDL.
  • Optop: an estimated-regression planner on top of Opt that can reason about autonomous processes.

Why this matters

HyperDoc often needs examples of systems that are not just libraries but small conceptual stacks. This one is valuable because utility support, type discipline, representation language, and planning engine remain visible as distinct layers rather than collapsing into one opaque tool.

That is also where the Mind and Mechanism seam belongs. The book is relevant here only insofar as it clarifies why computational explanation and representation matter once they change what the system can actually do. It does not add a second software stack beside the one already preserved on this page.

Import stance

Preserve the stack as an explanatory page plus reusable topics. Do not treat the old installation snippet as an operational recipe for current Common Lisp practice. It belongs as historical packaging evidence, not as present-day advice for this repository.
