Linking HyperDoc pages to FedWiki pages

This page documents one linking model only: a FedWiki page should be named by site plus page slug.

Connected communication surfaces

These links are not just technical pointers. They connect two communication surfaces for the same topic:

  • HyperDoc pages provide durable, inspectable reference context.
  • FedWiki pages provide editable, journaled working context.

For workflow-relevant topics, keep at least one navigable path between both surfaces. The FedWiki page store for localhost workflows is /Users/rgb/.wiki/wiki.ralfbarkow.ch/pages.

Idea 1: the site is part of the page identity

A FedWiki page is not identified by title alone. The same title can exist on many sites. Therefore the link must preserve the owning site.

HyperDoc should express that site as the HyperBook id. 

<a hyperbook="fedwiki:wiki.ralfbarkow.ch" page="find">FIND</a>

Idea 2: the slug is the stable page handle

The page part of the link should be the FedWiki slug, not just a display title. This fits collaborative-link resolution more closely and avoids hiding the real lookup model. 

<a hyperbook="fedwiki:wiki.ralfbarkow.ch" page="walk">WALK</a>

Idea 3: stay inside the HyperBook model first

The first choice should be an inspectable HyperBook link, not a plain browser hop. That keeps the destination available through normal views such as Story, Links, and Context.

Idea 4: fallback is secondary

If the relevant FedWiki HyperBook is not yet present, the system should prefer to resolve it through hyperbook:find-hyperbook. A raw external URL is only the fallback path.

Idea 5: this matters for workflow pages

The workflow around FIND, WALK, PRINT, and REVIEW becomes much more useful when a HyperDoc concept page can open the concrete FedWiki pages that carry the workflow.
