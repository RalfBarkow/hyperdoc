NOR Matcher Research Report

hyperdoc

This report situates the NOR matcher teaching demo in a narrow research neighborhood: switching logic, closure-compiled interpreters, continuation passing, regular-expression compilation, live Lisp development, and programming-education tracing.

The purpose is not to turn the NOR matcher into a production search engine. The purpose is to make a small object language inspectable enough that a beginner can see how logical forms become executable closure networks.

Thesis

The NOR matcher is best understood as a small compiler. Its source language contains strings and nor forms. Its target representation is not generated Lisp source and not machine code. Its target representation is a network of closures connected by explicit success and failure continuations.

This makes the demo a useful hinge between three teaching concerns:

  1. Boolean logic: one connective is enough.
  2. Lisp execution: functions are values and closures remember context.
  3. Compilation: an expression can be transformed once and executed many times.

1. Logical substrate: NOR as the only connective

A NOR form succeeds only when every subform fails. The demo therefore treats (nor A B C) as the primitive connective and derives the usual logical operations from it: 

(not A)    = (nor A)
(or A B)   = (nor (nor A B))
(and A B)  = (nor (nor A) (nor B))

This is the teaching bridge to George Spencer-Brown's Design with the NOR: the point is not merely that NOR is a hardware gate, but that a single operation can generate a complete logical vocabulary.

2. The matcher as a closure compiler

The central implementation function is nor-demo-make-nor-matcher. It receives a list of subforms and two continuations: one for success and one for failure. Empty NOR returns the success continuation. A non-empty NOR builds a matcher for the first subform and a matcher for the rest.

nor-demo-make-nor-matcher

The important instructional move is that success of any subform causes the enclosing NOR to fail immediately. Failure of a subform permits evaluation to continue with the rest of the NOR.

3. Continuation-passing shape

Although the code is ordinary Common Lisp, its control structure is continuation-passing in miniature. Each compiled matcher receives a target string and decides which next function to call. This makes short-circuiting explicit. 

subform succeeds  -> call failure continuation of enclosing NOR
subform fails     -> continue with the rest of the NOR
all subforms fail -> call success continuation

For teaching, this is preferable to beginning with a general account of CPS. The learner can first observe a concrete trace and then name the pattern.

4. Relation to regular-expression compilation

The matcher is not a regular-expression engine, but it belongs to the same family of ideas: translate a compact pattern language into an executable recognition structure. Classical regular-expression work translates regular expressions to automata. This demo translates symbolic query expressions to closures.

The boundary matters. An automaton-oriented implementation would make states and transitions primary. The NOR matcher makes continuations primary. That is exactly why it is a good Common Lisp teaching object.

5. Relation to definitional interpreters and partial evaluation

A direct interpreter would walk the query expression every time it checks a target string. The NOR demo instead walks the query once and returns a specialized matcher. That makes it a small, concrete example of the same general move studied in definitional interpreters and partial evaluation: separate the stable program from the changing input. 

interpreter style:
  run expression + target together every time

closure-compiler style:
  compile expression once
  run resulting matcher on many targets

6. Relation to live Lisp development

The demo should be taught from the REPL and the HyperDoc page together. The REPL shows live construction, redefinition, tracing, and inspection. HyperDoc supplies a durable story page with runnable examples.

This pairing is especially Lisp-like: the running image is useful because it can be interrogated and changed, but the durable source page remains the authority for rebuilding and reviewing the teaching object.

7. Relation to program-tracing pedagogy

The report returned by nor-demo-run is deliberately inspectable: it contains the expression, target, result, and trace. That trace is the learner-facing object. It turns invisible control flow into a sequence of visible decisions.

nor-demo-run

This makes the demo adjacent to educational tracing systems: the trace is not only debugging output, but also an explanatory artifact. The learner can compare the general rule for NOR with a concrete execution trace.

8. Demonstration arc

  1. Start with (nor) and show that empty NOR succeeds.
  2. Move to (nor "shuttle" "joke") on a sentence with neither word.
  3. Run the same form on a sentence containing a forbidden word.
  4. Point to the :nor-short-circuit trace event.
  5. Only then show the full NOR-only version of the original query.

Boundary

Do not overclaim this demo. It is not a complete Boolean algebra library, not a high-performance regular-expression system, and not a general-purpose compiler. It is a compact teaching specimen: a single-connective object language compiled into inspectable closures.
