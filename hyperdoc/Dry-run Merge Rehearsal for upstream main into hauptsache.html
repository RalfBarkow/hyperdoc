Dry-run Merge Rehearsal for upstream main into hauptsache

hyperdoc

This page adds a non-destructive merge rehearsal surface on top of the existing merge forecast, manual proposals, and executable dreyeck scaffold. The durable object is a typed git-merge-rehearsal, not only a note that a dry run happened.

In this slice the rehearsal mechanism is git merge-tree --write-tree --name-only against the explicit anchor commits. That keeps the working branch untouched while still recording a real virtual merge tree hash, the raw conflict set, and whether the current downstream scaffold is sufficient for the proposed ASDF and package direction.

At the current anchors that raw conflict set resolves into a typed current manual merge-driving frontier of six paths: one historical dossier raw conflict plus five promoted extra raw conflicts, with no untyped remainder.

Views

  • 👀merge-rehearsal shows the mechanism, merge-base anchor, virtual merge-tree hash, extra raw conflicts outside the current manual dossier, scaffold evidence, and the path-level results.
  • 👀summary on the rehearsal object shows the core counts and scaffold sufficiency status.
  • 👀rehearsal-results focuses the same object on the manual-conflict result table.
  • 👀execution-recipes on the execution-recipe surface turns the six proposal-backed paths into execution-grade splice guidance.
  • 👀current-frontier on the current manual merge-driving frontier object turns the raw results into the active merge gate and shows the six linked proposal objects and six linked execution recipes that now cover it.

Why this is still narrow

This rehearsal does not execute git merge, does not create a merge commit, and does not mass-move dreyeck paths. It only records what the current virtual merge says about the named manual proposals, promotes the five additional typed raw conflicts into the current frontier, and checks whether the first downstream scaffold is enough to support the intended direction. The follow-on proposal and execution-recipe layers are now complete enough that the remaining readiness question is execution quality, not missing guidance objects.
