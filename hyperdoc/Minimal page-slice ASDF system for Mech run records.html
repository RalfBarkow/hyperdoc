Minimal page-slice ASDF system for Mech run records

A narrow page-slice system for the Mech run-record material should follow the same basic pattern as the existing hyperdoc, hyperdoc/examples, and hyperdoc/examples/ops systems: one explicit defsystem, one real module rooted in the hyperdoc/ directory, and one Lisp source file that is loaded specifically so that the page's <source-of-function>...</source-of-function> references resolve in the running image.

Minimal defsystem shape

(asdf:defsystem #:hyperdoc/mech-run-records
  :description "Mech run-record documentation slice for HyperDoc"
  :author "Konrad Hinsen <konrad.hinsen@fastmail.net>"
  :license  "BSD"
  :version "0.0.1"
  :homepage "https://codeberg.org/khinsen/hyperdoc"
  :source-control (:git "https://codeberg.org/khinsen/hyperdoc.git")
  :serial t
  :depends-on (#:hyperdoc)
  :components ((:module "hyperdoc"
                :serial t
                :components ((:file "mech-run-record-examples"))))))

That is the smallest useful form. It keeps the page in the already indexed hyperdoc/ page directory, and adds only the file that must be loaded for the page's example function to exist.

Companion page

The page itself remains a normal HyperDoc text page, for example hyperdoc/First-class Mech Run Records in HyperDoc.html, and it should use: 

<source-of-function>mech-run-record-story-neighborhood-example</source-of-function>

That keeps the page idiomatic: the page shows an example by reference, and the system boundary guarantees that the referenced function is present when the slice is loaded.

Companion Lisp file

The companion source file should live at: 

hyperdoc/mech-run-record-examples.lisp

with content in the existing HyperDoc package, for example: 

(in-package :hyperdoc)

(defexample mech-run-record-story-neighborhood-example
  "Illustrative story-neighborhood run ledger for WALK 3 clicks, PRINT draft, and PREVIEW synopsis items."
  (-> '(:run-id "2026-03-16T12:00:00Z/walk-3-clicks"
        :script ("WALK 3 clicks"
                 "PRINT draft"
                 "PREVIEW synopsis items")
        :steps ((:op :walk
                 :argument (3 :unit :clicks)
                 :result :aspects-collected)
                (:op :print
                 :argument :draft
                 :result :draft-generated)
                (:op :preview
                 :argument (:synopsis :items)
                 :result :report-page-generated))
        :artifacts ((:kind :draft
                     :label "Draft volume"
                     :derived-from :print)
                    (:kind :report-page
                     :label "Synopsis items"
                     :derived-from :preview))
        :findings ((:kind :coverage
                    :value "gateway pages present")
                   (:kind :boundary
                    :value "three-click expansion used"))
        :note "Illustrative example only; this is not a claim about current persisted Mech state.")
      (assert-true)))

Why this is the right minimum

It matches three existing repo rules at once. The extra FedWiki dependency is unnecessary unless the example starts constructing real FedWiki objects or calling FedWiki-specific helper code.

  • A HyperDoc lives inside a real ASDF system and its source files must be loaded as components of that system.
  • Examples belong to the ASDF system that owns the code and pages being explained.
  • Examples displayed via <source-of-function> only work when the source file containing the defexample has already been loaded into the image.

So the page-slice system is not a new abstraction layer. It is a small, explicit ASDF boundary that keeps one documentation page and its runnable example honest with respect to load order.

What not to include in the minimal system

  • No new HyperDoc root object.
  • No separate page directory.
  • No extra topic layer unless the page introduces reusable vocabulary.
  • No tests in the first cut.

Those can be added later. The minimum viable slice is just: page plus companion example file plus a small defsystem that loads the companion file.

Optional stricter variant

If you want the slice to verify itself, add one smoke test system next to it: 

(asdf:defsystem #:hyperdoc/mech-run-records/tests
  :description "Smoke tests for the Mech run-record documentation slice"
  :author "Konrad Hinsen <konrad.hinsen@fastmail.net>"
  :license  "BSD"
  :version "0.0.1"
  :homepage "https://codeberg.org/khinsen/hyperdoc"
  :source-control (:git "https://codeberg.org/khinsen/hyperdoc.git")
  :serial t
  :depends-on (#:hyperdoc/mech-run-records
               #:hyperdoc/tests)
  :components ((:module "tests"
                :serial t
                :components ((:file "mech-run-record-slice-smoke")))))

But that is optional. The exact minimal shape for your concrete Mech run-record page is the single hyperdoc/mech-run-records system shown above.
