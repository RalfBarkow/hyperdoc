Journalmatic Journal Checker

hyperdoc

The checker in client/modules/journal-checker.js is the center of the plugin. It computes a set of findings over a page and its journal.

Inspectable objects

  • Chronology violation
  • Replay precondition violation
  • FedWiki story item id policy
  • Journal checker commit gate
  • Journal gate script and Lisp implementation

What it checks

  • null story items
  • huge combined page/journal size
  • bloated journals relative to story size
  • malformed actions missing expected keys
  • chronology errors when dates go backward
  • creation errors when create is missing or not first
  • revision errors when replayed journal state does not match current story

The important move is that the checker does not stop at syntax. It also asks whether the journal can still reconstruct the page.

Design lesson

A HyperBook journal checker should return findings as inspectable values, ideally keywords or condition-like report objects, rather than only printing a diagnostic string.

Commit routine integration

Treat the checker as a commit gate for localhost FedWiki page edits. python3 -m json.tool checks syntax only; journalmatic must still be clear of CREATION, CHRONOLOGY, REVISION, and MALFORMED findings before commit.

Keep commits in meaningful slices: journal repair-only commits first, then separate content/topic updates. Keep HyperDoc and localhost FedWiki commits in separate repositories and avoid push unless explicitly requested.

Timestamp note: a previous manual page-generation pass used hardcoded dates. When such dates are ahead of real fork time, the later fork action can receive a smaller date and trigger chronology/revision findings. Use runtime epoch-millis with monotonic bump from the last action date.

If chronology is already broken, apply monotonic normalization to action dates in existing action order before replay verification.
