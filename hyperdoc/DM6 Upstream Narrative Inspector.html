Why this inspector exists

Topic 968908, “What Jörg’s codebase is doing,” reframes the work as an architectural integration problem rather than a normal branch merge.

  • Jörg’s branch modularizes dm6 around renderer/feature layers such as TopicMap.*, TopicList.*, Feature.*, Storage, and event plumbing.
  • Our branch preserves the HyperDoc embedding contract through src/AppEmbed.elm and the Elm.AppEmbed.init ABI.
  • The integration target is Jörg modular internals + AppEmbed public seam + HyperDoc evidence vocabulary.
  • We should inspect first, then merge on an integration branch, then move evidence hooks inward to the new mutation seams.

Non-negotiable AppEmbed contract

Elm.AppEmbed.init({
  node: stage,
  flags: {
    slug: String(slug),
    stored: String(stored || '{}')
  }
});

For HyperDoc, Main.elm is not sufficient. The stable public ABI is the compiled Elm.AppEmbed module accepting string flags { slug, stored }.

Evidence hook target map

Evidence kind        Best hook after Jörg integration
-----------------------------------------------------
init                 AppEmbed.init
import               AppEmbed flag decode / FedWiki import path
store snapshot       Storage.storeCmd or Storage.storeWith
selection            Feature.Sel or ItemClicked dispatch path
drag                 Shared.Events + Feature.Mouse / TopicMap.Mouse
cross-boundary       before/after containment transition

The main architectural change is that semantic evidence should move inward. AppEmbed remains the public seam, but storage, selection, drag, and cross-boundary evidence should come from the real mutation sites after the modular branch is integrated.

Safe integration branch sketch

cd ~/workspace/dm6-elm

git fetch upstream
git switch main
git switch -c integrate-jorg-hyperdoc

# inspect first; merge only after the narrative says where the risks are
git merge --no-commit upstream/master

Use a named integration branch. Do not mutate main directly while preserving the cross-repository milestone story.

Acceptance criteria before merging

  • src/AppEmbed.elm exists and compiles.
  • The compiled bundle exports Elm.AppEmbed.
  • Flags remain { slug : String, stored : String }.
  • HyperDoc receives evidence for init/import/store/selection/drag/cross.
  • Store evidence is emitted once per semantic store, not twice from both wrapper and storage layer.
  • Cross-boundary evidence is based on before/after containment, not a particular internal message constructor.
