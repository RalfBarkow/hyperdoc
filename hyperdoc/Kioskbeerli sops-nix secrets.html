Kioskbeerli sops-nix secrets

This page documents the inspectable ASDF subsystem for the next planned Kioskbeerli Pi mutation: create encrypted sops-nix secrets. The subsystem is :kioskbeerli/sops-nix-secrets. It is plan-only by default and does not mutate the Raspberry Pi.

The starting boundary is the completed Kioskbeerli Den base-system milestone: the Pi survived flake-based test, switch, and reboot. The next intended secret is users/guest/hashed-password, represented as a runtime file path and task target only. This documentation and subsystem do not contain, print, store, or commit cleartext secret values or password hashes.

Inspectable subsystem

Load the subsystem from SLY or another ASDF-capable image: 

(asdf:load-system :kioskbeerli/sops-nix-secrets)

Main inspectable entrypoints:

  • (kioskbeerli/sops-nix-secrets:make-sops-nix-secrets-plan)
  • (kioskbeerli/sops-nix-secrets:make-sops-nix-secrets-session)
  • (kioskbeerli/sops-nix-secrets:sops-nix-secrets-scxml-chart)
  • (kioskbeerli/sops-nix-secrets:sops-nix-secrets-topic-bundle)
  • (kioskbeerli/sops-nix-secrets:sops-nix-secrets-next-actions)
  • (kioskbeerli/sops-nix-secrets:inspect-sops-nix-secrets-plan)

Minimal SLY inspection sequence: 

(asdf:load-system :kioskbeerli/sops-nix-secrets)

(defparameter *example-plan*
  (kioskbeerli/sops-nix-secrets:make-sops-nix-secrets-plan))

(defparameter *example-session*
  (kioskbeerli/sops-nix-secrets:make-sops-nix-secrets-session
   :plan *example-plan*))

(format t "~&~A~%mode=~S tasks=~D next=~D~%"
        (type-of *example-session*)
        (kioskbeerli/sops-nix-secrets:execution-mode-of *example-session*)
        (length
         (kioskbeerli/sops-nix-secrets:tasks-of *example-plan*))
        (length
         (kioskbeerli/sops-nix-secrets:next-actions-of *example-session*)))

(i *example-session*)

Plan tasks

The plan records the intended mutation as inspectable tasks rather than executable operations: 

verify-den-base-milestone
check-local-sops-tools
check-local-age-identity
derive-pi-age-recipient
draft-sops-yaml
create-encrypted-secret-file
verify-secret-file-is-encrypted
patch-host-module-enable-secrets
stage-secret-files
apply-secret-files-through-root-boundary
evaluate-flake-secrets
run-nixos-rebuild-test
verify-run-secrets
switch-secrets-configuration
reboot-verify-secrets
record-sops-milestone

Each task has preconditions, effects, status, evidence, an SCXML state link, and optional manual command specifications. The default execution mode is :plan-only. Command specifications are inspectable records; they are not executed by the subsystem or by smoke tests.

Topic taxonomy

The topic bundle separates five kinds of evidence-bearing concepts:

  • task topics for the plan steps
  • concept topics such as encrypted secret, sops-nix, age recipient, cleartext boundary, root boundary, activation-time decryption, and rollback point
  • reference topics for /etc/nixos/.sops.yaml, /etc/nixos/secrets/kioskbeerli.yaml, /etc/nixos/nix/nixos/modules/secrets-sops.nix, /etc/nixos/nix/nixos/hosts/kioskbeerli-pi.nix, ~/.config/sops/age/keys.txt, /run/secrets/users/guest/hashed-password, and var/kioskbeerli-pi-backup/
  • guard and failure topics for missing tools, plaintext detection, eval failure, rebuild-test failure, and decryption failure
  • recovery topics that return the operator to inspection and test boundaries without exposing secret material

Behavior contract

The SCXML artifact is kioskbeerli/sops-nix-secrets/sops-nix-secrets.scxml. Its progress states are: 

den-base-verified
tools-available
age-identity-ready
recipients-ready
policy-drafted
secret-encrypted
host-module-patched
files-staged
root-applied
flake-evaluated
test-activated
runtime-secret-verified
switched
complete

Its blocked states are missing-tools, plaintext-detected, eval-failed, rebuild-test-failed, and decryption-failed.

Guard boundary

The subsystem guards these boundaries:

  • no cleartext secret in Lisp output
  • no cleartext secret in committed files
  • no password hash in SLY transcript
  • no switch before rebuild test
  • no kiosk enablement
  • no hostname forcing
  • no DMX writes
  • no Pi mutation in the default plan-only path

The first actual rebuild boundary, when the operator explicitly chooses to perform the mutation later, remains nixos-rebuild test --flake .#kioskbeerli-pi. A switch is not the first operation.

Tests

(kioskbeerli/sops-nix-secrets/tests:run-sops-nix-secrets-smoke-tests)

The smoke tests prove ASDF loading, task shape, SCXML parsing, task-to-state links, topic bundle categories, plan-only execution mode, non-execution of command specs, and absence of secret-looking fixture material.

Boundary

This page and subsystem do not implement sops-nix, do not create real secrets, do not run nixos-rebuild, do not mutate the Pi, do not write to DMX, do not enable kiosk/Cage/Chromium, and do not force the runtime hostname from myhostname to kioskbeerli.
