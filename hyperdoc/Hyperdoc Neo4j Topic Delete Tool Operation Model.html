Hyperdoc Neo4j Topic Delete Tool Operation Model

This page records the first safe modeling milestone for tools/HyperdocNeo4jTopicDeleteTool.java. The milestone is source parity: HyperDoc can inspect the Java tool command surface as data, but it does not change deletion behavior and does not execute the tool. This first milestone is source parity, not behavioral change.

Why model the tool as operations?

The Java helper is a hand-audited offline Neo4j repair tool. It was used in the reconstruction of the 936040 incident, where a workspace n/a annotation topic was removed from an offline local DMX Neo4j store and then second-order orphan association/context nodes had to be cleaned up so topicmap fetches would work again.

Modeling the command surface as operation IR makes the boundary inspectable: readers can see command names, arities, confirmation tokens, read/write classification, known statuses, and warnings without opening a database or running Java. This is useful because the tool is intentionally not a generic node deleter. Its supported scope is HyperDoc-owned workspace annotation cleanup in an offline store.

What is intentionally not generated?

HyperDoc does not generate low-level Neo4j graph mutation logic from SCXML in this milestone. The deletion closure remains in HyperdocNeo4jTopicDeleteTool.java, where it is still hand-audited. The generated/reconstructed model covers only command names, arities, confirmation tokens, usage metadata, safety classification, inspector descriptions, and state-machine capability structure.

SCXML capability model

The SCXML file hyperdoc/hyperdoc-neo4j-topic-delete-tool-capability-model.scxml models the generic capability state machine for the tool. It routes a received command to read-only reporting/planning states, planned destructive states, emergency destructive states, or terminal success/refusal/missing states.

This model is deliberately generic and not specific to topic 936040. The 936040 reconstruction explains why these capabilities must be visible as operations, but the SCXML model describes the Java tool command surface rather than the single incident.

Safety boundary

  • The operation IR is read by Lisp as static data.
  • The inspector exposes metadata and command previews only.
  • No inspector action executes a Java command.
  • No test opens or mutates a Neo4j database.
  • The hand-audited Java deletion closure remains authoritative.
