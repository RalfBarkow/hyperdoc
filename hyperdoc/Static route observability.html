Static route observability

hyperdoc

Static route observability is the reusable skill for answering one narrow question first: which runtime component owns a public static asset path? This first skill slice is based on static computation from the current server wiring, not on live HTTP probing.

In the current runtime, /boot.html, /js/boot.js, and /js/jquery.min.js belong to the active CLOG static root, while /hyperbook-server/js/url.js belongs to an explicit views:add-asset-path mount owned by HyperBook server views.

What the skill makes explicit

  • the public request path,
  • the owning route contract,
  • the root directory that should serve the file,
  • the concrete resolved file path on disk.

Worked examples from this repo

  • /js/boot.js: the patched-boot investigation only became clear once the route was treated as a CLOG static-root asset instead of a generic JavaScript file.
  • /hyperbook-server/js/url.js: the URL-tab helper regression was a mounted-asset contract problem, not a global static-root problem.
