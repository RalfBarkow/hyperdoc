Normal association submit path vs evidence path

hyperdoc

This page makes the submit-boundary asymmetry explicit between the standard Connect association submit path and the request-evidence path. The key distinction is not a generic difference between two buttons. It is that the normal association path makes source-json and target-json authoritative on the payload-bearing element, whereas the evidence path makes snapshot-json authoritative on the payload-bearing element.

Operational asymmetry

In the normal association path, writeSubmitPayload() writes request id, context, source/target JSON, field ids, pane ids, and provider kinds onto the clicked submit button and tags that button with button-payload-v2. It does not attach data-dom-connect-snapshot-json to that authoritative payload element. Snapshot transport is therefore only a fallback path through the hidden inspect field if that field exists and is still readable at submit time.

In the evidence path, prepareEvidenceButton() tags the evidence button with connect-request-evidence-v1 and writes data-dom-connect-snapshot-json directly onto that payload-bearing button. It also mirrors the same JSON into the hidden inspect field, but that mirror is secondary. The inline snapshot JSON on the button is the authoritative transport carrier for later request-evidence reconstruction.

Server seam

The server-side seam is shared but the two paths meet it differently. dom-association-submit-payload reads snapshot JSON from data-dom-connect-snapshot-json on the payload-bearing element first and only then falls back to the hidden control referenced by data-dom-connect-snapshot-field-id. That means ensure-dom-connect-request-evidence and maybe-dom-connect-session-snapshot-from-json-string can only reconstruct a submit-boundary session snapshot when snapshot JSON was actually transported and parseable.

How to read "No submit-boundary session snapshot was captured."

That message does not necessarily mean the request failed. It can mean that the normal association path successfully transported source-json and target-json authoritatively enough to create or open the association object, but did not transport snapshot-json authoritatively on the payload-bearing element. In that case the later request-evidence object may still have request metadata and source/target anchors while lacking a reconstructed session snapshot.
