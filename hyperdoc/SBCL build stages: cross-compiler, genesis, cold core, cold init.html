SBCL build stages: cross-compiler, genesis, cold core, cold init

hyperdoc

This page makes the SBCL bootstrap pipeline inspectable as a sequence of stages. The important nouns are not vague “build magic,” but a host Lisp, a target-directed cross-compiler, target FASLs, genesis, the cold core, and cold init.

Stage 1: host Lisp and bootstrap compiler loading

The process begins in a host Common Lisp implementation. That host image loads the bootstrap machinery needed to compile target-side code. This is the live-image side of the build, but it is still only the first stage, not the final product.

Stage 2: cross-compiler emits target artifacts

The cross-compiler runs in the host but emits target SBCL FASLs. This stage matters because it starts to convert host-assisted bootstrap work into explicit target artifacts that can be handed to the next phase.

Stage 3: genesis writes the cold core

In the genesis build stage, SBCL simulates loading the target artifacts and writes the cold core. This is where the build stops being “just load more things into the host image” and starts becoming a distinct target image with its own startup boundary.

Stage 4: runtime performs cold init

The SBCL runtime starts from the cold core and performs cold init. This completes target-side initialization and yields the running SBCL system.

Why the stages matter

The pipeline is useful because it enforces host/target separation and supports bootstrap determinism. Each stage narrows the room for accidental dependence on host-image state and makes the final result more reconstructable from explicit inputs.
