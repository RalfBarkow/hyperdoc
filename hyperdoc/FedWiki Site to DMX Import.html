FedWiki Site to DMX Import

This feature imports a whole local FedWiki site into DMX as runtime data. It is an importer/synchronizer, not a generator for hundreds of authored topic constructors in the Topics HyperBook.

Goal

The importer enumerates local pages from an existing FedWiki hyperbook, derives a deterministic summary from each page story, builds a DMX payload, and upserts by a stable external key so repeated runs do not create duplicates.

Identity model

Imported identity is based on site domain plus local page slug, not on page title. The stable external key has the shape fedwiki:<domain>/<slug>.

Titles can change later. Slug plus domain remains the durable import key, and the importer stores that external key as the DMX topic uri. Slug remains a typed child topic, and the provenance envelope preserves the source HTML URL, JSON URL, source kind, and journal timestamp when available.

DMX write model

The importer currently reuses the fedwiki.page topic type and related children from the early-stage dmx-fedwiki plugin in the local dmx-platform source rather than inventing a new write protocol. That is an emerging plugin write model, not a finalized DMX platform contract. It currently writes typed children for fedwiki.slug, fedwiki.title, and fedwiki.page.json.

Because the existing fedwiki.page schema does not carry a dedicated site-domain child topic, the importer keeps the stable site-plus-slug identity in the DMX topic uri and serializes the full provenance envelope into fedwiki.page.json alongside the raw fetched page JSON.

Live lookup and writes follow the DMX core REST API: GET /core/topic/uri/<uri> for idempotent lookup, POST /core/topic for create, and PUT /core/topic/<id> for update. The endpoints are part of DMX core, but the FedWiki-oriented write model is supplied by a plugin-level extension. See DMX FedWiki Write Model.

Why this is not the Topics HyperBook

The Topics HyperBook is for authored and curated topic pages with title-based page ids. A bulk site import would pollute that authored surface and would collapse slug identity into titles. The importer instead treats FedWiki pages as runtime import candidates and writes them into DMX under stable external keys.

Dry-run and live mode

Dry-run is the default. It prints candidate rows and a create/update summary without writing to DMX. Live mode uses the same planning path but performs creates or updates through a separately configured DMX client. 

nix develop --command sbcl --no-userinit --non-interactive \
  --eval '(require :asdf)' \
  --eval '(asdf:load-system :hyperdoc :force t)' \
  --load tools/import-fedwiki-site-to-dmx.lisp -- \
  --domain sfw.c2.com --dry-run

nix develop --command sbcl --no-userinit --non-interactive \
  --eval '(require :asdf)' \
  --eval '(asdf:load-system :hyperdoc :force t)' \
  --load tools/import-fedwiki-site-to-dmx.lisp -- \
  --domain sfw.c2.com --dry-run --limit 10 --verbose

Failure modes

  • FedWiki sitemap or page fetch fails: the run stops on the network/read error.
  • Duplicate external keys appear in one run: the importer signals a duplicate-key condition instead of guessing.
  • Live mode is requested without HYPERDOC_DMX_IMPORT_BASE_URL: the importer signals a configuration error immediately.
  • DMX base URL configuration is absent in dry-run: the importer still works, but it assumes unmatched keys would be creates.
  • Write credentials are absent or rejected: the DMX server returns an authorization failure on the live REST call.

Authentication

The importer accepts either a full HYPERDOC_DMX_IMPORT_AUTH_HEADER value or HYPERDOC_DMX_IMPORT_USERNAME plus HYPERDOC_DMX_IMPORT_PASSWORD for HTTP Basic authentication. This mirrors the local dmx-platform access-control layer, which parses the HTTP Authorization header.

Relationship to DMX runtime proxies

This importer writes or plans DMX topic data. That is a different concern from the existing DMX runtime proxy surface in the inspector. Proxy objects are for reading known DMX topic ids at runtime; the importer is for synchronizing FedWiki page data into DMX first.
