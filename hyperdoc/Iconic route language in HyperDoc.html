Iconic route language in HyperDoc

hyperdoc

This page assimilates Aleksander & Morton 1993, A Neural State Machine for Iconic Language Representation, into HyperDoc as a narrow route-language refinement. The point is not to replace HyperDoc's existing station/route framing with paper jargon. It is to make that framing more semantically explicit: Touch-Fahrplan in HyperDoc can be read as a route language for grounded semantic retrieval, with gestures and mechanics underneath it rather than above it.

Operational objects

The paper's abstract claims are operationalized here as inspectable route-language objects, not as a neural runtime. The cue remains symbolic, the source station remains grounded, and understanding is represented as the retrieval route that links them.

The route-language example is primary. The NSMM object is exposed only as a supporting formalization of that route-level reading, not as a replacement abstraction for HyperDoc.

Conceptual order

The intended order in HyperDoc is: station -> route -> retrieval -> inspection -> gesture/mechanic. A station is first. A route between stations is second. Only then does it make sense to ask how a route is followed, inspected, or physically enacted.

This matters because the route is not merely a graph edge. It can be a durable retrieval relation between a cue and a grounded semantic state. A station is therefore more than a node label: it can be an inspectable world-state proxy, iconic state, evidence locus, or interpretation anchor.

HyperDoc reading of the paper

The iconic hypothesis is useful here because it treats language as a vehicle for retrieving richer representation rather than as a flat arbitrary label assignment. In HyperDoc terms, understanding succeeds when a route leads back into the right inspectable state, evidence chain, or trajectory, and fails when the cue does not recover the state that would make later interpretation or action intelligible.

The paper's Neural State Machine Model is relevant because it treats semantic distinction as a matter of state trajectories, not just static tokens. In HyperDoc prose, that means Follow route can name semantic re-entry into a grounded/iconic state, a trajectory through evidence, or an interpretation path. It does not need to mean only graph traversal.

The paper's two worked patterns matter locally as well. The cup example shows that a multimodal association can settle into a reentrant iconic state that a cue later retrieves. The rock-versus-curtain example shows that distinct semantics can live in distinct trajectories through iconic state structure, not only in flat labels attached after analysis.

Station and route definitions

A station in this reading is a potentially grounded semantic station: an inspectable proxy for the source meaning, world-state, document evidence, or local interpretation that matters to a task.

A route is a first-class retrieval relation between stations. It may connect a topic to a Zotero source, a source station to an annotation judgment, or a symbol-like cue to the inspectable evidence that makes it semantically useful. The route is durable because the retrieval path itself matters, not only its endpoints.

Lay route therefore means more than creating a connection. It can mean authoring or strengthening a retrieval path. Follow route means more than traversing an edge. It can mean re-entering the grounded state, trajectory, evidence chain, or interpretation path that lets a cue count as understood.

Inspection and trajectory

HyperDoc adds an inspection bias to this assimilation. The point is not to claim that the paper hands HyperDoc an implementation plan. The point is that HyperDoc can expose stations, routes, plans, reports, and annotations as inspectable objects, which makes grounded retrieval legible instead of implicit.

In the narrow operational model exposed above, a world-state proxy is the grounded station, a linguistic retrieval cue is the symbolic route starter, an iconic state is the inspectable grounded representation, a retrieval route is the first-class relation between them, and a trajectory records the understanding path that makes the route more than a static label link.

The supporting operational page Inspectable iconic retrieval objects exposes the fuller paper-backed example surface without turning this page into a second conceptual center.

Trajectory matters here because a later state can mean something different depending on the path that led to it. HyperDoc already preserves this kind of distinction in route chains, evidence sequences, and authorial review paths. The iconic-route reading simply makes that semantics explicit.

Boundary

This is a conceptual assimilation, not a runtime plan for gesture recognition, McCLIM implementation, or neural modeling. It leaves the existing Touch-Fahrplan station/route/Lay route framing intact and deepens it by treating routes as retrieval relations and stations as potentially grounded semantic stations.
