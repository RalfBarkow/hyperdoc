Graph leaf test

A graph leaf test succeeds when it finds a witness in the target graph. It returns both a Boolean result and evidence. A failed leaf still appears in the trace with :matched-p NIL and :evidence NIL. 

(:agent-alive lefty)
(:agent-symbol lefty L)

Missing agents do not silently count as dead. The :agent-dead leaf succeeds only when the agent exists and its alive slot is false.

Active/alive pair

For this teaching graph, Lefty and Rita are graph agents, not Mech execution engines. An active/alive pair exists when two alive agents are connected by their principal ports. 

(:active-alive-pair lefty rita)

The successful evidence names the leaf, the two agents, the edge, both oriented ports, and the alive reason. The matcher only observes that witness; it does not reduce the graph.

NOR over graph predicates

NOR keeps its truth rule over graph predicates: a nor form succeeds only when every child form fails. It short-circuits to failure when any child succeeds. 

(nor (:active-alive-pair lefty rita))

This means: it is not the case that Lefty and Rita form an active/alive pair. On the active fixture, the child succeeds and the NOR fails immediately.

Normal-form query

(nor (:any-active-alive-pair))

This is the normal-form query for the teaching demo. It succeeds when the graph has no active/alive pair anywhere. It fails as soon as the graph exposes one reducible active/alive pair witness.

Dispatcher

The graph matcher dispatches (nor ...) as logical syntax and keyword-headed forms as graph leaves. Unsupported forms signal an error rather than becoming false by accident.
