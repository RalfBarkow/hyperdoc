Ensuring Localhost FedWiki Counterparts for HyperDoc Pages

A practical way to keep HyperDoc and localhost FedWiki aligned is to treat the HyperDoc page set as the authoritative inventory, then ensure that each current HyperDoc HTML page has a localhost FedWiki counterpart.

The point is not to force the two forms to be identical in markup. The point is to ensure that each HyperDoc topic also exists as a writable localhost wiki page that can participate in everyday linking, journaling, and editing.

Inventory first

Start from the repository directory hyperdoc/ and collect the current *.html pages. That gives the authoritative set of HyperDoc text pages that should be mirrored.

For each page, derive its title from the page's <h1> text rather than from the filename. The title is the stable content identity used inside both HyperDoc and FedWiki.

Title to localhost slug

The corresponding localhost FedWiki page can be addressed by a slug derived from the title. A simple, defensible rule is: 

lowercase title
replace non-alphanumeric runs with '-'
collapse repeated '-'
trim leading and trailing '-'

This yields slugs such as:

  • HyperBook Journal Tools -> hyperbook-journal-tools
  • Running HyperDoc Examples -> running-hyperdoc-examples
  • Story Neighborhood Workflow -> story-neighborhood-workflow

Non-destructive rule

Do not overwrite an existing localhost page automatically. If the page already exists, assume it may contain local edits or journal history that should be preserved.

The safe default is therefore:

  1. detect all HyperDoc page titles
  2. compute the expected localhost slug for each title
  3. check whether that slug already exists in ~/.wiki/.../pages/
  4. create only the missing localhost pages

Structural conversion

A generated localhost page should preserve the topic structure, not the exact HTML. A simple conversion is sufficient for the first pass:

  • paragraphs stay paragraphs
  • <h4> sections become markdown headings
  • lists become markdown lists
  • <pre> and code blocks become fenced code
  • HyperDoc page links become FedWiki links by page title

This keeps the conceptual contents aligned while respecting the affordances of each medium.

Journal shape

Generated localhost pages should have a minimal valid FedWiki journal:

  • one create action first
  • one add action per story item
  • correct after chaining
  • stable item ids

This matters because malformed journals are harder to repair later than pages with simple but valid initial histories.

How to keep it current

This can be done as a repeatable maintenance step rather than a one-off import:

  1. scan hyperdoc/*.html
  2. compare against localhost slugs
  3. report the missing set
  4. generate only those pages
  5. optionally add index links from a current daily page

The key point is idempotence: rerunning the process should fill gaps without erasing local wiki work.

Why this works

HyperDoc remains the stable, inspectable narrative source. Localhost FedWiki remains the editable, journaled working surface. Ensuring a counterpart for each current HyperDoc page gives you coverage across both without forcing one representation to dominate the other.
