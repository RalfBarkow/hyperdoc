Diagnose static asset route ownership

hyperdoc

Diagnose static asset route ownership is the task skill for deciding whether a broken asset should be debugged as a CLOG static-root problem or as an explicit runtime asset-mount problem.

This task page is also static computation first. It tells you which route contract owns the path before you spend time on live probes or browser cache hypotheses.

  • hyperbook-server-url-js-static-asset-resolution

Procedure

  1. Inspect hyperdoc-static-asset-resolution-surface and read the Comparison view.
  2. If the failing path is /boot.html or under /js/, treat it as a CLOG static-root path first.
  3. If the failing path is under /hyperbook-server/, treat it as an explicit asset mount first.
  4. Only after ownership is clear, move on to live probes such as curl -I, browser reload, or process inspection.

Worked example boundary

The public /js/boot.js incident and the /hyperbook-server/js/url.js incident looked similar from the browser, but they belonged to different route contracts. This task exists so the next operator can separate those two cases before debugging the wrong layer.
