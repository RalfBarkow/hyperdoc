Reloading HyperDoc After Adding Lisp Objects

hyperdoc

A HyperDoc page can be correct in the repo and still fail at runtime if the running Lisp image was started before the referenced helper functions or objects existed.

The typical symptom is an error such as: 

The function HYPERDOC::KIOSKBEERLI-NIXPKGS-LOCK-OBJECT is undefined.

Inspectable objects

  • Undefined-function triage
  • ASDF component
  • asdf:load-system :force t

What this means

The page markup is being read correctly, but the current image does not yet contain the Lisp definition named in the page.

In practice this usually means one of two things:

  • the running image is stale and needs :hyperdoc reloaded
  • the referenced definition is not part of the loaded ASDF system

How to check

In the Playground, reload the system and check whether the function is now bound:

(progn (asdf:load-system :hyperdoc) (fboundp 'hyperdoc::kioskbeerli-nixpkgs-lock-object))

Expected result: a non-NIL value.

Pragmatic fix

Reload the system and reopen the page in a fresh pane:

(progn (asdf:load-system :hyperdoc) nil)

If the function is still undefined after reload, then the problem is not a stale image. The next thing to inspect is the ASDF system definition and whether the file containing the function is actually part of the loaded system.
