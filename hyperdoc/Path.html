Path

hyperdoc

A Path is a bounded, inspectable transformation chain with named intermediate states, explicit evidence, and a visible boundary where the chain either reaches its intended outcome or stops. In HyperDoc, a path should exist as a runtime object whose stages can be inspected, not only as page prose.

Path as object, not only prose

HyperDoc's evaluation model already separates value production from view rendering. A page expression produces a value object; the inspector then renders views for that object. A path therefore belongs in the runtime layer as an inspectable object with state, evidence, and boundaries.

The generic State machine abstraction is the reusable way to express such a path. DMX auth remains one worked example of that pattern rather than the model itself.
