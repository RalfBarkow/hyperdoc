Topic Title Changes and Canonical Link Maintenance

hyperdoc

This note documents the maintenance procedure for changing a HyperDoc topic title after the Topics HyperBook refactor.

Why title changes are special now

In the current Topics model, the canonical topic page id is the topic title. Authored topic links therefore use <a hyperbook="topics" page="Exact Topic Title">.

Backlinks are derived from those authored link targets. A title change is therefore also a link migration problem: changing the topic title without updating authored page= targets leaves old links pointing at a page id that no longer exists.

Current identity split

  • Canonical topic page id: topic title.
  • Identity anchor: topic :id / stable key.

The stable key remains useful for Lisp identity, audits, repair scripts, and migration tooling, but it is not the canonical page id that authored topic links resolve through. In this maintenance procedure, the stable key is the identity anchor for the same topic object while the title is being migrated.

Failure modes when a title changes without link migration

  • Authored hyperbook="topics" links that still point to the old title stop resolving.
  • Backlinks move to the new title only after authored links are updated; until then, the new topic page appears under-linked.
  • Readers may still see the old visible link text if markup migration is only partial.
  • Repair becomes harder if the stable key is not used to identify the intended topic object during migration.

Controlled rename scenario

Representative topic used for audit: HyperDoc runtime model, stable key hyperdoc-runtime-model.

If that title were renamed to HyperDoc runtime vocabulary model, the topic object could still be found by the same stable key, but every authored link whose page= value is HyperDoc runtime model would need to change to HyperDoc runtime vocabulary model. Until those link targets are migrated, the derived relation for the new title would remain incomplete and old links would fail page lookup.

Safe maintenance procedure

  1. Identify the topic by stable key in hyperdoc/topics.lisp, not by display text alone.
  2. Change the topic constructor’s :title to the new canonical title.
  3. Find all authored hyperbook="topics" links whose page= still uses the old title.
  4. Update those link targets to the exact new canonical title string.
  5. Keep visible link text aligned unless there is a deliberate reason for it to differ.
  6. Reload HyperDoc and verify the topic page resolves under the new title.
  7. Verify backlinks now appear on the new topic page and no authored links still target the old title.

What to verify before and after a title change

  • Before: count authored links that use the old canonical title.
  • Before: confirm the stable key still identifies the intended topic object.
  • After: confirm the topic page resolves by the new title.
  • After: confirm authored topic links now resolve with the new title string.
  • After: confirm backlink sources appear on the new topic page.
  • After: confirm no lingering authored links still use the old title.

Stable keys in repair and migration tooling

Stable keys are the safest handle for repair and migration because they do not depend on the reader-facing page title. They should be used to identify the intended topic object while title strings and authored topic links are being updated.
