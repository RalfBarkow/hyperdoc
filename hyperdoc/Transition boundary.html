Transition boundary

hyperdoc

A Transition boundary is a stage crossing during one concrete run. It records what stage was last reached, what condition had to be satisfied for the crossing, what evidence was emitted, and how failure was classified if the run stopped there.

What makes a transition boundary different

A contract boundary can exist even when no run is active. A transition boundary exists in motion: it is the stage edge where a concrete run crosses, pauses, or blocks.

  • It must record the last reached stage.
  • It must record whether the crossing was attempted.
  • It must record whether the crossing succeeded.
  • It must attach evidence and failure classification at the blocked or crossed point.

Worked DMX example

The DMX workspace-journal preflight is the current worked example. It is a transition boundary between a planned continuation and the later mutation stages that depend on a successfully prepared journal companion.

The blocked instance captures the current incident shape directly:

  • last reached stage: prepare-transition
  • crossing attempted: yes
  • crossing succeeded: no
  • failure classification: auth-blocked
