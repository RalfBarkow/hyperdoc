Clear Stale Nix Installer Backup Files on macOS

hyperdoc

This page documents the stale *.backup-before-nix blocker that can stop an upstream Nix reinstall on macOS even after the architecture problem has already been resolved.

Inspectable objects

What this blocker means

If the upstream installer correctly targets x86_64-darwin and then stops because /etc/bashrc.backup-before-nix already exists, the platform-selection problem is over. The remaining problem is stale installer backup state left by an earlier Nix install or uninstall attempt.

This is a safety stop, not a failed architecture match. The installer refuses to overwrite an earlier backup file blindly.

Inspect the backup file first

sudo ls -l /etc/bashrc /etc/bashrc.backup-before-nix 2>/dev/null || true
sudo sh -c 'printf "\n--- /etc/bashrc.backup-before-nix ---\n"; sed -n "1,200p" /etc/bashrc.backup-before-nix 2>/dev/null'
sudo sh -c 'printf "\n--- /etc/bashrc ---\n"; sed -n "1,200p" /etc/bashrc 2>/dev/null'

How to interpret the result

  • If /etc/bashrc does not exist, but /etc/bashrc.backup-before-nix exists and looks like a normal non-Nix shell file, move it back into place.
  • If /etc/bashrc already exists, for example as a live symlink to /etc/static/bashrc, do not restore the backup onto it. In that case the blocker is a stale backup file, not a missing original file.
  • If /etc/bashrc.backup-before-nix already contains Nix-added lines, do not restore it blindly.
  • If the backup content is ambiguous, keep it aside and inspect the other stale backup files before rerunning the installer.

Case 1: /etc/bashrc is missing

sudo mv /etc/bashrc.backup-before-nix /etc/bashrc

Case 2: /etc/bashrc is present

On the newer observed blocker, /etc/bashrc is already present as a live symlink to /etc/static/bashrc. In that case, do not restore the backup onto /etc/bashrc. Inspect the stale backup and the current live file first: 

# inspect first
sudo sh -c 'sed -n "1,200p" /etc/bashrc.backup-before-nix 2>/dev/null'
sudo sh -c 'sed -n "1,200p" /etc/bashrc 2>/dev/null'

If the backup looks like an ordinary old shell file and not something you need to preserve, move it aside so the installer can create a fresh backup of the current /etc/bashrc: 

sudo mv /etc/bashrc.backup-before-nix /etc/bashrc.backup-before-nix.stale

Broader stale-backup checklist

The same pattern can recur for other shell integration files:

  • /etc/profile.d/nix.sh.backup-before-nix
  • /etc/zshrc.backup-before-nix
  • /etc/bash.bashrc.backup-before-nix
  • /etc/zsh/zshrc.backup-before-nix

The upstream installer may stop on stale *.backup-before-nix files left by an earlier install. This is a safety stop, not a failed platform match. The correct response is to inspect the backup file, verify it does not already contain Nix-injected content, and then either restore it to the original path when the original file is missing or move it aside when the current live file is already present.

Rerun the installer

curl -L https://nixos.org/nix/install | sh
