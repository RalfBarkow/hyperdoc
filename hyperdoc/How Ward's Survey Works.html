How Ward's Survey Works

hyperdoc

Ward Cunningham's survey is easiest to understand as a fixed investigative progression: parse, inventory, drill down, inspect context, then compare similar occurrences.

Inspectable objects

  • Idiomatic survey
  • Usage view
  • Nesting view
  • Similar idioms
  • Structural recurrence

1. Parse the corpus

index.js reads every file in ../wiki-client/lib and parses them with Acorn. Each loaded module keeps the filename, source text, and parsed tree together.

2. Inventory node kinds and terminal values

The /index surface counts non-terminal node types across the whole corpus. From there, selected node kinds link to /terminal, which tallies distinct terminal values such as identifier names, operators, or literal values for one chosen field.

3. Drill into usage

The /usage surface lists every occurrence of the selected value and exposes adjustable structural context. Its width/depth controls let the reader expand or contract how much neighboring structure is shown around each hit.

4. Inspect nesting and local context

The /nesting surface takes one selected occurrence and shows the enclosing path through the walker stack together with a JSON rendering of the chosen hit. This is where local context stops being anecdotal and becomes inspectable.

5. Compare similar occurrences

The /similar surface normalizes a selected nested form and finds other occurrences with the same structural shape. That is the step that turns one interesting hit into evidence about recurrence.

Why the stack matters

visitor.js is a handwritten walker with explicit rules for many ESTree node kinds. It pushes each branch onto a stack before descending, so the UI can talk about both an occurrence and the enclosing structure that contains it.
