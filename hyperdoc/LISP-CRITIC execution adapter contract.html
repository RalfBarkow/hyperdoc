LISP-CRITIC execution adapter contract

This page defines the source-station-backed execution boundary for LISP-CRITIC in HyperDoc. The adapter represents the local FedWiki asset as an inspectable source station, tries to invoke it only when it is locally present, and records a raw run record instead of pretending that normalized review findings already exist.

Inspectable objects

  • default-lisp-critic-source-station
  • default-lisp-critic-contract
  • example raw run record

Source station

LISP-CRITIC remains a FedWiki-sourced local asset: ~/.wiki/wiki.ralfbarkow.ch/assets/pages/a-critic-for-lisp/. HyperDoc records that source station as data with its site, page, asset root, wrapper system, wrapper package, wrapper loader, and upstream file critique entrypoint. This is not vendoring: no LISP-CRITIC source is copied into the HyperDoc repository, and the test suite does not require the asset path to exist.

Invocation boundary

run-lisp-critic-contract returns a lisp-critic-run-record. When the source station is present, the adapter loads the wrapper ASDF system :a-critic-for-lisp, calls a-critic-for-lisp:load-lisp-critic, and invokes the upstream lisp-critic:critique-file entrypoint for each reviewed file. Standard textual output is captured as raw evidence.

The adapter deliberately records the invocation form and reviewed paths. It does not normalize the output into lisp-critic-finding objects, attach suppressions, or decide waivers in this slice.

Graceful absence

If the FedWiki asset root is absent, the adapter returns a run record with status :asset-missing. Load failures, unavailable critic APIs, and critique failures are also captured as run records with condition summaries. The default behavior is evidence-preserving and CI-safe: absence of the local source station is not an unhandled error.

Relation to the review-plan surface

The earlier page Integrate LISP-CRITIC into HyperDoc automated review models the plan, DITA-like task topics, Goldberg question coverage, and first-class plan-task relations. This page lands the next task in that plan: the executable boundary that can produce raw critic evidence while keeping finding normalization, rule metadata, source manifests, checksum policy, and suppression policy deferred.

Boundary

  • No FedWiki pages are edited by this adapter.
  • No network, DMX server, browser, or physical device is required.
  • No LISP-CRITIC source is copied into HyperDoc.
  • Raw run records are evidence, not final review findings.
