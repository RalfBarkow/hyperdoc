Surface

hyperdoc

A Surface is a bounded operational interface through which a user or robot can inspect, diagnose, act on, or publish some aspect of a HyperDoc-managed system. A surface is not mere UI chrome: it is defined by its scope, permitted operations, evidence forms, boundary conditions, and relation to adjacent surfaces.

Surface as object, not only prose

HyperDoc already distinguishes durable pages, topic objects, inspectable runtime handles, and FedWiki twins. A surface belongs in that same operational model. The page explains the concept, but the runtime object carries the scope, capabilities, outputs, boundary rules, and adjacent surfaces directly.

Surface classes in this repo

  • Authored/durable surface: stable HyperDoc or FedWiki publication surface.
  • Inspectable/runtime surface: one concrete opened page, tab, or runtime object.
  • Diagnostic surface: read-only diagnosis and evidence inspection.
  • Mutation surface: bounded action-bearing surface with explicit authority requirements.
  • Failure surface: blocked or lossy outcome kept as a first-class inspectable surface.

Surface is broader than Surface Answer

The existing Surface Answer remains one narrower answer-surface concept inside a broader generic surface vocabulary. It is not replaced here. Generic surface now sits above answer surfaces, documentation surfaces, and DMX runtime surfaces while keeping those layers distinct.

Worked DMX example set

  • Diagnosing DMX workspace repair triage as the read-only diagnostic surface.
  • Using authenticated workspace assignment repair console as the explicit-auth mutation surface.
  • DMX workspace journal model as the guarded runtime surface cluster those two surfaces operate within.
  • DMX workspace journal reconcile call graph as a live inspectable diagnostic surface around reconcile-time read/write-capable edges.
  • Diagnosing DMX workspace repair triage plus the blocked auth case around carrier 927558 and companion 927568 as the worked failure-surface vocabulary.
