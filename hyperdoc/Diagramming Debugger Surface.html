Diagramming Debugger Surface

hyperbook/server

The Diagramming Debugger is a new Playground runtime surface that derives collaboration/message traces from stepped evaluation.

It is implemented as an inspectable object that wraps the existing Playground stepper and records one event per attempted top-level form.

Inspectable objects

  • Diagramming Debugger Surface
  • Step trace message events
  • Graphviz sequence export
  • Playground stepper class layout

Runtime model

  • make-playground-diagramming-debugger builds a diagram object from selected Playground source.
  • playground-diagramming-debugger-step advances one step and appends a trace event.
  • playground-diagramming-debugger-run runs until completion/error while appending events.
  • graphviz-dot-text exports Graphviz DOT text.

Example DOT export

Example collaboration-flow graph exported from a short Playground run: 

digraph PlaygroundTrace {
  rankdir=LR;
  node [shape=box, fontname="Helvetica"];

  start [label="start"];
  step1 [label="step 1\\n(parse form)\\nstatus=ok"];
  step2 [label="step 2\\n(extract calls)\\nstatus=ok"];
  step3 [label="step 3\\n(apply call)\\nstatus=error"];
  done  [label="done"];

  start -> step1;
  step1 -> step2;
  step2 -> step3 [label="calls: blocks[op].emit"];
  step3 -> done  [label="last-error"];
}

You can render this text with Graphviz: dot -Tsvg trace.dot -o trace.svg.

Playground integration

The Playground toolbar now includes a Diagram action next to Step and Debug. It opens the diagramming debugger object in the inspector.

The diagram view provides:

  • Reset/Next/Run controls
  • step progress and parse-error handling
  • a timeline of captured events (form, extracted call symbols, status)
  • Graphviz DOT output for downstream rendering

Integrated Notes (2026-03-06)

The integration pass added a concrete stepper model snippet and screenshot reference so the surface description stays anchored to the current runtime object shape. 

(defclass playground-stepper ()
  ((object       :initarg :object   :reader playground-stepper-object)
   (package      :initarg :package  :reader playground-stepper-package)
   (source       :initarg :source   :reader playground-stepper-source)
   (forms        :initarg :forms    :accessor playground-stepper-forms)
   (index        :initform 0        :accessor playground-stepper-index)
   (last-value   :initform nil      :accessor playground-stepper-last-value)
   (last-error   :initform nil      :accessor playground-stepper-last-error)
   (parse-report :initform nil      :accessor playground-stepper-parse-report)
   (done?        :initform nil      :accessor playground-stepper-done?)))

Design boundary

This remains intentionally bounded: the diagram is derived from stepped top-level forms and inferred call symbols, not from a full VM-level instruction tracer.

The goal is to make collaboration diagrams inspectable and reproducible in the existing HyperDoc runtime loop without introducing a second debugger stack.
