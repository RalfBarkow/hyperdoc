Translate a full Git commit hash in story text into a Software Heritage revision link

hyperdoc

Purpose

Use this task when you want to verify or demonstrate the existing renderer behavior that turns a full Git commit hash in story text into a Software Heritage revision link.

Prerequisites

  • You have a full 40-character Git commit hash.
  • You are using the FedWiki story-text rendering path that already supports clickable commit IDs.
  • You understand that this is a renderer-local feature, not a new HyperBook.

Inputs

  • one full 40-character Git commit hash
  • story text containing that hash
  • an ordinary external link in the supported syntax, if you also want to observe mixed extraction behavior

Steps

  1. Identify a full 40-character Git commit hash.
  2. Place it into FedWiki story text.
  3. If you also want a normal external link in the same example path, use supported FedWiki bracket-link syntax such as [https://example.org Example].
  4. Render or inspect the story text through the relevant HyperDoc/FedWiki path.
  5. Observe that the commit hash becomes a Software Heritage revision link.
  6. Verify that the resulting URL has the shape https://archive.softwareheritage.org/swh:1:rev:<hash>/.

Expected result

The full commit hash is rendered as a clickable Software Heritage revision URL. In the same supported path, an ordinary external link expressed in bracket-link form remains present as its original URL.

Variations

  • The same capability applies in paragraph, markdown, and reference story items.
  • You can verify the behavior by inspecting the example, the smoke tests, or rendered output.

Common mistakes

  • Using a short hash instead of a full 40-character commit hash.
  • Assuming that bare external URL text is the supported ordinary-link contract in this exact example path.
  • Checking a text path that is not actually the FedWiki story renderer.
