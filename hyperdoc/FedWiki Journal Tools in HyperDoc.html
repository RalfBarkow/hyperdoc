FedWiki Journal Tools in HyperDoc

This page is about tools for working with Federated Wiki page journals as they are documented and inspected in HyperDoc. The concrete journal model belongs to FedWiki pages: page content is accompanied by a journal of actions that can be replayed, checked, repaired, and compacted.

In this repo, the immediate reference surface is the local plugin repository ~/workspace/wiki-plugin-journalmatic. That plugin provides a concrete set of tools for scanning, replaying, and repairing Federated Wiki journals. HyperDoc provides the documentation and inspection surface for those tools. A more general journal-aware HyperBook abstraction may be possible later, but that is not the subject of this page.

Why this matters

Many hard failures in localhost or forked FedWiki pages are not content problems. They are journal problems: malformed actions, missing creation steps, chronology drift, or journals that no longer replay to the current page state.

For writable FedWiki pages, a journal checker is therefore not merely an optional maintenance script. It is part of the operational tool surface needed to inspect, validate, and repair page history.

Scope

These pages describe FedWiki journal operations and point to executable Lisp implementations where relevant. The gate logic has a concrete Lisp implementation surface in Journal Gate Script and Lisp Implementation, and can be inspected through HyperDoc source-of-function views.

Date generation policy follows wiki-client style epoch-millis with monotonic increment from the last journal action date. This avoids hardcoded timestamps that can break chronology after local editing or remote forks.
