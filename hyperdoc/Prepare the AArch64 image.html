Goal

Produce a verified *.img artifact from a known aarch64 source, ready to flash and boot.

Inputs

  • target architecture: aarch64-linux
  • source path:
    • official prebuilt image (nixos-sd-image-*-aarch64-linux.img.zst)
    • or project build output (...system.build.sdImage)
  • host toolchain for decompression/checksum verification

Procedure

  1. Select one source of truth (official prebuilt or project build).
  2. Download/build the artifact and record provenance (URL/commit/date).
  3. Decompress (zstd -d) when needed.
  4. Verify artifact integrity against the Hydra-published SHA-256 before flashing.
  5. Confirm filename and architecture include aarch64-linux.

Download Artifact from Hydra (Path A)

Use this when you want the latest official prebuilt SD image instead of a project-local build.

Normative result of the corrected command path: download is saved directly as a Hydra artifact filename ending in .img.zst, preserving provenance in the filesystem name. Recovery is only needed for the older failure mode where download was saved as file 1.

Decision boundary: Hydra download vs local build

  • Use Hydra download when you want the fastest path to a known-good upstream image baseline.
  • Use local build (Path B) when you must include project-specific modules, patches, or pinned flake inputs.
  1. Open the Hydra job page: nixos.sd_image.aarch64-linux.
  2. Open the latest successful build (green checkmark).
  3. On the concrete build page, record:
    • artifact URL (...download/1/...aarch64-linux.img.zst)
    • build URL and timestamp for provenance notes
    • published SHA-256 value from the build page table or from the same build URL queried as JSON
    • for automation, use build JSON field buildproducts["1"]["sha256hash"]

Command Sequence

Mechanism note for this path: the Hydra latest endpoint redirects to a URL whose path identifies the concrete build. Use that exact build URL as the checksum source of truth: the build page publishes the SHA-256 in HTML, and the same build URL queried with Accept: application/json exposes buildproducts["1"]["sha256hash"]. The resolved artifact URL already contains the exact published filename, so download can write explicitly to $PUBLISHED_NAME without any redirect-name heuristic.

Shell note: this is the primary canonical procedure and it is written for POSIX shell syntax (sh/bash/zsh). If your interactive shell is fish, either run this block via bash -lc '...' or use the fish-native equivalent below. 

# POSIX shell block for sh/bash/zsh. In fish, either run via: bash -lc '...'; or use the fish-native equivalent below.
# 0) Tooling
nix-shell -p curl wget zstd python3

# 1) Resolve the exact build behind the current "latest" endpoint
LATEST_URL="https://hydra.nixos.org/job/nixos/unstable/nixos.sd_image.aarch64-linux/latest/download/1"
BUILD_DOWNLOAD_URL="$(curl -fsSI "$LATEST_URL" | awk 'tolower($1)=="location:" {gsub(/\r/, "", $2); print $2; exit}')"
test -n "$BUILD_DOWNLOAD_URL"
BUILD_URL="${BUILD_DOWNLOAD_URL%/download/*}"
echo "build_url=$BUILD_URL"

# 2) Read the published metadata for build product 1
BUILD_JSON="$(curl -fsS -H 'Accept: application/json' "$BUILD_URL")"
PUBLISHED_NAME="$(printf '%s' "$BUILD_JSON" | python3 -c 'import json,sys; print(json.load(sys.stdin)["buildproducts"]["1"]["name"])')"
EXPECTED_SHA256="$(printf '%s' "$BUILD_JSON" | python3 -c 'import json,sys; print(json.load(sys.stdin)["buildproducts"]["1"]["sha256hash"])')"
ARTIFACT_URL="$BUILD_DOWNLOAD_URL/$PUBLISHED_NAME"
test -n "$PUBLISHED_NAME"
test -n "$EXPECTED_SHA256"
echo "artifact_url=$ARTIFACT_URL"
echo "published_sha256=$EXPECTED_SHA256"

# 3) Download artifact to the exact published filename
test ! -e "$PUBLISHED_NAME"
ARTIFACT="$PUBLISHED_NAME"
wget -O "$ARTIFACT" "$ARTIFACT_URL"
test -f "$ARTIFACT"

# 4) Confirm architecture marker in the published/downloaded filename
echo "$ARTIFACT" | grep 'aarch64-linux\\.img\\.zst$'

# 5) Verify SHA-256 against Hydra's published build metadata
LOCAL_SHA256="$(shasum -a 256 "$ARTIFACT" | awk '{print $1}')"
# Linux alternative:
# LOCAL_SHA256="$(sha256sum "$ARTIFACT" | awk '{print $1}')"
test "$LOCAL_SHA256" = "$EXPECTED_SHA256"
echo "sha256_match=$LOCAL_SHA256"

# 6) Decompress into .img
unzstd -d "$ARTIFACT"

# 6a) Inspect directory state (portable command)
ls -la

# 7) Record provenance for replay/debugging
{
  echo "hydra_job=https://hydra.nixos.org/job/nixos/unstable/nixos.sd_image.aarch64-linux"
  echo "latest_download=$LATEST_URL"
  echo "build_url=$BUILD_URL"
  echo "artifact_url=$ARTIFACT_URL"
  echo "artifact=$ARTIFACT"
  echo "sha256_expected=$EXPECTED_SHA256"
  echo "sha256_local=$LOCAL_SHA256"
  date -u +"download_utc=%Y-%m-%dT%H:%M:%SZ"
} > aarch64-image-provenance.txt

Use ls -la for directory inspection in this runbook. Do not assume a local alias such as la exists.

Alternative: fish-native command sequence

Use this only if you want to run the procedure directly in fish instead of wrapping the canonical POSIX block with bash -lc '...'. 

set -l LATEST_URL "https://hydra.nixos.org/job/nixos/unstable/nixos.sd_image.aarch64-linux/latest/download/1"
set -l BUILD_DOWNLOAD_URL (curl -fsSI "$LATEST_URL" | awk 'tolower($1)=="location:" {gsub(/\r/, "", $2); print $2; exit}')
test -n "$BUILD_DOWNLOAD_URL"; or exit 1

set -l BUILD_URL (string replace -r '/download/.*$' '' -- "$BUILD_DOWNLOAD_URL")
set -l BUILD_JSON (curl -fsS -H 'Accept: application/json' "$BUILD_URL")

set -l PUBLISHED_NAME (printf '%s' "$BUILD_JSON" | python3 -c 'import json,sys; print(json.load(sys.stdin)["buildproducts"]["1"]["name"])')
set -l EXPECTED_SHA256 (printf '%s' "$BUILD_JSON" | python3 -c 'import json,sys; print(json.load(sys.stdin)["buildproducts"]["1"]["sha256hash"])')

set -l ARTIFACT_URL "$BUILD_DOWNLOAD_URL/$PUBLISHED_NAME"
test -n "$PUBLISHED_NAME"; or exit 1
test -n "$EXPECTED_SHA256"; or exit 1
test ! -e "$PUBLISHED_NAME"; or exit 1

set -l ARTIFACT "$PUBLISHED_NAME"
wget -O "$ARTIFACT" "$ARTIFACT_URL"
test -f "$ARTIFACT"; or exit 1

echo "$ARTIFACT" | grep 'aarch64-linux\.img\.zst$'; or exit 1

set -l LOCAL_SHA256 (shasum -a 256 "$ARTIFACT" | awk '{print $1}')
test "$LOCAL_SHA256" = "$EXPECTED_SHA256"; or exit 1

printf "OK\nartifact=%s\nsha256=%s\n" "$ARTIFACT" "$LOCAL_SHA256"

Verification rule: this step is complete only when the local shasum -a 256 value equals the published Hydra build metadata value from buildproducts["1"]["sha256hash"] for the exact build selected by latest/download/1. A mismatch is failure.

Postcondition (decompression handoff): after unzstd -d nixos-image-sd-card-*.img.zst, the working directory can contain both the preserved compressed artifact and the decompressed flashable image. This coexistence is normal, not an error state.

Reader flow: missing assumptions checklist

  1. Assume your host can run nix-shell, curl, wget, python3, and zstd; if not, stop and install tooling first.
  2. Assume network access to hydra.nixos.org; if not, switch to local build Path B.
  3. Assume the selected Hydra build exposes buildproducts["1"]["sha256hash"]; if not, stop and compare manually against the build page before flashing.
  4. Assume target media is the intended SD card; verify device identity before any destructive write step.

If checksum verification fails, stop immediately and retry from the Hydra build page. Do not flash an unverified image.

Fallback: historical filename-loss recovery

Filename loss is a known failure mode of the naive download path. If the local file was saved as 1, recover the true artifact filename from the Hydra build page and rename before decompression. This is fallback only, not the normal expected flow.

Acceptance

  • artifact exists as .img and is readable
  • architecture is confirmed as aarch64 target
  • provenance is recorded for later replay/debugging
