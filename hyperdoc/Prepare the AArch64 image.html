Goal

Produce a verified *.img artifact from a known aarch64 source, ready to flash and boot.

Inputs

  • target architecture: aarch64-linux
  • source path:
    • official prebuilt image (nixos-sd-image-*-aarch64-linux.img.zst)
    • or project build output (...system.build.sdImage)
  • host toolchain for decompression/checksum verification

Procedure

  1. Select one source of truth (official prebuilt or project build).
  2. Download/build the artifact and record provenance (URL/commit/date).
  3. Decompress (zstd -d) when needed.
  4. Verify artifact integrity (size/checksum if available).
  5. Confirm filename and architecture include aarch64-linux.

Download Artifact from Hydra (Path A)

Use this when you want the latest official prebuilt SD image instead of a project-local build.

Normative result of the corrected command path: download is saved directly as a Hydra artifact filename ending in .img.zst, preserving provenance in the filesystem name. Recovery is only needed for the older failure mode where download was saved as file 1.

Decision boundary: Hydra download vs local build

  • Use Hydra download when you want the fastest path to a known-good upstream image baseline.
  • Use local build (Path B) when you must include project-specific modules, patches, or pinned flake inputs.
  1. Open the Hydra job page: nixos.sd_image.aarch64-linux.
  2. Open the latest successful build (green checkmark).
  3. On the build page, copy:
    • artifact URL (...download/1/...aarch64-linux.img.zst)
    • published SHA-256 value
    • build URL and timestamp for provenance notes

Command Sequence

Mechanism note for this path: the Hydra latest endpoint redirects to a URL whose path ends with the concrete artifact filename, and --trust-server-names tells wget to adopt that redirected server-provided name. 

# 0) Tooling
nix-shell -p wget zstd

# 1) Optional: resolve current "latest" endpoint
LATEST_URL="https://hydra.nixos.org/job/nixos/unstable/nixos.sd_image.aarch64-linux/latest/download/1"

# 2) Download artifact (preserve redirected Hydra filename)
wget --trust-server-names "$LATEST_URL"

# 3) Determine artifact filename
ARTIFACT="$(ls -t *.img.zst | head -n1)"
echo "artifact=$ARTIFACT"

# 4) Confirm architecture marker in filename
echo "$ARTIFACT" | grep 'aarch64-linux\\.img\\.zst$'

# 5) Verify SHA-256 (replace EXPECTED_SHA256 from Hydra build page)
EXPECTED_SHA256="REPLACE_WITH_HYDRA_SHA256"
shasum -a 256 "$ARTIFACT"
# Linux alternative:
# sha256sum "$ARTIFACT"

# 6) Decompress into .img
unzstd -d "$ARTIFACT"

# 6a) Inspect directory state (portable command)
ls -la

# 7) Record provenance for replay/debugging
{
  echo "hydra_job=https://hydra.nixos.org/job/nixos/unstable/nixos.sd_image.aarch64-linux"
  echo "latest_download=$LATEST_URL"
  echo "artifact=$ARTIFACT"
  echo "sha256_expected=$EXPECTED_SHA256"
  date -u +"download_utc=%Y-%m-%dT%H:%M:%SZ"
} > aarch64-image-provenance.txt

Use ls -la for directory inspection in this runbook. Do not assume a local alias such as la exists.

Postcondition (primary path): local directory contains a newly downloaded file named nixos-image-sd-card-*.img.zst, and no manual rename from 1 is required.

Comparison note: naive wget "$LATEST_URL" may save as 1; corrected wget --trust-server-names "$LATEST_URL" saves as the concrete artifact filename.

Postcondition (decompression handoff): after unzstd -d nixos-image-sd-card-*.img.zst, the working directory can contain both the preserved compressed artifact and the decompressed flashable image. This coexistence is normal, not an error state.

The .img.zst file is the preserved download artifact; the .img file is the flash input.

aarch64-image-provenance.txt is the replay anchor: it records which exact artifact was chosen, from which Hydra path, and when. Keep it next to the downloaded image while flashing and post-boot verification.

Reader flow: missing assumptions checklist

  1. Assume your host can run nix-shell, wget, and zstd; if not, stop and install tooling first.
  2. Assume network access to hydra.nixos.org; if not, switch to local build Path B.
  3. Assume checksum is available from the selected build page; if missing, do not flash.
  4. Assume target media is the intended SD card; verify device identity before any destructive write step.

If checksum verification fails, stop immediately and retry from the Hydra build page. Do not flash an unverified image.

Fallback: historical filename-loss recovery

Filename loss is a known failure mode of the naive download path. If the local file was saved as 1, recover the true artifact filename from the Hydra build page and rename before decompression. This is fallback only, not the normal expected flow.

Acceptance

  • artifact exists as .img and is readable
  • architecture is confirmed as aarch64 target
  • provenance is recorded for later replay/debugging
