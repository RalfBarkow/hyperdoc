Locate and replace the legacy workspace hyperdoc.service definition

Find where the old workspace-checkout unit is defined and replace it with the supported flake/NixOS deployment path.

Inspectable objects

  • Replace legacy unit with flake host profile
  • Legacy workspace-checkout hyperdoc.service
  • dreyeck supported deployment model

Purpose

Remove dependence on /home/rgb/workspace/hyperdoc as the runtime source under systemd.

Prerequisites

  • Diagnose sbcl command-not-found in the legacy hyperdoc.service completed.
  • Access to the NixOS configuration source used for dreyeck.ch.

Context

Installing sbcl into the legacy unit PATH is only an emergency workaround. The supported fix is to replace the legacy unit model.

Steps

  1. Find where the old unit definition is declared: 
    grep -R "HyperDoc (workspace checkout)" /etc/nixos /home/rgb/workspace 2>/dev/null
grep -R "/home/rgb/workspace/hyperdoc" /etc/nixos /home/rgb/workspace 2>/dev/null
grep -R "exec ./start.sh" /etc/nixos /home/rgb/workspace 2>/dev/null
  2. Remove or replace that legacy definition in the host configuration.
  3. Ensure the target model is flake-driven deployment from local source state, not a server-local checkout launcher.
  4. Confirm the required deployment outputs exist locally: 
    nix eval --raw .#nixosConfigurations.dreyeck-ch.config.networking.hostName
nix eval --raw .#apps.$(nix eval --raw --impure --expr builtins.currentSystem).release-smoke.program

Emergency note

While migrating, you may stop restart-loop noise temporarily: 

sudo systemctl disable --now hyperdoc

Result

  • The old workspace-checkout unit definition is identified for removal/replacement.
  • The migration path is aligned to supported deployment.
  • If the nixosConfigurations.dreyeck-ch or release-smoke checks fail here, stop and port the missing deployment profile before continuing.
