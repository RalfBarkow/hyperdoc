Deploy or restart dreyeck and confirm live parity

This operator task is the main follow-up after the Startup load-set mismatch diagnosis: either deploy the corrected build or restart the packaged service, then confirm Scoped example parity.

Inspectable objects

  • Deploy or restart dreyeck and confirm live parity
  • Deployment command locality
  • dreyeck local verification gate
  • dreyeck runner rehearsal
  • Restart dreyeck release service
  • Confirm scoped example parity on dreyeck
  • Live parity evidence
  • NixOS generation rollback

Purpose

Reach a running dreyeck service that exposes the same intended scoped example layers as localhost, without weakening the existing load-boundary model.

Prerequisites

  • Verify HyperDoc locally before deployment passed.
  • You know whether the task is a full deployment or only a service restart.
  • You have controller-local access, target-host access, and a rollback path.

Command locality breakdown

Follow Deployment command locality strictly: local verification and rebuild commands stay on the controller, SSH commands target dreyeck.ch, and public URL probes remain public verification.

Recommended sequence

  1. Verify locally.
  2. Back up and record the current generation.
  3. Rehearse before any real switch.
  4. Choose exactly one operational path:
    • deploy from the local flake if code/configuration changed.
    • restart the release service if the deployed generation is already correct.
  5. Verify HTTP/UI reachability.
  6. Confirm scoped example parity.
  7. If parity or reachability fails, roll back.

Expected success signals

  • The service is up and serving expected URLs.
  • The portable and ops example scopes are present again.
  • No manual rescue load is needed after the service starts.

Failure interpretation

  • If the service is up but portable/ops scopes are empty, suspect a load-set problem rather than a discovery bug.
  • If parity appears only after ad hoc REPL loads, startup wiring is still wrong.
  • If the service does not come back at all, treat restart/deploy as failed and use rollback.

Automation from within HyperDoc

HyperDoc already documents runner-friendly rehearsal steps, but this task page does not assume a one-click deploy. Dry/non-destructive rehearsal remains separate from switch/restart, and rollback remains explicit.
