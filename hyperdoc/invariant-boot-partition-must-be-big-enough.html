Invariant: Boot Partition Must Be Big Enough

hyperdoc

The Raspberry Pi SD-image workflow assumes that /boot is large enough to hold kernel, initrd, boot metadata, and multiple generations.

Inspectable objects

  • Boot partition capacity for nixos-rebuild boot
  • nixos-rebuild boot
  • nixos-rebuild test

Operational Thresholds

  • >= 256MB: recommended baseline
  • < 128MB: stop and re-image
  • 30 MiB: incompatible with NixOS boot asset copying in practice

Why This Matters

A successful nixos-rebuild boot needs room for:

  • kernel copies
  • initrd copies
  • /boot/nixos/ generation files
  • /boot/extlinux/extlinux.conf rewrite

If the partition is too small, the kernel copy can fail and extlinux can be left truncated. That makes reboot unsafe.

Observable Symptoms

  • cp: ... No space left on device
  • Failed to install bootloader
  • only extlinux.conf.tmp.* exists
  • extlinux.conf reduced to a short header-only file

A successful nixos-rebuild test does not imply that the next reboot is safe. The failure only becomes visible when boot assets must actually be copied into /boot.

Reboot Unsafe Criteria

  • /boot is below the minimum threshold
  • /boot/extlinux is missing
  • extlinux.conf is missing or clearly truncated
  • /boot/nixos does not contain a complete new generation after rebuild

In these cases, do not reboot. Re-image first or repair the boot partition layout before continuing.

Correction Path

  • Visible error: No space left on device during bootloader or kernel copy, or Failed to install bootloader.
  • Local diagnosis: df -h /boot shows a too-small or full partition, and extlinux.conf is missing or only extlinux.conf.tmp.* remains.
  • Corrective action: re-image with an official NixOS SD image that provides a large enough boot partition, or explicitly resize the boot partition before retrying.
  • Verification: /boot/extlinux/extlinux.conf exists, /boot/nixos contains non-.tmp kernel and initrd assets, and the machine reboots successfully.
