Reference comparison

py4dmx authenticates by posting to /access-control/login, capturing a JSESSIONID session material, and using session plus workspace cookie shape for non-GET writes. It does not need a second authorization credential on the later write once the session exists.

HyperDoc's guarded workspace-assignment request now matches the important py4dmx non-GET pattern: method PUT, session-only auth, session plus workspace cookie shape, JSON accept header, and a zero-length body. The one documented divergence is content type: py4dmx sends JSON content type for PUTs, while HyperDoc leaves content type unset on the zero-length assignment PUT to avoid an implicit form-media request. That divergence explains prior media-type failures, not the current 401.

dmx-platform route semantics

dmx-platform exposes the REST route PUT /workspaces/{workspaceId}/object/{objectId} in WorkspacesPlugin.assignToWorkspace. The route calls checkAssignmentArgs(object, workspaceId). That checks both target workspace write access and object write access before assigning the workspace facet.

dmx-platform also has a private helper for initial assignment that deliberately skips the object write check, because initial assignment is what creates the permission context. The public REST route does not use that helper. For an object with no workspace assignment, core permission logic grants READ but refuses WRITE. dmx-platform maps nested access-control exceptions to HTTP 401.

Why this is not a reconstruction failure

  • The planned topic action is :UPDATE, not :CREATE.
  • Topicmap placement in 919822 is present.
  • The remaining operation is only workspace assignment.
  • Deleting would risk associations and references while still requiring a new workspace assignment.

Delete/recreate boundary

Delete/recreate is not the default repair path. It is a last-resort migration only after a full reference audit, hard-delete permission, verified absence of foreign references, replacement topic creation, workspace assignment, topicmap placement, duplicate-URI checks, and explicit operator approval.
