Distinction

  • Surface Answer: immediate answer in the terminal/Codex session.
  • Artifact Answer: durable answer in HyperDoc/FedWiki/Lisp source artifacts.

The broader surface abstraction now sits above this answer-specific distinction. Surface Answer remains the narrower answer-surface concept rather than the generic model for every HyperDoc surface.

Required behavior

  1. Every response provides a Surface Answer.
  2. If the request changes behavior, documentation, or workflows, also provide an Artifact Answer.
  3. For conceptual-only turns, include artifact deltas as a plan unless explicitly skipped.

Reconstruction protocol

  • Process trace: what was checked and decided.
  • HyperDoc delta: page/section updates.
  • Lisp delta: topic/object/view/function updates.
  • FedWiki delta: slug/title/summary/references and daily anchors.
  • Replay checks: JSON parse, journal integrity, and link resolution checks.

Prose To Object Bridge

Prose-only guidance is not enough for reliable replay. Each operational claim should expose a clickable inspectable object so users can move directly from explanation to executable/inspectable state without dropping to raw structure.

Display Argument Policy

Finding: remove the :display argument entirely and rely on each object's text representation. This keeps labels consistent with inspectable object identity and reduces navigation drift introduced by ad hoc display strings.

Skillization loop

Repeated patterns are extracted into reusable routines so the runtime can execute them directly, instead of requiring one-off assistant steps each time.

Codex Resume Branch Context

Codex resume exposes the related git branch for each Codex session. This is an operational context signal for replay: a session answer should be read in its branch context, not as branch-agnostic output.
