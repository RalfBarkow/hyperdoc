This bridge page treats the Graham closure/NOR matcher as the executable case and the route-planning page as the abstraction target. The narrow question is: can the matcher's continuation trace be represented as a first inspectable HyperDoc route object?

Bridge argument

  1. Graham closure: a returned function remembers a lexical binding. The teaching artifact starts with make-adder: the function remembers n and later uses it.
  2. NOR matcher closure: a matcher leaf remembers its predicate and its success/failure exits. When the leaf fails, the failure continuation is the remembered alternate route through the compiled matcher.
  3. HyperDoc route object: a route remembers failed premises, alternatives, repairs, evidence, and the original trace events, so the path can be inspected or replayed without re-running the matcher.

Executable bridge

The bridge does not replace the matcher. It runs the existing closure/NOR demo and converts the emitted trace into a small route IR. The default case uses (nor (:agent :shuttle) (:agent :joke)) on the Apollo graph: both leaves are absent, so the failure continuation advances to the next remembered alternative and yields visible route repairs.

Route IR

  • continuation-route: id, intention, origin, target, steps, alternatives, repairs, evidence, trace events.
  • continuation-route-step: from, to, operation, premise, constraint, result, success continuation, failure continuation, evidence.
  • continuation-route-repair: failed step, remembered refusal, alternate step, continuation, evidence.

Replay surface

The route object keeps enough data to replay the path as rows without calling the matcher again. A later UI can render the same route as a table or tree:

step choice remembered refusal success continuation failure continuation repair evidence
step-01 (:agent :shuttle) absent leaf not used advance to next leaf try remembered alternative original NOR trace event

Scope boundary

This is not McDermott-style planning, not a general graph planner, and not a navigation redesign. It is the smallest executable bridge from closures as remembered refusals to routes as inspectable, repairable continuations through uncertainty.
