Get hauptsache working on dreyeck.ch

Minimal cautious procedure to deploy HyperDoc from local hauptsache state to dreyeck.ch.

Inspectable objects

  • dreyeck supported deployment model
  • Cautious nixos-rebuild activation sequence
  • Deployment command locality
  • NixOS generation rollback

Purpose

Provide a deployment path that is short but safety-first: backup, record rollback references, verify, dry/test activation, verify, switch, rollback if needed.

Prerequisites

  • SSH access to the target host.
  • Nix CLI with flake support on the controller machine.
  • Local repository checkout at branch hauptsache.

Context

hauptsache should be verified locally and deployed from the local flake; the server should not be repaired by checking out that branch directly.

Task sequence

  1. Detect legacy workspace-checkout hyperdoc.service on dreyeck.ch
  2. Diagnose sbcl command-not-found in the legacy hyperdoc.service
  3. Locate and replace the legacy workspace hyperdoc.service definition
  4. Back up dreyeck.ch before deployment
  5. Record dreyeck.ch generation before rebuild
  6. Verify HyperDoc locally before deployment
  7. Rehearse dreyeck.ch deployment with runner
  8. Deploy dreyeck.ch from the local flake
  9. Verify HyperDoc on dreyeck.ch
  10. Roll back HyperDoc on dreyeck.ch

Observed blocker

If hyperdoc.service still says “HyperDoc (workspace checkout)”, dreyeck.ch is still on the old deployment model, and that must be replaced before hauptsache can be deployed in the supported way.

Emergency note

To stop restart-loop noise during migration, you may temporarily disable the old unit: 

sudo systemctl disable --now hyperdoc

Result

You have a cautious deployment flow: backup and rollback references first, then local verify, dry-activate, test, verify, switch, and rollback if required.
