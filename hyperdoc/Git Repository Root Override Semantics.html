Git Repository Root Override Semantics

hyperdoc

Git-backed history surfaces need two separate runtime facts: a usable Git executable and a repository root that actually carries Git metadata. The repository-root override exists so a deployed runtime can intentionally ask Git about a live checkout instead of only the packaged source snapshot inside the release image.

Repository-root precedence

  1. hyperdoc::*git-repository-root* inside the current Lisp image.
  2. HYPERDOC_GIT_REPOSITORY_ROOT from the runtime environment.
  3. the default root derived from the loaded ASDF system source tree.

The effective root, its source, and its interpreted mode are now inspectable on Git-history surfaces and runtime-unavailability conditions.

Packaged runtime versus live checkout

A packaged HyperDoc release image can contain a source snapshot under /nix/store/.../share/hyperdoc/source/ without shipping usable .git repository metadata. In that default mode, Git-backed history surfaces should remain truthful and render repository-metadata-unavailable instead of pretending the runtime has a live checkout.

A live checkout mode is different: if the runtime explicitly points HYPERDOC_GIT_REPOSITORY_ROOT or hyperdoc::*git-repository-root* at a real checkout, the same Git-backed history surfaces can resolve real commit and history objects.

Intentional provenance split on deployed hosts

Hosts like dreyeck.ch can intentionally split provenance: executable code still comes from the immutable packaged release, while Git history inspection is allowed to read from a mutable workspace checkout such as /home/rgb/workspace/hyperdoc.

That split is deliberate. It keeps deployed code reproducible while still allowing operator-facing history and merge-preparation surfaces to inspect the live repository state when the host provides one explicitly.

Operator guidance

  • Use nix develop when you want local live-checkout behavior by default.
  • Use HYPERDOC_GIT_PROGRAM when the runtime needs explicit Git executable discovery.
  • Use HYPERDOC_GIT_REPOSITORY_ROOT when a deployed runtime should inspect a real checkout instead of the packaged source tree.
  • Expect packaged releases without an override to stay inspectably unavailable for Git history rather than failing as raw subprocess errors.
