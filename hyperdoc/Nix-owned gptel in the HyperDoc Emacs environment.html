Nix-owned gptel in the HyperDoc Emacs environment

hyperdoc

This reference/contract page defines the reproducible HyperDoc Emacs launch path. Nix owns the editor and its packages, an immutable repository bootstrap owns startup configuration, and the operator manages llama-server separately.

Ownership contract

  • The flake output hyperdocGptel builds gptel from the explicitly locked source revision.
  • The flake output hyperdocEmacs composes gptel, Transient, Compat, SLY, SLIME, Magit, and the existing editing packages from one Emacs package set.
  • The flake output hyperdocEmacsBootstrap copies the repository bootstrap into an immutable Nix-store output.
  • The hyperdoc-emacs launcher always executes that Emacs closure with -Q and loads that store bootstrap.
  • The bootstrap starts the named server hyperdoc, configures Local Gemma 4 E2B, and loads SLY.
  • Spacemacs, package.el, ~/.emacs.d/elpa, and /Users/rgb/workspace/gptel own nothing in this path.
  • llama-server remains an independently managed operator process; startup never sends it a request.

Reproducible source boundary

gptel-src is locked to revision 8701e2bd80c5d2091ce2decef5d34d6fce4a3ada. The package declares version 0.9.9.5 and requires Emacs 27.1 or newer, Transient 0.7.8 or newer, and Compat 30.1.0.0 or newer. The separate nixpkgs-emacs input supplies the coherent modern Emacs package set; the repository's Common Lisp package set remains on its existing pin.

Live-session safety boundary

Hot-loading is allowed only through an emacsclient whose server reports the identity of the target Emacs process. Before loading, capture the SLY connection object, inferior process, mREPL buffers, loaded Transient version, and library locations. If the valuable Emacs process has no server socket, preserve it unchanged: do not restart it, synthesize keyboard input, attach a debugger, replace Transient in place, or guess which GUI process is the target.

Expectation artifact

Expectation
The running HyperDoc/SLY Emacs can be reached by a matching emacsclient and can therefore receive a verified hot-load.
Observed boundary
The earlier hyperdoc-sly-connect launcher started Emacs with -Q and connected SLY, but did not start an Emacs server.
Classification
False expectation for the current launcher contract: a SLY connection does not imply an Emacs server socket.
Resolution
Keep the public SLY launcher interface, but route it through the Nix-owned bootstrap that starts the dedicated server before the dynamic SLY connection.
Prevention
The matching hyperdoc-emacsclient always selects server name hyperdoc, with an environment override reserved for disposable tests.

Operator commands

The canonical SLY launch preserves positional host and port arguments:

nix run .#hyperdoc-sly-connect -- 127.0.0.1 <printed-slynk-port>

The matching client selects the deterministic hyperdoc server:

nix run .#hyperdoc-emacsclient -- --eval '(server-running-p server-name)'

HyperDoc owns port 8080. The independently started llama-server owns 127.0.0.1:8081. From the operator's llama.cpp checkout its current separate start form is: 

./build/bin/llama-server \
  -hf google/gemma-4-E2B-it-qat-q4_0-gguf:Q4_0 \
  --host 127.0.0.1 --port 8081 --jinja

This command is never run by the HyperDoc launcher. To inspect the configured backend without sending a request, use the matching client: 

nix run .#hyperdoc-emacsclient -- --eval \
  '(list (gptel-backend-name gptel-backend)
         (gptel-backend-url gptel-backend)
         gptel-model
         (locate-library "gptel")
         (locate-library "gptel-openai"))'

Both library paths must begin with /nix/store/; neither may name the local gptel checkout or ~/.emacs.d/elpa. Run make hyperdoc-emacs-path to print the launcher selected by the flake without launching it.

(defun i (object)
  "Safe inspector helper for SLY mREPL.
Prefer CLOG only if it is already loaded; otherwise use CL:INSPECT.
Never calls SLYNK:INSPECT-IN-EMACS directly."
  (let* ((clog-package (find-package "CLOG-MOLDABLE-INSPECTOR"))
         (clog-symbol
           (and clog-package
                (find-symbol "CLOG-INSPECT" clog-package))))
    (cond
      ((and clog-symbol (fboundp clog-symbol))
       (handler-case
           (progn
             (funcall (symbol-function clog-symbol) :object object)
             object)
         (condition (condition)
           (format t "~&CLOG inspector failed; falling back to CL:INSPECT: ~A~%"
                   condition)
           (inspect object)
           object)))
      (t
       (inspect object)
       object))))

Boundary

This contract configures—but does not contact—the local backend. It does not start llama-server, mutate the connected Common Lisp image, reload HyperDoc, or address an earlier live Emacs server. Environment overrides are limited to HYPERDOC_GPTEL_HOST, HYPERDOC_GPTEL_MODEL, and the disposable test server name.
