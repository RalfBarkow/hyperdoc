Authority

The pages named above stay authoritative for what they declare. The CTM document dreyeck/work/project/hyperdoc-project.ctm is derived from them by write-project-ctm and is not edited by hand; a test fails when it is not what the pages give now. A CTM document read later, for example one an exchange partner changed, is a revision of its own: it is read, inspected and compared, and nothing of it is written back to a page.

Identity

Every Topic has a subject identifier: a tag: IRI under tag:dreyeck.ch,2026:hyperdoc/, which names and does not locate.

  • A Work Topic is work/topic/ followed by its data-topic ID. A proposal has the ID it would be declared with, so a later declaration is the same Topic.
  • A page is page/, its HyperBook ID and its page ID in that HyperBook, lowercased with each other run of characters a hyphen. Renaming a page changes it.
  • An authored statement is statement/, its page, its data-from, data-relation and data-to, and a number that counts equal statements on that page in authored order.
  • A control is control/, its work package and its data-control ID; a repository file is file/ and its repository path; an assignment is assignment/ and its data-assignment ID; a derived gap is gap/, its rule and its subject.
  • Types, Role types and Occurrence types are schema/ and a name; each has a name and, where it matters, a description in the document.

No name, label, position or line number is part of an identifier. The Document IRI tag:dreyeck.ch,2026:hyperdoc/project.ctm is fixed for every revision; it names no Topic, and CXTM comparisons use it as base locator.

What the document states

  • A declaration is a Topic typed by its data-kind, with its label as name, its data-status as the occurrence work status, and its sentence as declaration text. declared on names the page that declares it, carried by the page its declaration names.
  • An authored statement is an Association of the type its data-relation names: the Relation Contract Topic for a work:relation/… reference, otherwise a relation word. Its Roles are the source and target Role types of that type, played by the Topics of data-from and data-to. The statement Topic reifies it and is stated on its page. Direction comes from the authored attributes, never from a drawn edge.
  • WBS decomposition (decomposes into), plan dependency (depends on) and result (produces) are three Association types with their own Role types.
  • A WBS Dictionary entry gives its work package the occurrences scope, acceptance criterion, authority, effect and evidence, and its controls; a control with a test names the test file that exercises it, and whether that file contains the stated marker.
  • A proposal is proposed on Implementation Assignments, has no work status and is never declared on a page. An assignment records its goal, Work Item, deliverable, source authorities, preconditions, acceptance criteria, evidence and the state its executor reports. No acceptance is recorded by an execution.
  • A gap is derived by a stated rule where the declarations do not say enough, and concerns the Topics it names. It adds no relation of the Work.

Work status is an occurrence; provenance is in declared on, proposed on and stated on; no scope is used.
