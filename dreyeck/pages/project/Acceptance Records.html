Acceptance Records

Draft. This page is not a source of the project CTM. Once the user makes it one, it is the only page that states that a work package was accepted or rejected, or that an earlier record is withdrawn. It records no decision: nothing on any page has been accepted.

A record is written by the user. The executor of an assignment never writes one, and no test result, passed suite, completed assignment, work status or evidence entry makes one. A judgment states one decision, accepted or rejected, on one declared work package, against an explicitly named revision of that package's acceptance criterion in a declared WBS Dictionary, by an authority this page declares, at a time, and names the evidence entries it considered. A record is never changed or removed: a correction is a new record that supersedes the earlier one, and a withdrawal supersedes without judging. Which record is in force follows from supersession alone, never from a time; two records that nothing supersedes leave the work package undecided. The project CTM checks each record and refuses an incomplete one rather than complete it.

Authorities

Who may decide on acceptance, as declared here. A declaration, not an authentication.

  • The owner of the HyperDoc project — the user. How the user is named here is the user's decision.

Records

Form of a record

A judgment would be written as follows; this example is text, not a record.

<section data-acceptance-record="ID">
<h3>Title</h3>
<p data-field="work-package" data-ref="WORK-PACKAGE-ID">the declared work package decided on</p>
<p data-field="criterion" data-ref="WORK-PACKAGE-ID" data-revision="sha256-HEX">the revision of its acceptance criterion applied: sha256- and the SHA-256 of the criterion's text</p>
<p data-field="decision" data-decision="accepted|rejected">the decision</p>
<p data-field="decided-at" data-datetime="YYYY-MM-DDThh:mm:ssZ">when</p>
<p data-field="authority" data-ref="AUTHORITY-ID">who decided, as declared above</p>
<ul data-field="considered-evidence">
<li data-evidence="ASSIGNMENT-ID/ENTRY-ID">an identified evidence entry of an assignment</li>
</ul>
<ul data-field="supersedes">
<li data-record="EARLIER-RECORD-ID">why, when this record corrects an earlier one of the same work package</li>
</ul>
</section>

A withdrawal is written with <p data-field="disposition" data-disposition="withdrawn"> in place of the decision. It names the work package, the time and the authority, and supersedes at least one earlier record of the same work package; it names no criterion and considers no evidence.
