First schema design

Inspect the existing constrained native Topic type. This selects the project model's application type, not a verified TMCL declaration.

The existing constrained subject is tag:dreyeck.ch,2026:hyperdoc/schema/implementation-assignment, with occurrence type tag:dreyeck.ch,2026:hyperdoc/schema/goal. These are application identities, not verified TMCL PSIs. The design considers required classification, a proposed exactly-one nonblank Goal, evidence/report types, occurrence reification, source and execution Roles, stable identity, complete conditional run facts, and provenance/acceptance boundaries.

Each design requirement has valid and invalid examples and a comparison with the current Lisp checks in the full matrix. Normative TMCL mappings remain unresolved for every row. An emitted first Goal field does not prove that missing/duplicate source Goals are refused. A schema shape check cannot authenticate an executor, prove a run happened or confer acceptance authority.

A future schema map may refer to the same application type subject while retaining its own authoring authority and Document IRI. Ordinary CTM identity fixtures test separate objects, shared subject identifiers and canonical content import; they are explicitly not a TMCL schema or validation result. Import does not preserve all statement provenance automatically. No general TMDM-to-CTM serializer is claimed.
