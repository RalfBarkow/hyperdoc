Where the Source Lives

dreyeck/lisp-critic/reading

This book's Code pages tab shows nothing, and that is not an oversight. Code Pages means the Lisp source components under one component of one system — this book's own — and what it names is the directory holding these pages, which contains no Lisp at all. The tab is answering a narrow question correctly.

The two facts that produce the empty tab, read from the book itself

The question it is not answering is where this subject's source lives. That has a different shape, and no single ASDF system contains it.

Three kinds of ownership

The source falls into three layers, and the difference between them is not where the files sit but what may be done with them.

  • repository-owned — four systems in this repository. They are ours and already loaded, so ASDF can be asked about them without evaluating anything new.
  • page-attached — a system that lives beside a wiki page. Asking ASDF about it would mean running a definition that arrived with a page, so it is read as text and listed as files.
  • vendored-historical — a copy of Zach Beane's 2004 distribution of Chris Riesbeck's engine, carrying a definition of its own. Observed the same way, and for the same reason.

A projection that discovered the second and third layers by loading them would have destroyed the distinction it exists to show. So each layer is observed by the means that layer permits, and the projection records which means it used.

Files are not nodes in the projection. Six systems and three layers are something a reader can take in; twenty-four file nodes are a thicket. Each system topic carries its own observation, files included, so nothing is lost — it is one inspection away rather than drawn.

The two edges that cross between layers are read from the source binding, which names the wrapper system it registers and the upstream system that wrapper loads. They are not a guess about what probably calls what.

What this does not do

It evaluates nothing. The page-attached definition is read as text, no system is registered from it, and the engine stays away — the tests check that its four packages are absent both before and after. Reading where source lives is a question about files, and a file question answered by running code would be answering a different question.

It also leaves Code Pages alone. The narrow meaning is worth keeping: a book that carries source should be able to say which source it carries, without that answer expanding to include everything its subject touches.
