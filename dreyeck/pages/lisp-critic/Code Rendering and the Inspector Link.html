Code Rendering and the Inspector Link

dreyeck/lisp-critic/reading

Decision 2: should an ordinary Code item keep its Inspector link to the item itself? No decision has been taken. A Claude Code review wrote this page to prepare it; the answer is the project owner's.

The link is the small code label above the source text. Clicking it opens the Code item in the Inspector, where its stored data is shown, among it the programming language its author gave. Showing the link runs nothing. What a reader may do once the item is open is a separate matter, decided by the Inspector's own views and the project's rules for operations, not by how the Code item is shown.

The probe saw this link before the Verified Example system was loaded, leading to the very same item, and saw no link afterwards: link before, none after, evidence commit e91349f6. It checked the link's data, not a click in a browser.

Answer: Keep the link

In practice: every ordinary Code item shows the code label as a link to itself, as it did before. Items marked as Verified Examples are not affected: they have their own, separately approved display, which shows no such links.

For:

  • It is the only way from a shown Code item to its own data, the language included. Without it the language is still stored, but a reader of the page no longer reaches it from the item. (observed that the data stays; the rest follows from it)
  • The link leads somewhere to look; showing it does not run the code. (observed: the probe rendered it and evaluated nothing; a click was not tested)
  • It is how ordinary Code was shown before the Verified Example system existed. (observed)

Against:

  • A link makes more reachable. In a development image, where the rules for operations are not enforced, the Inspector may offer to run functions on an object it has opened. That concerns what happens after following the link, not showing it. (inferred from the rules' code)
  • Nobody is known to use the link on Code items. (no evidence either way)

Answer: Remove the link

In practice: ordinary Code is shown as plain escaped text only. To do this in every image, the general way of showing Code has to change, for all Code items; doing it only in the Verified Example code removes the link only where that code is loaded, which is today's behaviour and depends on the first decision.

For:

  • Fewer ways onward from text written by others. (an assumption about what is safer)
  • It matches the Verified Examples, which show no links at all. (observed in their tests)

Against:

  • No test and no document asks for the link to be removed from ordinary items. (observed)
  • The reader loses the way to the item's data from the page. (follows from the observation)

The earlier question

Keeping the link is part of what Position A asks for, but not all of it: Position A also says the earlier look should not have changed unintentionally, which this decision does not settle. Removing it is close to Position B. The two positions conflict only if "passive" is taken to mean "without any link"; the earlier look was already passive and escaped. Both answer the question. That mapping is the review's reading.
