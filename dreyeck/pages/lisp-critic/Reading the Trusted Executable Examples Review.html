Why this page loads nothing it criticises

The criticism concerns what loading dreyeck/verified-example does to every Code item of an image. Reading it must not do that, so this book does not depend on that system, and the definitions below are cited at a commit rather than shown as loaded functions.

1. Observed source

Two revisions are kept apart. The reviewed code is commit 9b57bd4bb87d92fbf3061b91a42a6f539e18cdb1. The review artefacts are this page and three Wiki pages, identified by the commit that contains them and, for each Wiki page, by the SHA-256 of its file.

  • The method added for Code items, dreyeck/src/verified-example.lisp lines 160–166. File SHA-256 981fb3f0…9339a, the value recorded in docs/trusted-executable-examples-evidence/verification.txt; SHA-256 of the seven lines, each ending in a line feed, 9545ac54…ed9c86.
  • The method every Item type had before, hyperbook-fedwiki/story-items.lisp lines 109–115, unchanged by the reviewed commit. It renders a type label, an Inspector reference to the item and the escaped text. File SHA-256 b2a75127…6c55d; SHA-256 of the seven lines 0226bd08…c0439e.

Line 161 of the first file says: “Ordinary Code remains a passive source view.” That documented statement is what the question below examines.

2. Claude's criticism, as a discourse

The criticism is not a verdict but three Wiki pages, structured by the folds of the Claim Template: question, claim, support and oppose. Each paragraph is one move, and each link stands under the fold that gives it its role.

  • The question: should the new :code method preserve the prior Inspector rendering of unmarked Code items? Under its claim fold it links the two positions.
  • Position A: yes, the prior rendering is existing behaviour an opt-in extension should not change unintentionally.
  • Position B: not necessarily, passive escaped text may be the intended design.

Every move names its kind, fact, assessment or normative assumption, and the warrant of its content: observed, derived, inferred or hypothesized. That a move supports or opposes a position is a second claim, Claude's argumentative assignment. It is interpreted, and nothing checks it. The difference between the two methods is derived from reading them; that this difference supports Position A is not derived but argued.

The pages belong to a local site of their own, named trusted-examples-review.invalid, a name that resolves nowhere. Their links are resolved in that site's page store, so a link leads to the local page, not to a remote one. A role comes from where a link stands, not from what its target says: these folds are structure written by Claude, not IBIS rules that anything enforces.

3. Checks actually run

  • The SHA-256 values in verification.txt were recomputed for the five files at 9b57bd4b and match, and the line hashes above were computed from git show. That is observed. It says the source cited is the source that was tested, not that the criticism holds.
  • No other render-story-item method for :code exists in the repository, and no system other than its own subsystems depends on dreyeck/verified-example. Observed by search.
  • The slice's own test ran on 2026-10-31, run by the slice's implementers. Its case for unmarked Code checks escaping only, so its result does not bear on the question.
  • This page's structural check reads the three Wiki pages, their folds, their journals and the local resolution of their links. It checks structure, not the criticism.

4. Not yet checked

The probe P1 has not been executed. It would render one unmarked Code item before and after loading dreyeck/verified-example, in a fresh process, and compare the HTML and the Inspector references. Until it runs, the difference between the two renderings rests on reading alone. Once it has run, its run and its result will be observed; whether the difference is a defect will still be the question above, open to argument.

Nor has EXTRACT or the Claim Link Survey been run over these pages. Which typed relations those mechanisms would derive from the folds is therefore not observed either.

5. Your judgement

This page records no answer, and none is simulated. You may accept or reject a position, propose another, add or contest evidence, raise a new question, or judge the criticism unwarranted. Each of these is a paragraph on your own site that links back to the page it answers, so that a reply stays yours and Claude's moves stay Claude's.

Fischer's response step, accept, reject or explain, is not implemented here. A binding decision on work is a different thing again: the project's Acceptance Records are written by the project owner, about declared work packages, and none of them concerns this question.
