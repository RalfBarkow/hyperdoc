Everything below comes out of files on this disk. The engine is vendored in a local source station, and the definitions shown here are transcluded from it rather than copied into this page, so they cannot drift out of agreement with the code that runs.

(ensure-riesbeck-engine-loaded)

That line is the page's own precondition, and it can fail honestly. The engine is not a dependency of this repository: it is loaded out of a local source station that is deliberately not deployed. Where that station is mounted, the definitions below are transcluded from it and the examples run. Where it is not — a served HyperDoc, for instance — each definition is replaced by an explicit "not available here" view, and the examples report :NOT-AVAILABLE-IN-THIS-RUNTIME instead of claiming to be executable.

Provenance of the source station

The station wraps Chris Riesbeck's Lisp Critic from Northwestern's CS 325 in the ASDF-loadable form Zach Beane published on 2004-05-06. Beane's README records exactly three changes: require/provide removed, course-package references replaced by lisp-critic-user, and an ASDF system file added. Nothing is fetched when this page is read; the station is read where it already is.

The package and system boundary

Two packages matter. The engine lives in LISP-CRITIC; rule names are interned in LISP-CRITIC-USER, which is the package Beane introduced in place of the course package. The wrapper system a-critic-for-lisp exists only to make the preserved code discoverable and loadable — it deliberately does not define an analyzer protocol of its own.

How a rule is represented

A rule is a pattern plus a response template, registered under a name. This is the defining macro, transcluded from the engine:

(engine-source-view "DEFINE-LISP-PATTERN")

It expands into a registration call, which is where the pattern and the response actually get stored:

(engine-source-view "ADD-LISP-PATTERN")

The recommendation the rule carries — use CADR or SECOND instead of (CAR (CDR ...)) — is not written into this page. It is the response template stored by the engine, and it arrives here only by being read from the rule object.

How a rule is applied

This is the function our slice calls. It takes a rule name and a form, and returns findings:

(engine-source-view "APPLY-CRITIQUE-RULE")

And this is how a finding becomes the sentence a reader sees:

(engine-source-view "MAKE-RESPONSE-STRING")

The engine's own entry points

The engine offers its own interface, which our slice does not replace. Note that CRITIQUE is a macro, not a function — it takes the definition itself rather than a quoted form, which is the first thing that surprises anyone loading this code into a modern image.

(engine-source-view "CRITIQUE") (engine-source-view "CRITIQUE-DEFINITION") (engine-source-view "CRITIQUE-FILE")
