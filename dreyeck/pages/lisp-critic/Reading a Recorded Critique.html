Recorded, not live

These evaluations were produced with the 2004 Riesbeck/Beane Lisp Critic in a trusted development runtime. This server does not run that engine. It is loaded as code that arrived with a page, which a served runtime does not run, and its licence for redistribution has not been established. What the server reads is the record of a run.

Recorded is not written by hand. Every recommendation below is the text the engine produced. The record names the example by page, form, character range and a digest of the source it was read from, and the engine by the digests of its files. When a page is opened, the example is observed again in this server's own source. That says whether the record is still about the example as it reads now, and where in it the rule matched.

A recommendation worth taking

READING-PLAN adds a documentation string to a copied definition with (setf (cdddr form) (cons "…" (cdddr form))). The rule SETF-PUSH matches it.

setf-push-recorded-example

A match to read critically

READING-OUTSTANDING-CHANGES compiles (lambda (x) (+ x 1)) from quoted data, then redefines the same function as (lambda (x) (+ x 2)), to show a change that exists only in the running image. The rule X-PLUS-1 matches (+ x 1).

Open the recorded X-PLUS-1 evaluation

x-plus-1-recorded-example

The match is inside a QUOTE. The rule reads the example's source as code throughout; it cannot ask what the quoted list is for, or why its 1 sits beside a later 2. Should the example follow the recommendation? That is a judgement for its reader, not a fact the rule has established.

What a Critique is

A Critique is a rule's finding, with the evidence it rests on. It is not a defect report. A match is not a mistake, and a recommendation is not a change anyone has made. Keeping the rule, the match and the engine inspectable is what lets a reader decide what to do with it.
