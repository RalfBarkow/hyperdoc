The previous page showed an engine that prints findings. This page shows what this repository adds: every rule application becomes a record, and a finding becomes an object.

One rule, applied for real

The target program is never evaluated. Only the rule is applied to its text, which is why a critic can safely look at code that would not run:

run-one-rule

Three outcomes, not two

The distinction that matters is between "the critic had nothing to say" and "the critic did not get to speak". Collapsing them would make a broken run look like a clean program. 

successful execution + match      → Evaluation Record + Critique
successful execution + no match   → Evaluation Record only
failed execution                  → Evaluation Record with condition

Each case below is a real run against the real engine.

The three together

Read the :OUTCOME key in each case. The invariant is that a rule application always yields an Evaluation Record; only the first case also yields a Critique.

How the outcome is derived

The summary is computed from the evaluation-record protocol rather than from critic-specific slots, which is why the same three terms would apply to any other evaluated thing in this repository:
