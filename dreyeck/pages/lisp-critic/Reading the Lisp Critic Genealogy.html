Reading the Lisp Critic Genealogy

dreyeck/lisp-critic/reading

Several different things have been called "Lisp Critic". This reading keeps them apart, because they are not versions of one another and only some of them can be shown running here.

Why this is not simply a linter

The oldest station is Gerhard Fischer's 1987 A Critic for LISP. That system was an integrated environment for incremental learning and "learning on demand": rules and a rule interpreter, but also a user model, explanation with a knowledge browser, and visualization support, all present together. Its purpose was to improve Lisp programs locally according to a style encoded by rules — explicitly not a whole-program correctness framework.

A modern linter shares the surface behavior (look at code, say something about it) and almost none of the rest. Reading the two lines as one history loses exactly what was interesting about the first.

Each of those sentences is a claim with a source. The reading records them individually rather than summarising a paper from memory:

Three things "here is the Lisp Critic" can mean

The distinction that keeps this reading honest is what kind of access we have to each station. It is checked, not asserted: the example below looks at the filesystem and the running image. 

:DOCUMENTED        a local document describes it; no source here
:SOURCE-OBSERVED   source files are readable in this workspace
:EXECUTABLE        the code runs in this image

Fischer's system reaches the first rung and no further. Riesbeck's engine reaches all three. Our slice reaches all three and adds objects of its own. Giving those the same visual weight on a page would be the easiest way to mislead a reader, so the status travels with every station.
