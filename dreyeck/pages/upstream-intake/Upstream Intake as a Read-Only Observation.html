Upstream Intake as a Read-Only Observation

dreyeck/upstream-intake

An upstream hint is initially an object to observe, not a change to execute. HyperDoc retains the reference and the locally observable facts so that a later integration decision can be made explicitly and inspected in context. 

OBSERVE
  -> LOCATE
  -> COMPARE
  -> CLASSIFY
  -> INSPECT

This process does not continue automatically to MERGE, CHERRY-PICK, INSTALL, or SUPERSEDE. The intake records evidence; it does not prescribe an operation.

Two kinds of upstream reference

A :GIT-COMMIT reference asks questions about commit identity and the current local history:

  • Is the commit object present locally?
  • Is it an ancestor of the current HEAD?
  • What is its merge base with HEAD?
  • Which local or remote-tracking refs contain it?
  • Which fact-derived classification follows?

A :COMPONENT reference asks a different set of questions. It retains a local subject, an upstream candidate, a proposed relation, a verification status, and explicit contract observations. It does not use Git ancestry as a proxy for capability equivalence.

Commit classifications

  • :ALREADY-INTEGRATED: the observed commit is an ancestor of the current HEAD.
  • :AVAILABLE-NOT-INTEGRATED: the commit object is present, but is not an ancestor of the current HEAD.
  • :NOT-AVAILABLE-LOCALLY: the checkout has no local commit object for the supplied reference.

None of these classifications means “merge required” or “cherry-pick required.” Commit identity, patch equivalence, and an integration decision are three distinct questions: 

Git commit identity
  != patch equivalence
  != integration decision

Component intake preserves an analogous distinction: 

observed upstream capability
  != verified contract equivalence
  != supersession decision

Implemented observation operations

MAKE-UPSTREAM-COMMIT-INTAKE performs the local object, ancestry, merge-base, and ref observations. Its implementation performs no fetch.

make-upstream-commit-intake

MAKE-COMPONENT-INTAKE records a relation hypothesis and its contract questions without evaluating the candidate implementation.

make-component-intake

UPSTREAM-REFERENCE-SUMMARY turns either inspectable object into a copy-pasteable Lisp plist. The object itself remains the primary evidence.

upstream-reference-summary
