Assessing an Upstream Commit

dreyeck/upstream-intake

Observing an upstream commit says where it stands. Assessing it asks what it means for dreyeck.ch: what it changed, where that definition stands in the fork, which ASDF system owns it and which should, what it may affect, and what to do about it. The assessment reads Git objects and source text; it loads no library code, fetches nothing, and records no decision. A decision is a proposal until a person accepts it, and accepting it is not carrying it out.

Three things are separated there, each with the epistemic status of its support: the handler that upstream changed is the second of the two in make-fedwiki, and the first, around the HTTPS connection attempt, is the same before and after; in the fork the changed type list no longer stands in make-fedwiki but in initialize-fedwiki, so the upstream hunk cannot be applied as it is; and the choice between the parent class and the explicit condition classes is a decision that is deferred, with its evidence, rather than made.
