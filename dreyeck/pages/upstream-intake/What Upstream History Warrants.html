What Upstream History Warrants

dreyeck/upstream-intake

Once the upstream history is observable, it can be used as a warrant oracle. A local difference is justified when some upstream commit accounts for it, and unwarranted when none does. That turns an argument about taste into a question with an answer.

Three categories, not two

:UPSTREAM-NOW-PROVIDES        protocol Konrad deliberately generalized
:DREYECK-SPECIALIZATION       local policy expressed through that protocol
:REMAINING-LOCAL-LIBRARY-DELTA  local library change with no upstream seam

Each row in the result carries an :UPSTREAM-WARRANT resolved out of the observation layer and an :LOCAL-EVIDENCE line read from the tracked file. A row cannot claim upstream provenance without naming the warrant that supplies it.

The Dreyeck specialization is a separate entry rather than a fourth row, because it is not a thing upstream provides or fails to provide. It is local policy that happens to rest on two published names.

What this history does not warrant

Observe the remaining local delta and the residual coupling

page-loading-local-delta-example

Two findings, of different kinds.

code-subdirectory and cl-source-file-components-under are absent from upstream hyperdoc/core.lisp through 8a1149 and present locally. That is a genuine library delta: a local extension with no upstream counterpart in this range. It is intentional, and naming it as such is more useful than pretending the boundary is clean.

The LOAD-PAGE :AFTER method is subtler. The method itself sits on a public seam, but its body reaches the DOM through the internal hyperdoc::parse-tree slot, because this history establishes no public parse-tree accessor. So a supported extension point still carries an unsupported coupling inside it. The protocol work did not retire that.

One spelling, and why history settles it

Upstream writes the lambda list with a bare parameter name. The local committed source carries a package prefix on that same parameter: 

upstream   (defgeneric page-class (hdoc filetype))
local      (defgeneric page-class (hyperdoc::hdoc filetype))

Compare the two spellings by text and by reading

page-loading-serialized-spelling-example

The example reports :SAME-TEXT-P NIL and :SAME-READING-P T. In package hyperdoc both spellings designate the identical symbol, so the binding is unaffected: this is not a bug, and the code is correct either way.

What the history adds is provenance. The warranted change at beb1689 was the arity — one argument became two. No upstream commit in this history produces a package prefix on a lambda-list parameter, because a printer produces that and a person does not. The semantic difference has a warrant; the representational difference has none.

Upstream's own source carries the counter-evidence. The method added in beb1689 reads ((hd hyperdoc ), with a stray space before the closing paren, and the export clauses still carry their organizational comments. Hand-edited source keeps its typos and its comments; a read-and-print round trip normalizes the first and destroys the second.

This is a provenance finding, not an instruction. Knowing that a spelling is unwarranted is a reason to record it, not a reason to rewrite source so that it resembles upstream. No source is changed by reading this page.

How to use this

semantic difference + upstream warrant   -> justified, keep
semantic difference + no warrant         -> a local decision, name it
textual difference  + no warrant         -> representation, record it
