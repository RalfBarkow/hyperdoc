Topicmap Interaction Documentation

dreyeck/work/ctm-page-authoring

This is the carrier of the Work item topicmap-interaction-documentation in Work Breakdown: technical documentation of the two Topicmap inspection Operations Inspect Topicmap sign and Inspect represented object, written as four DITA 1.3 topics and kept as typed Story Items of a Federated Wiki page. The Work item is contained in the area Interaction and is current work of HyperDoc Dogfooding. It documents code that exists; it changes none, and it grants no authority.

What this Work item is, and what it is not

  • It is a Work item of the backlog: bounded, with a status, and judged as it is understood. It is not a work package of the WBS of Authoring the CTM Plan Page. That WBS has the editing of one wiki Item as its scope, and this Work item does not add to that scope: its statuses, its plan and its dictionary are as they were.
  • It is technical documentation in the sense of Work Breakdown: how a result is built, run and checked. It describes the current code and is not a plan. The Item edit path itself is documented on Item Edit Path in HyperDoc; the Topicmap it produces is what the four topics explain.
  • It relates to the existing work by the plain relations contains and current-work of the Work Breakdown. No Relation Contract was added for it.

Deliverable, acceptance, evidence, plan step, status

DeliverableThe four DITA topics as Story Items of the Federated Wiki page topicmap-inspection-dita, readable and navigable in the HyperDoc Inspector: the page, and its Items Topicmap Signs and Represented Objects (concept), TMDM Roles and Projected Edges (concept), Topicmap Gesture Operations (reference) and Inspect a Topicmap Sign (task).
Acceptance criterionEach topic is DITA 1.3 that validates against its DTD; what it says about Targets, Operations and results is what the implementation does; from the Work Breakdown a reader can open a topic, read the difference between Inspect Topicmap sign and Inspect represented object, and inspect the real HyperDoc and TMDM objects it names. Whether the criterion is met is judged by the user, as scope verification (PMBOK Guide 2000 §5.4) is; a passing test does not decide it.
EvidenceThe test system dreyeck/dita-story-item/tests (Lisp) with its validation of the four Items against the DITA 1.3 DTD, and the browser script scripts/test-ctm-page-authoring-documentation.mjs, which walks the path from the Work Breakdown to the objects. Source references: dreyeck/src/topicmap-gesture.lisp, dreyeck/src/gesture-binding-witness.lisp, dreyeck/src/topicmap-inspector.lisp, dreyeck/src/topicmap-tala-inspector.lisp, dreyeck/work/item-edit-topicmap.lisp. Evidence on a copy is not acceptance and not a deployment.
Plan stepD1, writing and checking the four topics, one step that produces the deliverable above. It depends on nothing outside this repository. It is open.
StatusThe data-status of the declaration in Work Breakdown. It is changed only through the existing Change work status operation and is not derived from a test result.

Reading the result

The Story Items have the type dita. No Federated Wiki plugin for that type exists in this repository, so the Inspector's own reading is the smallest integration that was needed: dreyeck/dita-story-item. A Story Item of this type has the view DITA topic, the structured reading, and the view Story item, the XML source as stored. An xref whose href starts with hyperdoc: opens the named Inspector object: a class, a function, an Operation, a worked example or another Item of the page. An editor for the type would be a plugin of its own and is not part of this work.

Where the page file is

The page file is retained at dreyeck/work/topicmap-inspection-docs/site/pages/topicmap-inspection-dita, built from the topics in the directory beside it by scripts/build-topicmap-inspection-page.py. The links above open objects only in a Catalog whose site root holds a page of that slug; elsewhere they open an explanation. Putting the file into a site root is the operator's step, like the transfer of the plan page, and nothing here does it.
