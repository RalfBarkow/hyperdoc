CTM Plan Page WBS Dictionary

dreyeck/work/ctm-page-authoring

The WBS Dictionary for Authoring the CTM Plan Page. Each entry defines one work package of that page's WBS: what it contains, when it is accepted, which authority it needs, which effect it performs and what evidence shows it. An entry describes the package; it grants nothing. The planned controls for the later concrete edit are listed with the existing test that already exercises each one generically, or marked as planned where none does.

1 Verified page source

Observe the page ctm-and-tmdm-in-hyperdoc at the site root of the HyperDoc instance that will edit it, through the existing local site reader (read-local-fedwiki-page, configured-local-site-root), and record site id, site root, slug, page SHA-256 and the Item ids of its story.

The site root is the one the editing instance is configured with; the slug is a valid page slug; the Item to be edited occurs exactly once; the page digest is recorded, and any difference from the last local observation is explained (for example a fork entry added by the transfer).

None to write. Reading the site root needs only the file access the instance already has. The transfer itself is the operator's.

None: read-only observation.

An observation record with site root, slug, digest and Item ids, read in the instance that will perform the edit.

  • Correct site root, slug and Item id: an invalid slug and an absent Item id are refused.

2 Inspectable edit proposal

Form, inside the HyperDoc Inspector, the expected Item (the exact current JSON of the one Item), its replacement with the same id, and the ordinary FedWiki edit Action, bound to the page digest of package 1. Show all three without executing anything.

The replacement keeps the Item id and differs from the current Item; the content was decided by a person and that decision is recorded; the proposal names the digest it was formed against.

None to prepare. The content decision belongs to the user.

None: an unexecuted proposal.

The proposal object in the Inspector and the recorded content decision.

  • Change at exactly one Item: an Item id that occurs more than once is refused.

3 Authorized single-item edit

Execute exactly the proposal of package 2 with the existing M0 writer edit-fedwiki-page-item, holding a page-authoring capability for this site root, this page and the Action edit. In production that capability is derived by the existing authenticated path from a signed envelope, a registered principal, a single-use challenge and an authoring rule.

The writer returns its edit record; nothing is executed without a capability that covers the page and the Action; a page that no longer holds the expected Item is refused as stale; the journal gains exactly this Action.

A page-authoring capability for site dreyeck.ch, page ctm-and-tmdm-in-hyperdoc, Action edit, derived from an authenticated principal's authoring rule. Not granted.

One FedWiki edit Action on one Item of one page.

The writer's edit record and the authoring request's observation.

  • No execution without permissible authority: a missing capability, or one that does not cover the page or the Action, is refused.
  • Refusal on a stale source: an Item that no longer equals the expected Item is refused without writing.
  • Journal continuation: the journal gains exactly the ordinary edit Action.

4 Verified persisted result

After the effect, read the page again in a fresh process and compare it with the proposal and with the observation of package 1: the same Items in the same order, the edited Item equal to the replacement, every other Item unchanged, the journal extended by exactly the Action.

All comparisons hold. A mismatch is reported as unverified and is not repaired or retried automatically.

None to write: an independent observation.

None: read-only verification.

A verification record with the page digests before and after and the result of each comparison.

  • Unchanged other story Items: every Item other than the edited one reads back unchanged.
  • Fresh reconstruction: the page is read in a new process and its Items and journal are compared with the proposal. The existing writer test rereads within its own process only.
