Planning with SHOP3

dreyeck/work/reading

Status: optional in-memory experiment. Question: can SHOP3 usefully plan document-one-D2-concept?

The current dreyeck/shop3 system supplies a plan-result object, plan normalization and manual-topic examples. Historical extraction-planning examples demonstrate shop3:find-plans, shorter plans, plan trees and final states. Those historical worktrees were read only.

  1. Identify concept/source
  2. Formulate Text Page
  3. Create executable example
  4. Render
  5. Verify
  6. Expose in Inspector
  7. Relate in Topicmap
  8. Review

The optional experiment uses one ordered method and modeled stage facts. Its primitive operators only update SHOP3's simulated state; they do not write pages, render D2, verify real output, invoke an editor or apply changes. In particular a modeled “verified” fact is not verification evidence.

Verdict B: this experiment restates the hand-written sequence. It can return the eight stages and refuse a problem with no known source, but offers no alternative decomposition, resource decision or repair strategy. That is evidence for this small domain only, not a general assessment of SHOP3.

The existing generic step normalizer labels unknown operators as source edits. This experiment therefore exposes the raw/shorter plan through the existing result object's Inspector slots, without presenting that classifier as a documentation-specific checklist. A useful next investigation would need actual alternate methods and observed preconditions; neither is invented here.

(asdf:load-system "dreyeck/work/planning")
(defparameter *documentation-plan*
  (dreyeck/work/planning:documentation-plan-example))
(clog-moldable-inspector:clog-inspect :object *documentation-plan*)

This optional system is absent from normal Catalog startup. Run (asdf:test-system "dreyeck/work/planning/tests") to check the actual plan and missing-source control. It grants no execution authority and is not connected to source mutation.
