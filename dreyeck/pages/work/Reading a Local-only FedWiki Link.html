Reading a Local-only FedWiki Link

dreyeck/work/reading

This reading follows the opt-in, read-only FedWiki integration at HyperDoc revision 5639701c2dc33701d9be15c7a3f2ec90702126d6. Its question is narrow: how can a missing local link target lead to a SHOP3 fork plan without creating a local page?

The public Catalog serves this text. The optional ASDF system dreyeck/work/fedwiki-local-only is not part of normal Catalog startup. The runnable example below is for an explicitly selected local SLY/CLOG development image; opening this page executes no planner and performs no Wiki writes.

1. Observe the actual local link

The retained fixture page pages/source contains a paragraph story item at index 1, with text [[Missing]]. Its link target slug is missing. The example explicitly chooses local site fedwiki:local and reads the page from the local store; it does not infer the own site from the item's remote site field or from its journal.

In this fixture the target page is absent: finding = :confirmed-local-absence and target-page = NIL. A failed local read would instead mean :unknown, not absence. The observed local state is distinct from any later simulated plan state.

2. Read the additional evidence with its limits

The example's inert JSON evidence file declares a remote-snapshot from remote-item for the target missing, a fork-permitted fact, and fork-source-policy = cached-copy-sufficient. The saved copy is checked for an allowed path, SHA-256 digest, FedWiki page structure and stated site/slug association. The own site cannot appear as its own remote source.

These checks establish local byte integrity and structural consistency, not authenticated historical provenance or present remote availability. The evidence file is an explicit model input, not a network request.

3. Inspect SHOP3 preparation and resolution

prepare-link calls the consolidated PR-#33 defederation planner. For this case it can plan a fork from the verified cached copy. The native plan, plan tree and simulated final states remain available on the preparation result. Repeated preparation of the same target inside a plan has one modeled fork; continuation of an accepted simulated result needs no second fork.

resolve-link receives only a verified planning result for this observation. The resulting modeled-local-page is hypothetical and supports a local-only resolution plan. No remote fallback is performed, no fork is executed, and target-page remains NIL in the actual local store.

4. Task: inspect the observation in an existing SLY/CLOG image

Goal. Follow the existing observation, verified local evidence and simulated SHOP3 results in the CLOG Moldable Inspector. This task does not start a server, materialize a Wiki page or execute a fork.

Prerequisites

  • Use a SLY mREPL connected to the intended local development image and the HyperDoc checkout with this optional system. Inspect *default-pathname-defaults* or the ASDF source directory if unsure which checkout the image is using.
  • The image's ASDF source registry must include both dreyeck/work/fedwiki-local-only and the separate clog-moldable-inspector system. Loading the former does not load the latter.
  • For the browser step, CLOG must already be running in this same Lisp image, with an existing connected browser body. A CLOG listener running in another SLY image does not satisfy this prerequisite.
  • Evaluate each code block as its own SLY request. Do not paste all steps as one request: SLY reads the entire request before evaluating the first form. An as-yet unloaded package named later in the input therefore causes a reader-package error even if an earlier form would load it.

Step 1. Load the observation runtime

(asdf:load-system "dreyeck/work/fedwiki-local-only")

Expected. SHOP3's defederation and link-resolution domains load successfully. This does not imply that the Inspector package is available.

Step 2. Load and check the separate Inspector system

(asdf:load-system "clog-moldable-inspector")

After that request has completed, evaluate:

(list (find-package "CLOG-MOLDABLE-INSPECTOR")
      (fboundp 'clog-moldable-inspector:on-new-inspector))

Expected. A package object and T. If ASDF cannot find the system, inspect the development image's source registry before proceeding; do not substitute a server restart. If the package is absent, stop here.

Step 3. Create and check one observation

(defparameter *local-only-link-reading*
  (dreyeck/work/fedwiki-local-only:demo))
(list (dreyeck/work/fedwiki-local-only:finding *local-only-link-reading*)
      (dreyeck/work/fedwiki-local-only:target-page *local-only-link-reading*))

Expected. (:CONFIRMED-LOCAL-ABSENCE NIL). demo prepares and resolves plans for the fixed local fixture; it performs no Wiki write or remote request. The result is one observation with references to its planning history.

Step 4. Verify the existing CLOG connection

(list :running (clog:is-running-p)
      :body (and (boundp 'clog-user:*body*)
                 clog-user:*body*
                 (clog:validp clog-user:*body*)))

Expected. :RUNNING T and :BODY T. A missing body or inactive listener is a prerequisite failure, not evidence that the Local-only example failed. Do not run an implicit start operation against another listener or the production image.

Step 5. Open the observation in the existing Inspector body

(let ((body (and (boundp 'clog-user:*body*)
                 clog-user:*body*)))
  (assert (clog:is-running-p) ()
          "CLOG is not running in this SLY image.")
  (assert (and body (clog:validp body)) ()
          "No connected CLOG body in this SLY image.")
  (clog-moldable-inspector:on-new-inspector
   body :object *local-only-link-reading*
   :pane-width "600px" :playground? nil))

This uses the existing on-new-inspector entry point rather than clog-inspect, which may start CLOG when no listener exists. If the body is not available in clog-user:*body*, first establish the actual body binding of this image; do not create another server merely to satisfy the example.

Expected. The Local-only evidence view links to the actual own-site object, source page and revision, story item, wiki link, observation evidence, preparation result, resolution result, SHOP3 problem, planned operations and simulated final states. These are object references, not illustrative copies.

Result and troubleshooting

The reading succeeds when the Inspector lets the reader distinguish the observed missing local target from the external cached-copy claim and from the simulated fork, while the real store remains unchanged. The CLOG navigation itself has not yet been witnessed in this reading; record the actual result before marking it accepted.

Reader-package error: Package CLOG-MOLDABLE-INSPECTOR does not exist means Step 2 has not successfully run before the next input is read. It does not contradict a successful Step 1. Compiler and ASDF warnings during Step 1 do not by themselves establish a failure; check whether the load completed.

Missing or invalid CLOG body: Stop at Step 4, then inspect the actual Lisp image and browser connection. Do not restart an unrelated service.

What has and has not happened

  • Observed: a real local page and link were read; the target was absent at observation time.
  • Externally stated and checked: a stored copy and a selected source policy were validated as local evidence inputs.
  • Planned: SHOP3 computed a possible fork and subsequent modeled local-only resolution.
  • Not executed: no fork, remote retrieval, page materialization or production resolver change occurred.

Source for this exact reading: runtime and demo, R1 review evidence. The known F4–F7 limits and the missing D2/TALA reading environment remain documented; they are not concealed by this example.
