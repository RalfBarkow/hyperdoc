Reading a Local-only FedWiki Link

dreyeck/work/reading

This reading follows the opt-in, read-only FedWiki integration at HyperDoc revision 5639701c2dc33701d9be15c7a3f2ec90702126d6. Its question is narrow: how can a missing local link target lead to a SHOP3 fork plan without creating a local page?

The public Catalog serves this text. The optional ASDF system dreyeck/work/fedwiki-local-only is not part of normal Catalog startup. The runnable example below is for an explicitly selected local SLY/CLOG development image; opening this page executes no planner and performs no Wiki writes.

1. Observe the actual local link

The retained fixture page pages/source contains a paragraph story item at index 1, with text [[Missing]]. Its link target slug is missing. The example explicitly chooses local site fedwiki:local and reads the page from the local store; it does not infer the own site from the item's remote site field or from its journal.

In this fixture the target page is absent: finding = :confirmed-local-absence and target-page = NIL. A failed local read would instead mean :unknown, not absence. The observed local state is distinct from any later simulated plan state.

2. Read the additional evidence with its limits

The example's inert JSON evidence file declares a remote-snapshot from remote-item for the target missing, a fork-permitted fact, and fork-source-policy = cached-copy-sufficient. The saved copy is checked for an allowed path, SHA-256 digest, FedWiki page structure and stated site/slug association. The own site cannot appear as its own remote source.

These checks establish local byte integrity and structural consistency, not authenticated historical provenance or present remote availability. The evidence file is an explicit model input, not a network request.

3. Inspect SHOP3 preparation and resolution

prepare-link calls the consolidated PR-#33 defederation planner. For this case it can plan a fork from the verified cached copy. The native plan, plan tree and simulated final states remain available on the preparation result. Repeated preparation of the same target inside a plan has one modeled fork; continuation of an accepted simulated result needs no second fork.

resolve-link receives only a verified planning result for this observation. The resulting modeled-local-page is hypothetical and supports a local-only resolution plan. No remote fallback is performed, no fork is executed, and target-page remains NIL in the actual local store.

4. Follow the same objects in a local Inspector

In a SLY image with the checked-out revision and CLOG Moldable Inspector already running, evaluate the following forms separately:

(asdf:load-system "dreyeck/work/fedwiki-local-only")
(defparameter *local-only-link-reading*
  (dreyeck/work/fedwiki-local-only:demo))
(list (dreyeck/work/fedwiki-local-only:finding *local-only-link-reading*)
      (dreyeck/work/fedwiki-local-only:target-page *local-only-link-reading*))
(clog-moldable-inspector:clog-inspect
 :object *local-only-link-reading*)

The status form is expected to yield (:CONFIRMED-LOCAL-ABSENCE NIL). The Local-only evidence Inspector view links to the actual own-site object, source page and revision, story item, wiki link, observation evidence, preparation result, resolution result, SHOP3 problem, planned operations and simulated final states. Follow the object references: the page does not re-create those objects as illustrative copies.

Reader's check: Can you identify the source of the local absence, the separately supplied cached-copy claim, the planner's hypothetical fork, and the unchanged local store? The code and identity tests have been reviewed; navigation through those links in a live CLOG session remains a separate observation.

What has and has not happened

  • Observed: a real local page and link were read; the target was absent at observation time.
  • Externally stated and checked: a stored copy and a selected source policy were validated as local evidence inputs.
  • Planned: SHOP3 computed a possible fork and subsequent modeled local-only resolution.
  • Not executed: no fork, remote retrieval, page materialization or production resolver change occurred.

Source for this exact reading: runtime and demo, R1 review evidence. The known F4–F7 limits and the missing D2/TALA reading environment remain documented; they are not concealed by this example.
