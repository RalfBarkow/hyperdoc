One Page From Browser to NDN and Back

dreyeck/ccnx-federated-wiki

This page follows Plain Text Example through the Main repository at 8426dc5, one step at a time, and then shows how the Prototype at c5b1b93 differs. Every step names the lines it rests on. Nothing was run; the example is derived by applying what those lines say.

The path in Main

#StepWhat the source doesLines (pinned)
1Edit pageHandler.put stamps the action with the current time and stores it locally. pushToServer exists but is never called. pageHandler.coffee L76–L163
2Page to JSON pushToLocal appends the action to journal, rebuilds story from the page on screen, and adds page, excludes and favicon. pageHandler.coffee L76–L95
3JSON to IndexedDB updatePage sets version to the date of the last journal action and writes the record into the store page/<slug>.json, key version. repository.coffee L141–L176
4Announce If the browser is online, an Interest <prefix>/page/update/<page>/<version> goes out on every active face. repository.coffee L127–L139
5Serve: NDN Content Object A peer answers an Interest for a page: the record, as JSON.stringify text, becomes the content of an object named <interest>/<version>, with a freshness of 604800 seconds, and the object is signed. interfaces.coffee L9–L53
6NDN retrieval The closure takes the content of the first object, parses it as JSON and hands it on. Pages are asked for when a face opens (welcome-visitors) and for every [[link]] that is drawn. ndn-closures.js L43–L149, wiki.coffee L70–L91
7Back into IndexedDB updatePageFromPeer removes the records named in the incoming excludes and stores the page. repository.coffee L94–L124
8Wiki page Pages are rendered from IndexedDB only. The former Ajax read from a server is commented out. pageHandler.coffee L18–L72

Documented. The Main ReadMe describes the same design: pages “are stored locally in the clients IndexedDB … and synced on page update action” (ReadMe.md L4). Source and ReadMe agree.

The express server of the repository still stores pages as flat JSON files (server/express/lib/page.coffee), but the client path above does not use them.

How the Prototype differs

  • It reads differently. A page not found locally is asked for as /sfw/<slug>; once it arrives it is shown and immediately republished locally as a fork (pageHandler.coffee L22–L78).
  • It names differently. The version is a publication timestamp, not the last journal date.
  • It keeps less. The store has one record per slug; a later write replaces it. Other lines of the page go to a separate store of twins.
  • It signs when asked. The Content Object is made, and signed, when an Interest for the name arrives (ndn-closures.js L255–L277).

Documented. The Prototype's ReadMe calls the concept “workable, though it will be some time before it is useable.” It names a thin server with a websocket proxy and a client that renders, saves and serves pages in IndexedDB. The source matches that division.
