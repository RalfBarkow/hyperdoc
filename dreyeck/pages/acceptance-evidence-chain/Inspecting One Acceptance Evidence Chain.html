Inspecting One Acceptance Evidence Chain

This optional reading connects one original execution report, its retained log and a specified HyperDoc revision. Its evidence revision is 9176349edb473becd7423a7ca246f9bc07a75388; its specified tested revision is 36c69d3312ae70748ecd40a5452759fcfaad25c4. It reads Git objects at these exact commits, not the checkout's moving files.

The report says that a command executed, with its recorded working directory, environment overrides, timestamps and exit code. Those remain reported statements. This inspection independently checks properties of the retained artifacts: Git blob identities and the log's SHA-256 against the report. A matching digest establishes content consistency, not that every historical event occurred as reported.

The JSON has no tested-revision field. The source candidate-build.nix, retained at the evidence commit, contains a literal reference to the specified revision. The reading retains that source too. It neither evaluates Nix nor proves that the historical process used these exact descriptor contents. The source revision is an explicit inspection context; its local Git commit identity is checked separately.

What the result means

The evaluation protocol describes this inspection. Its status is :inspected; its times are the inspection's times. The historical timestamps and exit code stay in the report and carry :reported warrant. A nonzero reported exit code is still inspectable when its retained artifacts are consistent.

The log is UTF-8 text containing non-ASCII characters. Before hashing it, the adapter verifies that the decoded text re-encodes to octets with the exact original Git blob identity. A lossy round-trip is refused. This bounded reader does not claim to be a generic binary Git-file reader.

No acceptance record, TMDM schema or SHOP3 domain is created. No result here supplies an acceptance decision, independent-author assessment or deployment authority. The command, working directory and environment strings are never executed or followed.
