Curiosity Token as Topic Map

Ward's page Curiosity Token on found.ward.fed.wiki is shown here a second time, as a Topicmap of the objects it consists of. Nothing is drawn by hand: every topic is an object read from the page's JSON.

  • The page as retained, fetched on 2026-10-24.
  • The record of the retained JSON: its URL, fetch time, status and SHA-256, which is checked when the page loads.
  • The JSON itself, as parsed.

The token is an item id

Story item cf80b0444c62866e is a markdown item whose text is # Curiosity. It is the third of eleven items, and it is not a pagefold. What makes it a token is its id, not its text or its type. The page itself says so: the token keeps its "referential power" when its text or its type changes.

The page's own journal shows such a change. Item e1708c9ae711cfa0 was added as a paragraph and later edited to markdown, keeping its id.

Where the item came from

The journal entry that added the item records an attribution: page Photo Rotator on photos.ward.dojo.fed.wiki. This is documented provenance. It does not tell on which other pages the id occurs today; Photo Rotator itself is not retained here.

Who looks for it

Two items are SEARCH items:

  • SEARCH ITEMS cf80b0444c62866e names exactly this item's id.
  • SEARCH WORDS curiosity names a word.

So does a paragraph, which writes the id out in its text.

The search commands are read, not run. What a search finds depends on the sites a reader's Wiki can see, and no search result is recorded here.

The Topicmap

Curiosity Token as Topic Map opens with Point on cf80b0444c62866e. It holds:

  • the page;
  • its eleven items, numbered by position;
  • all 33 journal entries;
  • the attribution and the page it names;
  • the two search commands.

Every association names where it comes from:

  • story: which items the page holds, and in which order;
  • journal: the entry that adds or edits an item, places it after another, or records an attribution;
  • derived: read by this projection from an item's text, such as the id a SEARCH command or a paragraph names.

Topic ids begin with site and slug. A later, recorded search result can therefore add the same item id found on other pages as further topics, related by the shared id instead of merged with this item. That is the step from one page towards the distributed graph of What Remains to Be Demonstrated?.
