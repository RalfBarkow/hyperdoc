The branch names one input

The deployment branch does not contain the Mech extension. Its flake.nix names a single input, mech-composition, by full OID: the input line. Its flake.lock fixes that input's revision and NAR hash: the lock node. The input is RalfBarkow/wiki a83c3e0d6662a10af000696fc3f1401524cef818: the composition revision.

wiki-discourse is the branch's own wiki plus one Mech

wiki-discourse is defined in profilePackages through withMech. That function imports nix/wiki-profile.nix from the composition. It takes the branch's own wiki package and replaces only node_modules/wiki-plugin-mech.

The Mech package refuses an unpinned source

The composition builds Mech with nix/mech.nix, whose build step runs nix/mech-build.mjs. Before anything is built, that script asserts three things:

  • the module's content digest, computed by moduleIdentity, equals the pin;
  • the lockfile digest equals the pin;
  • Ward's snapshot reproduces the pinned tree and commit.

The pin is mech-pins.json's module entry, which names the module commit 1dbedae7b776ca38c36dc04302796be7a07b9371 and its digest 457b7e39….

What the chain yields, and what it does not

The whole chain as one object ends with two values. Both come from a record made before the deployment: the x86_64-linux store path of wiki-discourse, which was evaluated, not built, and the bundle hash 19b14c31…. Whether that package was built and runs is the subject of What the Deployment Proves.
