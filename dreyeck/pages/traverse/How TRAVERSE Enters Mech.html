How TRAVERSE Enters Mech

Mech runs a block by looking up its command name in one exported, mutable object: Ward's blocks catalog at WardCunningham/wiki-plugin-mech a028b4bba04e539dcaa090423d38a00a0050489d, used by the unchanged run. Nothing in Ward's source is edited.

Two entries, two profiles

The upstream entry only re-exports Ward's modules. The discourse entry imports the same catalog and calls two installers before exporting it:

  • installDiscourse adds EXTRACT, EDGES and DEBUG and wraps WALK for the role ways;
  • installDiscourseTraverse refuses an existing TRAVERSE, requires EXTRACT, and then adds one entry, TRAVERSE: { emit: traverse_emit }.

Which profile is built decides which entry is bundled. So TRAVERSE exists only in the discourse profile's bundle.

What the block does

traverse_emit checks that NEIGHBORS and EXTRACT ran before it. It takes the page holding the Mech item as its root and calls three functions in order: resolveEdges, traverse and presentGraph. It then publishes the result as an aspect, the same way WALK does, so the unchanged SOLO block can hand it on. All of these sources, and whether each entry installs TRAVERSE.
