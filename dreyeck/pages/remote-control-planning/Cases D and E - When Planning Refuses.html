5 of 6 · Refusal when prerequisites are missing

Cases D and E - When Planning Refuses

Two available transports are not enough for a valid plan. The cases with no solution reveal the boundary that both methods require. Here, the absence of a plan is an expected consequence of the modeled conditions, not a network failure.

Case D: no hypothetical authorization

In D, the API and both access routes are present, but the authorization fact is missing. Both methods require it. SHOP3 can therefore use neither decomposition and returns no solution. A different transport cannot substitute for the missing prerequisite.

Compare the initial facts of D with Case D as an inspection object and its result with no plan. Plans, plan trees, and final states are empty; the initial problem remains inspectable.

Modeled assumption. This refusal applies to the modeled task. It does not prove that a real application rejects unauthorized access. This slice includes neither real authentication nor an access-control test.

Case E: no Application API

In E, hypothetical authorization is given and both access routes are available. Yet the shared domain interface to the local runtime is missing. No transport can replace that interface: both methods require the Application API and are inapplicable without it.

The initial facts of E, Case E, and its result with no plan show a different cause of the same planning outcome. SHOP3 is not saying that an API could never be built; it finds no solution under the supplied facts.

The positive controls

In Case A, only direct access is missing: the agent method remains applicable. In Case B, only the agent session is missing: the direct method remains applicable. Together with C, D, and E, these controls distinguish a missing alternative from a missing shared prerequisite.

These small cases bound the planner's contribution precisely: it enumerates possible approaches in the model and refuses impossible ones. The final page explains the evidence for these claims and the acceptance checks that remain open.
