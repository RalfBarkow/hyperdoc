Planning Remote Control for the Zettelkasten App with SHOP3

dreyeck/work/remote-control-planning

Optional, plan-only architecture experiment for Zettel 11551: Remote Control für die Zettelkasten-App. Execution authority stays on the MacBook, model authority in the local Zettelkasten runtime; Android is a control surface. This is neither an implemented remote-control feature nor an approved project baseline.

The existing documentation experiment received verdict B: one fixed decomposition. Here two separately defined HTN methods share the task (enable-mobile-control zettelkasten macbook-a android). SHOP3 selects applicable decompositions from hypothetical input facts; it does not discover architectures.

Two methods

  • Agent session: local agent/MCP client accesses an assumed UI-independent Application API, reached through a remote agent session.
  • Direct API: an assumed HTTP/WebSocket adapter exposes that API to an authenticated mobile browser/PWA.

Both require modeled Application API availability, authorization, local execution authority and local model authority. Agent requires an agent-session fact; Direct requires a direct-transport fact. Their first primitive operators differ. Every primitive only adds facts to SHOP3's simulated state. No callback, file write, application start, permission grant or network operation belongs to the domain.
