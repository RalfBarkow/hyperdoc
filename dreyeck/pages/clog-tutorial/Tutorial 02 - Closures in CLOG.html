Tutorial 02 — Closures in CLOG

CLOG's second tutorial keeps the heading of the first and changes what a click does. It titles the page "Tutorial 02" and adds "Hello World! (click me!)"; the k-th click then adds k paragraphs that each say "Clicked k times.". It runs here the way Tutorial 01 does, as one more route on the CLOG server this HyperDoc image serves from:

(route-relation (tutorial-2-route))

The four lines are read as for Tutorial 01: the handler CLOG's table holds at the route, the file the image says it was defined in, and a live link completed by your browser, offered only while the route is mounted.

One route, many windows

This is ON-NEW-WINDOW as the installed CLOG ships it:

clog-tut-2::on-new-window

The counter x is bound inside ON-NEW-WINDOW, and CLOG calls that function once for every browser window that opens the route. Each window therefore gets a click handler closing over a counter of its own: open the live page twice and the two count separately, and reloading a window starts it from zero. A route is where the tutorial is mounted; each window is one run of it.

That was already true of Tutorial 01, whose heading turns green only in the window clicked, but nothing there accumulates, so it could not be seen. The counter itself is not shown on this page: it exists only in a closure held by one window's click handler, and nothing here reads it.

What is new relative to Tutorial 01

  • The heading is made with CREATE-SECTION, a Lisp call for an HTML section element, where Tutorial 01 wrote the HTML text for CREATE-CHILD.
  • State lives in a closure per window, as above.
  • Each click scrolls the window to the end with SCROLL-TO and HEIGHT.
  • START-TUTORIAL hands CLOG:INITIALIZE the symbol ON-NEW-WINDOW, where Tutorial 01 handed it the function, as Tutorial 01's comments announce. This book registers the symbol for both, so a redefinition reaches new windows.

Mounting it from here

This is the part of (clog:run-tutorial 2) that applies in HyperDoc; Running the CLOG Tutorials in HyperDoc says which parts do not. In a development server, ► mounts the route and opens it in the Inspector, where its Live page is then a link. A served Catalog does not run it, and the marker in place of ► says why.

How it is mounted

As for Tutorial 01, START-TUTORIAL would call CLOG:INITIALIZE and open a browser on the machine running Lisp, so it is not called. INSTALL-TUTORIAL-2-ROUTE loads the definitions and adds this one path to the server that is running, and refuses without one. It repeats Tutorial 01's three steps rather than sharing them: two tutorials show what these two have in common, not what the rest of the collection has.

What is checked, and what only a browser shows

The tests read CLOG's own tables: the route holds this tutorial's handler and not Tutorial 01's, mounting twice changes nothing, and nothing calls CLOG:INITIALIZE. That each window counts on its own is a fact about browsers connected to a running server, and the live page is where it can be seen.
