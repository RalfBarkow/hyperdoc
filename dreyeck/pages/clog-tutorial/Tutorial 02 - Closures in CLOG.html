Tutorial 02 — Closures in CLOG

Each ON-NEW-WINDOW call binds X to zero and creates a callback that captures that binding and the original body. The k-th click increments X and creates k paragraphs under that body. Three sequential clicks therefore leave 1, 3, and 6 paragraphs. Another window begins independently at zero.

Counter → output

Follow the retained body, window, callback and click registration through their Inspector references. Each dispatch row connects the observed X transition to the original paragraph objects created by that call and their creation parent. Open a paragraph's HTML or Tree view to inspect its effect.

The installed source

ON-NEW-WINDOW uses CREATE-SECTION for the heading, LET for X, INCF for its transition and DOTIMES to create the output. Each paragraph addition also calls SCROLL-TO on this body's window.

clog-tut-2::on-new-window

X is shown as an observed lexical-state value: a completed sequential dispatch's paragraph count, together with INCF and DOTIMES, establishes its value. The lexical cell itself is not generally exposed by the Inspector. This reading uses no SBCL closure-environment introspection. Incomplete or overlapping dispatches are marked instead of supplying a reliable X transition.

Observe development windows

Run this observation example before opening new live windows. It retains the original callback and dispatcher without rewriting either closure. During each dispatch it retains CREATE-CHILD's original return objects, so their identity and creation parent remain available. It does not reconstruct them later through DOM traversal.

Only the original handler's initialization and its retained dispatcher establish observation scopes. Other Inspector/Catalog creation activity is excluded. The development workflow describes releasing observations.
