Running the CLOG Tutorials in HyperDoc

CLOG's tutorial README describes one way of working: load CLOG in a REPL, then evaluate one form per tutorial. Shown here as text, not evaluated:

(ql:quickload :clog)
(clog:run-tutorial 1)

The README's transcript continues with CLOG starting its own web server, listening on 0.0.0.0:8080, and says that most tutorials then open a browser. This page says which of those steps happen in HyperDoc, and in what form.

Why RUN-TUTORIAL is not run here

RUN-TUTORIAL loads the tutorial's file and calls its START-TUTORIAL, which calls CLOG:INITIALIZE and then CLOG:OPEN-BROWSER. In a fresh REPL, INITIALIZE starts CLOG's server, on 0.0.0.0:8080 by default.

In this image a CLOG server is already running: it is serving this page. CLOG keeps one server per image, and INITIALIZE called on a running server starts nothing new. It makes the tutorial's handler the handler of /, and it sets extended routing to whatever it is given, which, called as START-TUTORIAL calls it, is off. The Catalog at / would become the tutorial, and page addresses such as /<book>/<page> would no longer reach their pages. OPEN-BROWSER would start a browser process on the machine running this server, not in your browser. The tests observe the first two effects on CLOG's own tables, without a listener. RUN-TUTORIAL must therefore not be evaluated in a HyperDoc server.

Each upstream step and its counterpart here

UpstreamIn HyperDoc
Load CLOG Already loaded: CLOG is an ASDF dependency of this book.
(clog:run-tutorial N) Load the tutorial's definitions and mount its handler at /clog-tutorial/NN, for a tutorial classified for that: so far Tutorials 01 and 02.
Start the server Already done by HyperDoc, and never repeated.
Open a browser Follow the Live page link on the tutorial's page, in your own browser.
Evaluate a form at the REPL Run the tutorial page's example with ►; its result opens in the Inspector.
Inspect, change, evaluate again The handler's Source code, the Playground in a development server, and the Live page and the Inspector to see the result.

Where the examples run

Each tutorial page has one example, MOUNT-TUTORIAL-01 and MOUNT-TUTORIAL-02: the part of RUN-TUTORIAL that applies here. An example changes the running server: it adds a route for every visitor. It therefore has no operation contract, and a served Catalog shows a marker in place of ►, saying why. In a development server, ► runs it. The Playground follows the same line: it evaluates code only in a development server.

A contract would not be the right way to offer it publicly. The only permission the authority layer knows is that of an anonymous visitor, so a contracted example would let anyone change the server. Whether a public Catalog should have these routes mounted when it starts is a separate question, decided outside this book.

Everything else on these pages is read when the page is shown: route state, handler and source. Showing a page changes nothing.
