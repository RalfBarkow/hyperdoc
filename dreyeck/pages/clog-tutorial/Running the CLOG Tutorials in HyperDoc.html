Running the CLOG Tutorials in HyperDoc

CLOG's tutorial README describes one way of working: load CLOG in a REPL, then evaluate one form per tutorial. Shown here as text, not evaluated:

(ql:quickload :clog)
(clog:run-tutorial 1)

The README's transcript continues with CLOG starting its own web server, listening on 0.0.0.0:8080, and says that most tutorials then open a browser. This page says which of those steps happen in HyperDoc, and in what form.

Why RUN-TUTORIAL is not run here

RUN-TUTORIAL loads the tutorial's file and calls its START-TUTORIAL, which calls CLOG:INITIALIZE and then CLOG:OPEN-BROWSER. In a fresh REPL, INITIALIZE starts CLOG's server, on 0.0.0.0:8080 by default.

In this image a CLOG server is already running: it is serving this page. CLOG keeps one server per image, and INITIALIZE called on a running server starts nothing new. It makes the tutorial's handler the handler of /, and it sets extended routing to whatever it is given, which, called as START-TUTORIAL calls it, is off. The Catalog at / would become the tutorial, and page addresses such as /<book>/<page> would no longer reach their pages. OPEN-BROWSER would start a browser process on the machine running this server, not in your browser. The tests observe the first two effects on CLOG's own tables, without a listener. RUN-TUTORIAL must therefore not be evaluated in a HyperDoc server.

Three situations

The same tutorial is met in three situations, and what a reader can do differs between them:

  • upstream, standalone: CLOG in a REPL of your own, as its README describes;
  • a HyperDoc development server: a HyperDoc image run on your own machine with development enabled, as the person who owns it;
  • a public HyperDoc reading, such as the Catalog on dreyeck.ch: a server you read as an anonymous visitor.

Why the examples run only in development

Each tutorial page retains its existing transport example, MOUNT-TUTORIAL-01 and MOUNT-TUTORIAL-02: the part of RUN-TUTORIAL that applies here. An example changes the running server: it adds a route for every visitor. It therefore has no operation contract, and a served Catalog shows a marker in place of ►, saying why. In a development server, ► runs it. The Playground follows the same line: it evaluates code only in a development server.

The additional OBSERVE-TUTORIAL-01 and OBSERVE-TUTORIAL-02 examples enable object retention in subsequently opened development windows. They mount nothing and dispatch no click. Their forwarding observer preserves the original CLOG dispatcher and tutorial callback; Tutorial 02 retains paragraphs at creation time. These examples also have no public operation contract and require explicit development mode.

Opt-in uses CLOG's existing debug hook to establish observation only while the selected original Tutorial 01/02 ON-NEW-WINDOW runs. An existing debug hook is forwarded unchanged; other handlers and later Inspector callbacks establish no tutorial initialization scope.

The window registry holds weak references: after CLOG drops a closed connection, the reading does not keep that window alive. In development, run RELEASE-TUTORIAL-OBSERVATIONS to stop observation, restore original dispatcher entries and clear captured bindings, even if an observation itself remains open in the Inspector. It unmounts nothing and changes no tutorial state.

CLOG first allows its reconnect grace period, then removes the connection's data. The next observed-window lookup or new tutorial-window registration prunes that disconnected observation and clears its captured objects and paragraphs without waiting for GC. Observation stays enabled for new windows.

A contract would not be the right way to offer it publicly. The only permission the authority layer knows is that of an anonymous visitor, so a contracted example would let anyone change the server. Whether a public Catalog should have these routes mounted when it starts is a separate question, decided outside this book.

Everything else on these pages is read when the page is shown: route state, handler and source. Showing a page changes nothing.
