Two Relations Hidden in One Nest

Ward's concrete example contains two different routes:

Subordinate execution (reported nested composition):
SOLO
  LISTEN node
    REPORT title

Event propagation (source fragment and reported reach):
Solo popup click handler
  → publishSourceData / topic=node / title payload
  → window.opener.postMessage
  → opener window message reception
  → LISTEN node
  → [current nested-input handoff: unestablished]
  → REPORT lookup target

Why is REPORT subordinate to LISTEN?

REPORT is a statement nested under LISTEN in the supplied composition. Ward reports that enclosing actions run subordinate statements. The subordinate relation identifies which action runs another; it does not restrict where the listener's events originate.

Why can LISTEN hear an event from elsewhere?

Ward reports that LISTEN is operational as soon as it is rendered, that a subsequent CLICK MESSAGE can be heard to the left, and that forward/backward event broadcast across the lineup is intentional historical behavior. This mixes subordinate execution and broadcast reach. These statements are author-reported; the supplied postMessage call alone is not proof of the whole lineup policy.

Retained Mech a028b4b provides a narrower source observation: render calls run, run dispatches block emitters, LISTEN registers window.addEventListener('message', listen), and its handler accepts publishSourceData when data.topic or data.name matches the requested topic. Those observations explain a window-wide receiver independently of nesting. This retained LISTEN has no nested body/input dispatch.

Inspect the author-reported claims and proposal; inspect the actual retained source objects.

Where does title enter?

Ward's supplied click-handler fragment constructs the payload before sending it:

const message = {
  action: 'publishSourceData',
  topic: 'node',
  title: props.title || props.name.replaceAll(/\n/g,' ')
}
window.opener.postMessage(message)

title enters as message.title from props.title or the newline-normalized props.name. The source fragment's revision is not supplied. The older retained Solo dialog has a doInternalLink producer; it is not substituted for this new publishSourceData fragment.
