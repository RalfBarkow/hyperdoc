Falsifying a Gesture/Binding Witness

A first witness was written to show one thing about gestures, and a review took it apart. This page is not the repaired version's release notes. It is about how to read what the corrected recognizer keeps, and in particular how to read an input that changed nothing.

What survived?

Distinct Bindings reference the same opaque semantic Operation identity. A radial-menu sector, a learned mark and an Inspector action are three different Bindings; the thing they point at is one object, EQ in the sense of Lisp identity. The witness models transient recognition up to the selection of that identity. No execution mechanism is part of it: the identity is a structure with an id and a title, it is not FUNCALLable, and there is nothing here that could run it.

That is a claim about what the objects are, not a measurement of something that failed to happen.

What was wrong with the first witness?

Four behaviours, each found by a trace rather than by reading. A release was recorded as :RELEASED-IN-DEAD-ZONE while the pointer was twenty units outside it, because the transition was named after a condition it never checked. Entering a disabled sector ended the whole session, although the evidence only ever established that a disabled sector cannot become active. A reveal timer arriving after marking had begun raised an error, although a real timer fires whatever the user is doing. Moving after a sector was selected raised an error too, although re-selecting before release is the ordinary way a marking menu is used.

Those are recorded here as review findings, in prose. The executable objects on this page all come from the corrected implementation.

How is an input that causes no transition explained?

gesture-session-reading

Run it. Each record is one delivered input sample with the state before it, the effects it had, and the state after. The effects are a list because one sample can have more than one: a pointer move that leaves the dead zone and lands in a sector produces :PRESSED->MARKING and :MARKING->SECTOR-SELECTED at the same timestamp. Joining effects to inputs by timestamp would merge them into one; the join here is the order of the evidence trace.

expert-marking-reading

An effect is either a :TRANSITION or an :OBSERVATION. An observation is a sample the recognizer consumed and deliberately did nothing with. It is in the record, with a reason, because an input that vanishes without trace is exactly what made the old witness able to misreport a release.

What does a disabled sector mean?

disabled-then-enabled-reading

The pointer enters the disabled sector, then an enabled one, then releases. The disabled sector appears as an observation naming the Binding that was encountered, and the session stays live; the later move selects the enabled Binding, and the release completes. Not selectable is not the same as cancelled.

The reading layer has to interpret the raw DETAIL of each entry, because the reducer stores whatever was most informative where it stood: a keyword for a guard, a Binding for a completion, a plist for a selection, a string for the disabled Binding's id. That case distinction lives in %TRANSITION-DETAIL and %OBSERVATION-DETAIL and is tested. It never invents a reason the trace did not record, and a shape it does not recognise is carried through rather than dropped.

Two things that look alike and are not

obsolete-deadline-session

A reveal deadline delivered after marking has begun is consumed, recorded as :OBSOLETE-REVEAL-DEADLINE, and leaves the state where it was. That is an observation.

Now compare it with what happens when the pointer leaves every enabled sector: the active selection is cleared and the session returns to its menu or marking state. That is a transition, :SECTOR-SELECTED->MENU-VISIBLE with reason :NO-ENABLED-SECTOR-AT-ANGLE, and it is visible as one in the derived record. Both look like “nothing was completed”; only one of them left the state alone. The reading layer does not add a third kind of effect to describe the second, because the state machine already describes it.

Where this witness stops

There is no browser input, no radial rendering, no persistence, and no execution protocol. The samples are synthetic and the operation identity is opaque by construction. The state machine's :NOTES carry three statements that read like invariants; nothing validates them, so they are filed as documentation, and the test that runs the generic validator is named for what that validator actually checks — known states, guards, events, and no outgoing transition from a terminal state.

Input after a terminal state still signals a condition. That is a contract, not an outcome, and it was left alone on purpose.
