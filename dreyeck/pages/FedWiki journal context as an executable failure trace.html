FedWiki journal context as an executable failure trace

dreyeck/fedwiki-journal-context-debugger

This page materializes an observed FedWiki failure path as five executable, inspectable steps. It preserves the journal reference, the operations that consume it, and the actual runtime outcomes. The fifth step demonstrates the production containment boundary added after this failure was observed.

Execution evidence

The published wiki-links.json journal on hyperdoc.dreyeck.ch contained this entry: 

{
  "type": "fork",
  "site": "localhost:3000",
  "date": 1786347264584
}

Opening “Wiki Links” through HyperDoc then produced an unhandled USOCKET:NS-HOST-NOT-FOUND-ERROR with HOST-OR-IP "localhost:3000". The observed backtrace included: 

(USOCKET:GET-HOSTS-BY-NAME "localhost:3000")
(USOCKET:SOCKET-CONNECT "localhost:3000" 443)
(:IN HYPERBOOK/FEDWIKI::MAKE-FEDWIKI)

The first four steps retrace the evidence path without calling MAKE-FEDWIKI from an example: 

fork journal entry
  -> SITE-OF
  -> "localhost:3000"
  -> context site references
  -> context resolution boundary / GET-FEDWIKI
  -> HTTPS protocol probe
  -> USOCKET:SOCKET-CONNECT host="localhost:3000", port=443
  -> actual runtime outcome

The observed dreyeck.ch outcome at the final step was NS-HOST-NOT-FOUND-ERROR. The executable probe below records the actual outcome of the current host; it does not assert that every platform must produce the same condition.

Production operations

The trace crosses the real SITE-OF, EXTRACT-CONTEXT, GET-FEDWIKI, and MAKE-FEDWIKI operations. EXTRACT-CONTEXT now composes explicit reference extraction and resolution operations. MAKE-FEDWIKI runs the complete INITIALIZE-FEDWIKI operation in its worker thread; specific operational failures become the proxy's retained status.

Each example returns a FEDWIKI-DEBUG-STEP containing only STEP, INPUT, OPERATION, and OUTCOME. The specialized inspector view keeps OUTCOME clickable, including when it is the real condition object.

1. Journal reference

This example builds a real JOURNAL-ENTRY from the observed data and invokes the real SITE-OF operation. Its outcome is the exact string "localhost:3000".

fedwiki-journal-reference-example

2. Context references

This local-only step calls the real CONTEXT-SITE-REFERENCES operation. It preserves the ordering and deduplication rule used by EXTRACT-CONTEXT and performs no resolution or network access.

fedwiki-context-references-example

3. Resolution boundary

The real RESOLVE-CONTEXT-SITE-REFERENCES operation receives a local recording resolver. The step input contains the resolver's recorded calls. The resolver also returns each exact string it receives, so the operation outcome materializes that "localhost:3000" crossed the resolver boundary. The example neither replaces a global function nor accesses the network. Production calls use GET-FEDWIKI as the default resolver.

fedwiki-context-resolution-boundary-example

4. Protocol probe

This step invokes the real synchronous PROBE-FEDWIKI-PROTOCOL operation with "localhost:3000". An ERROR is caught in that same thread and retained as the step's raw outcome. Therefore the public example makes the failure inspectable as a value instead of letting it terminate the running HyperDoc process. A successful probe or immediate connection refusal is likewise retained as its actual normal return value.

fedwiki-protocol-probe-example

5. Initialization containment

This deterministic, network-free step injects one simulated USOCKET:NS-HOST-NOT-FOUND-ERROR at the protocol-probe boundary. It then invokes the real INITIALIZE-FEDWIKI operation and shows that STATUS-OF retains the identical condition object. No global function is rebound. The preceding protocol-probe example remains the raw, real low-level probe.

Local-first reading

The following is an interpretation and open hypothesis, separate from the execution evidence above:

A journal site reference is evidence/provenance first. Resolving it to a presently reachable network endpoint is a distinct, contextual operation.

Production keeps the journal reference unchanged: it does not rewrite or filter localhost:3000, split it into a host and port, or assign an alias. A failed context proxy now retains its operational condition while local page data remains available, and lookup can continue with subsequent context proxies.
