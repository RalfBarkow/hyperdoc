Writing D2 by Hand

dreyeck/topicmap/tala/authored

The other page in this book shows a diagram derived from a Topicmap: every node there names a Topic, and the rendering is checked against the projection that produced it. This page shows the simpler thing. The diagram below was written as D2, by hand, and stands for nothing but itself.

The text is the object. It is not a Lisp form that builds D2, and it is not stored somewhere else and displayed here — it is the content of this page, and the image is derived from it. Nothing behind it knows what network or user mean.

The source

network: {
  cell tower: {
    transmitter
  }
}

user -> network.cell tower: make call
network.cell tower -> user: ring

Laid out by TALA, through the same pinned renderer the generated diagrams use. The image is not interactive and carries no identity: there is no Topic to return to, because no Topic was involved.

What this is not

It is not editable here. The source is read from the page and rendered; to change the diagram you change the page. An editable block would need a place to put what a reader typed, and this slice deliberately does not decide where that is.

It is also not bound to anything. A generated projection can answer the question which object is this node?, because the projection holds a checked mapping from each D2 key to a Topic. Authored text has no such mapping, and giving it one is a separate capability rather than a missing detail: someone would have to say which keys are meant to name existing objects, and what it means when one does not.

What it does establish is that the authoritative payload can be ordinary D2. Everything else — the layout engine, the SVG, this page — is derived from that text and can be regenerated from it.
