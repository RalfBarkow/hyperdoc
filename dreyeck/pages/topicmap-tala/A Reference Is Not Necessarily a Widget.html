A Reference Is Not Necessarily a Widget

A reading page renders into HTML and, while it renders, collects the objects it referred to. VIEW-REFERENCES returns those objects. It is tempting to read that list as “the widgets on this page”, because on a page made only of <source-of-function> transclusions the two coincide. They are not the same question.

What does a page actually keep?

reading-page-reference-classification

Run it. Each entry names the reference, the runtime type of the object the page kept, and whether that object is a widget. Two kinds of non-widget appear on these very pages. A <a page=> link keeps the HTML-PAGE it points at, so a reader can open it. A <a expr=> link keeps the object its expression named — on From DEFVIEW to Generic Dispatch that is a STANDARD-GENERIC-FUNCTION. Both are real references and neither can be rendered and run the way a transcluded source widget can.

The list of non-widget kinds is open, which is the reason the predicate asks what an object is rather than listing what it might be. A fourth page in this book, Writing D2 by Hand, keeps a string and two conses and has no widgets at all.

The distinction, as code

page-widget-references classify-page-references

One predicate: a reference is a widget when the object it kept is itself a view. Everything else on this page follows from that.

The two widgets just above are worth one more look. Both render, neither offers a button, because a transcluded DEFUN is readable while only a DEFEXAMPLE is also runnable. “Widget” and “runnable” are a second pair of categories that happened to coincide on the earlier reading pages, where every transclusion was an example.

The counts are not written down here on purpose — they change whenever a page gains a link, and a number copied into prose would then be wrong while still looking authoritative. Read them from the example.

What would show this is wrong

The reading test does not compare the widget count against a remembered integer. It counts the <source-of-function> elements in the page file itself and requires the widget count to equal it, and it requires every reference the predicate rejects to be something that is genuinely not a view. If the predicate ever admitted a page link or rejected a transclusion, the two independently obtained numbers would disagree and the test would fail.

This is also why the distinction was worth a page rather than a fix. Three separate places had counted references as widgets, and each of them had pinned a number that happened to be right at the time. The number was never the claim.
