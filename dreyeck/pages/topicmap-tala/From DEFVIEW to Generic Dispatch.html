From DEFVIEW to Generic Dispatch

Start at the existing 👀tala-input view. Its source says (views:defview 👀tala-input (input tala:tala-input) ...). The definition installs a method on a generic function; the view returned when that function is called is a different object. These examples observe the loaded SBCL image, without scratch globals or running the TALA renderer.

Which view operations are generic?

reading-view-operations

In this image OBJECT-REF and ALL-VIEWS are ordinary functions; VIEW-REFERENCES and VIEW-HTML are generic accessors. Do not infer generic dispatch from an operation's name. The example returns their actual functions and definition sources, including method sources for generic functions. An accessor's generic-function source record can have no pathname even when its accessor and :before methods have file-backed sources. These are distinct observations.

Read alongside the observations

Peter Seibel, Practical Common Lisp (Apress, 2005), chapter 16, “Object Reorientation: Generic Functions”, explains how methods implement an operation and specialize its behavior for arguments. Use the three methods above as a concrete example of primary and qualified methods belonging to one operation.

Chapter 17, “Object Reorientation: Classes”, explains class definitions, inheritance, and slots. Inspect the TALA:TALA-INPUT specializer as the class of the argument on which this view specializes; the method belongs to the generic function, not to the class.

These chapter connections are authored reading suggestions. The observed program graph does not assert that a method requires a chapter or that one chapter precedes another. A warranted learning relation would need its own explicit authorship and evidence contract; this page leaves that relation in prose rather than introducing a new Topicmap ontology.
