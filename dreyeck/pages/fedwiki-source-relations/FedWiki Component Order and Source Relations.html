3. Forward source use

FETCH-SITE-OWNER is defined in fedwiki.lisp and its function body calls PROCESS-TEXT-AND-LINKS, defined in story-items.lisp. The corresponding typed facts are :CALLS and the derived file relation fedwiki.lisp — :uses-definition-from → story-items.lisp.

4. Reverse use through a development helper

FIND-EXAMPLES-FOR-STORY-ITEM-TYPES occurs below the source heading ;; find examples. It is classified as a :DEVELOPMENT-HELPER, not as proven unused code. It reads *NEIGHBORHOOD* from fedwiki.lisp, producing the reverse derived file relation.

5. Existing loading routine

The task is to compile, load, and then use the complete hyperbook/fedwiki system. Its task location is the serial ASDF component contract. With fedwiki.lisp before story-items.lisp, *NEIGHBORHOOD* is already declared when the latter compiles. The forward call initially occurs only inside a function body, and its target exists after the complete system has loaded.

6. Task and problem assessment

Under this current load-and-use contract, an existing routine solves the stated task. Under definition 48.2, the observed mutual source use is therefore not automatically a problem. Independent component loading, exclusively forward provider relations, development-helper separation, or the complete removal of compiler forward references would be stronger tasks whose necessity has not yet been demonstrated.

7. Topicmap projection

The generic Dreyeck Topicmap projection has exactly seven topics and nine associations. Its manually positioned symbol topics expose both directions without adding duplicate file-to-file edges or changing the native SVG renderer.

8. Two unexecuted refactoring hypotheses

  1. Move FIND-EXAMPLES-FOR-STORY-ITEM-TYPES to a later development/observation component. This is explicitly :NOT-EXECUTED.
  2. Extract the Wiki-text parser as a coherent earlier component such as wiki-text.lisp. The unit consists of *URL-REGEX*, *ANY-EXCEPT-CLOSING-BRACKET-REGEX*, *LINK-REGEX*, and PROCESS-TEXT-AND-LINKS. Moving only the function to utilities.lisp is incomplete.

A DECLAIM or forward declaration could document a compiler contract, but it would not decouple the source files.

10. How the clickable examples work

  1. <in-package> selects DREYECK/FEDWIKI-SOURCE-RELATIONS as the reader package for embedded expressions.
  2. While HyperDoc renders the page, it reads and evaluates each expr attribute in that package. Errors become inspectable condition values rather than unreadable page fragments.
  3. HyperDoc retains the returned Lisp object as an object reference behind the link. Clicking the link opens that object in a pane.
  4. The view attribute selects the initial Inspector view. The other views remain available as tabs because they are views of the same observation type.
  5. Reloading the text page evaluates the expressions again and therefore creates fresh observations. The fixed Git commit, rather than object identity, makes the results comparable.
