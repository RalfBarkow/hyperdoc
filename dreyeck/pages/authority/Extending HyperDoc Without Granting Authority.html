Extending HyperDoc Without Granting Authority

The source and bounded containment witness motivate an acceptance criterion for using HyperDoc as a library:

Downstream applicability should not itself grant browser invocation authority.

This is a desired composition contract, offered for upstream discussion. The concrete upstream question is:

Can HyperDoc provide a supported way for downstream code to make the invocation decision inspectable, use it to determine the affordance, and enforce it again at invocation time?

Keep discovery open; decide invocation separately

Automatically discovering downstream methods is useful. We want 👀operations to keep exposing real behavior and its source. Discovery should establish that a method is a candidate for this object. Whether a browser visitor may execute it is a separate decision. The upstream definition currently constructs Evaluate along with discovery; the dreyeck replacement is one experiment in separating them.

Make the description and decision inspectable

A reader should be able to inspect the operation, its target, possible effects, required authority, expected result and unresolved questions. For example, the adopted LOAD-PAGE definitions read source and update Page state; the Code Page method also evaluates SEE arguments. The current LOAD-PAGE record marks invocation authority unresolved. A useful Inspector can show that uncertainty alongside the definition.

The decision should explain why an operation is offered or refused here. The present evidence objects expose contracts and decision functions; the example does not itself exercise an invocation decision. The purpose is to let a downstream library user supply a decision that a reader can inspect and understand.

Enforce the decision when invoking

Hiding a button does not enforce authority. At server-side invocation the operation must still be permitted, its required capability present, and its target and authority current. The present method-thunk gate rechecks its limited contract decision, and the effect-free witness challenges that gate. It does not verify every target snapshot, effective method combination or evaluation path. The supported library capability we are asking about must connect the decision with the actual invocation, as well as the affordance.

Control disclosure independently

The pathname source illustrates why a non-writing view may still need authority. A library user needs to describe which resources a view may disclose and to whom. Neither a write-effect contract nor a hidden Evaluate button settles it.

Give authored evaluation its own account

The render-time source requires further questions: which source authority supplied this expression, why should rendering evaluate it, and what may it do? We have not established the required contract for that route. Render-time evaluation remains unresolved; the method-thunk witness does not settle it.

The dreyeck containment replaces upstream methods and relies on internal seams, recorded by its adapter inventory. It is evidence for discussion, not a completed HyperDoc security architecture.
