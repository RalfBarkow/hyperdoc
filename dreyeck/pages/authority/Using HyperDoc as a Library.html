Using HyperDoc as a Library

We want to use Konrad Hinsen's upstream/main HyperDoc as a library and develop the dreyeck systems separately. Downstream development includes new classes, generic functions, methods, views and operations. We want those extensions to remain discoverable and inspectable without their applicability alone granting a browser visitor permission to execute them.

Upstream source inspection

The upstream Inspector discovery functions select methods for an object and filter for one required argument. The upstream Operations definition then constructs an Evaluate thunk for each selected method; its body calls that method's generic function on the object. The reference construction, browser handler and thunk dispatch source show how an Evaluate reference leads to server-side Lisp evaluation.

The current effect-free witness asserts that a pure uncontracted method stays visible, has no Evaluate offer, and is refused at dreyeck's typed method-thunk gate. It contrasts that refusal with a permitted observational Page reader. It tests this guarded route under dynamic served parameters, not every remote evaluation path. The library question is therefore about composition: should adding behavior also grant browser invocation authority? We want to preserve 👀operations as a way to discover and inspect real methods while making invocation a separate decision.
