Using HyperDoc as a Library

We want to use Konrad Hinsen's upstream/main HyperDoc as a library and develop the dreyeck systems separately. This lets us build on HyperDoc's objects and Inspector while giving our own extensions their own source and responsibility. The current source-adoption boundary records what was adopted and which local differences remain; this checkout is not a claim that all those differences have disappeared.

For a downstream developer, extension includes new classes, generic functions, methods, views and operations. We want those extensions to participate in the library without each definition silently becoming permission for a browser visitor to execute it.

The composition that raised the question

The installed upstream Inspector source constructs an Evaluate thunk for each method selected by its one-argument discovery rule. The thunk calls the method's generic function on the inspected object. The Evaluate reference and browser handler carry that call into the server's Lisp image. Together these sources expose this route:

downstream adds a method selected for this object
    → Inspector lists the method in Operations
    → Operations offers Evaluate
    → a browser invocation evaluates its Lisp thunk

The policy suite's composition test uses a downstream Page method with a visible effect as a probe. Under the served policy the method stays visible, is offered no Evaluate and is refused with zero probe calls; outside that policy the same invocation runs once. That test runs in dreyeck/authority-policy/tests; this page shows its current source and does not run it.

The issue is the composition rule, even when the added method is harmless: does adding behavior also grant remote invocation authority? We want to keep 👀operations useful for discovering and inspecting real methods. Approval to invoke them is a further decision. The current effect-free experiment shows one dreyeck attempt to separate the two. It covers the guarded method-thunk route; render-time page expressions remain under investigation.

This reading continues through the distinctions, the Lisp witnesses, the desired library contract, and future upstream changes.
