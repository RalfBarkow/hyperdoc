Using Upstream Safely

A library composition contract must survive changes to the library. Before adopting a future upstream/main revision we would therefore ask: has its remote authority surface changed when composed with dreyeck?

“Upstream Intake” is our name for observing a candidate revision before deciding to integrate it. The existing general Intake reading is optional background; its other examples concern commit observation and curation, not a demonstration of authority compatibility. The page-loading observation constructor, current containment drift check and its test provide concrete starting points. The drift check is bounded to known adapters and several enumerated surface changes; it is not a complete authority review. Its existing test can detect those recorded dependencies moving.

A future intake review could compare the candidate and retained source, then exercise their composition with downstream classes and methods. Beyond API compatibility and passing tests, it should ask:

  • Do new or inherited methods enter the Inspector's discovery list? Does a harmless uncontracted downstream method acquire an invocation offer?
  • Have generic Evaluate affordances, reference construction, browser handlers or server-side evaluation routes changed?
  • Do new views disclose files or other resources, or bypass the expected source-root decision?
  • Have authored or render-time evaluation paths changed? Which source authority supplies their expressions?

The actual source definitions identify today's comparison points. The current dreyeck containment witness supplies a repeatable negative case and a permitted observational contrast for typed method thunks under dynamic served parameters. It does not execute pristine upstream. New cases would be needed for surfaces that these examples do not cover.

An intake result should distinguish source differences, observed composed behavior, proposed consequences and unknowns. In particular, a passing method-thunk test must not close the render-time authority question. That topic remains under investigation.

For provenance, the repository-relative source-adoption record identifies the adopted HyperDoc reference and remaining local differences. This checkout and its containment witness should not be read as pristine upstream.
