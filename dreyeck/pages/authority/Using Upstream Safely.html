Using Upstream Safely

A library composition contract must survive changes to the library. Before adopting a future upstream/main revision we would therefore ask: has its remote authority surface changed when composed with dreyeck?

Our existing Upstream Intake reading separates observing a candidate from integrating it. The page-loading comparison and current containment drift check provide concrete starting points. The drift check is bounded to known adapters and several enumerated surface changes; it is not a complete authority review. Its existing test can detect those recorded dependencies moving.

A future intake review could compare the candidate and retained source, then exercise their composition with downstream classes and methods. Beyond API compatibility and passing tests, it should ask:

  • Do new or inherited methods enter the Inspector's discovery list? Does a harmless uncontracted downstream method acquire an invocation offer?
  • Have generic Evaluate affordances, reference construction, browser handlers or server-side evaluation routes changed?
  • Do new views disclose files or other resources, or bypass the expected source-root decision?
  • Have authored or render-time evaluation paths changed? Which source authority supplies their expressions?

The actual source definitions identify today's comparison points. The live witness supplies a repeatable negative case and a permitted observational contrast. New cases would be needed for surfaces that these examples do not cover.

An intake result should distinguish source differences, observed composed behavior, proposed consequences and unknowns. In particular, a passing method-thunk test must not close the render-time authority question. That topic remains under investigation.

No upstream update is performed by this reading. Return to the proposed library contract or the beginning of the five-stop reading.
