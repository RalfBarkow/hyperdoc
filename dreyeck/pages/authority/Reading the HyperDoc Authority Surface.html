Reading the HyperDoc Authority Surface

The library composition problem asks us to distinguish several relations. The examples below give them concrete meaning before we discuss extension points.

From a method to an invocation

Method applicability concerns dispatch: a method specialized on Page can participate when its generic function receives a Page. Our marker method is such a definition. Inspector discovery has its own selection rules, including superclass traversal and a one-argument filter; inspect the actual discovery functions rather than treating this list as a complete account of CLOS dispatch.

Inspectability means being able to see that method and read its definition. Invocation affordance means being offered a way to run it. The upstream Operations definition supplies both a method reference and an Evaluate button. Those are distinct offers.

Invocation authority asks whether this visitor may request that execution in this context. The current dreyeck contracts and decisions give the marker no contract and give PATH-ITEM-OF an observational contract. Under served policy the containment source keeps the method reference but withholds its Evaluate offer and checks again at thunk invocation. This is a local experiment, not an upstream library contract.

Capability, effect and verification

Runtime capability asks whether the image has the means to carry out an operation; permission asks whether it may. The Page reader contract requires no additional capability (:none) and allows anonymous invocation. In contrast, the Work status contract requires an authoring environment and owner permission. The decision source treats capability and permission as separate checks; its present permission model only grants anonymous access.

For a changing operation, effect authority identifies what it may act on, and effect extent bounds what may change. The same Work contract names an exact observed source declaration and bounds the intended change to one status character range in one HTML file. Its post-effect verification record calls for checking installed source and rereading the Topic. These are contract statements, not evidence that this reading has performed a write. No changing operation is used in our executable witness.

Two other authority questions

Disclosure asks what an inspection may reveal. The pathname Items and Content views can expose directory entries or file contents without changing those files. The same source group shows dreyeck's current root check. A description of write effects alone would not answer who may read those resources.

Authored evaluation asks why code supplied by a Page may run. The HTML generator and expression-link serialization source call PARSE-AND-EVAL while rendering, before an invocation button is clicked. This is a separate authority class. Its source and permitted effects remain under investigation; the guarded method witness does not establish containment for it.

Applicability, inspectability and invocation authority are different relations. Next: inspect the Lisp and run the witnesses. The Library definitions view transcludes the external definitions beside the downstream source.
