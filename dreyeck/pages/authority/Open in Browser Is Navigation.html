Open in Browser Is Navigation

This case was found while auditing executable affordances, but its resolution is not an authority-policy rule. The upstream representation made client navigation look like a server-side action. Replacing that representation removes the invocation rather than authorizing it: nothing on this page decides that an operation may run, because the affordance stops being an operation.

upstream:  PAGE-URL → ACTION-BUTTON → THUNK → CLOG:OPEN-BROWSER → server host
link:      PAGE-URL → ordinary link → visitor's browser

The topicmap of both paths gives each relation a warrant and the epistemic status the other dreyeck topicmaps use: source-observed (read in the pinned or downstream source), directly observed (in the running image, the tests or the browser witness), mechanically derived, or design inference (that an href can carry PAGE-URL, the proposed upstream change and the adapter's deletion condition).

Upstream: a Wikipedia page and its URL

In HyperDoc's hyperbook-wikipedia/wikipedia.lisp (8a114919), a WIKIPEDIA-PAGE belongs to the book of one Wikipedia edition and carries its title. PAGE-URL derives the page's address from these two:

(navigation-source-view :page-url)

Upstream: Open in browser as a title-bar action

The title bar of a Wikipedia page comes from this method:

(navigation-source-view :upstream-title-bar)

ACTION-BUTTON renders a button whose id names an action reference to the THUNK, a closure over the body. When the button is clicked, the Inspector's click handler evaluates the thunk on the server. Its body calls CLOG:OPEN-BROWSER, which by its own documentation launches a web browser on the local machine:

(navigation-source-view :open-browser)

The local machine is the one running the server. A visitor's click therefore starts a process on the server host. On a Catalog run on one's own machine, that host is the visitor's machine too, which is why the action looks right there.

PAGE-URL is already data

The thunk's only input is (page-url page), which exists before anything is clicked. Following a URL needs no Lisp evaluation: an href can carry it, and the visitor's browser follows it. The title-bar generic asks for "HTML inline elements", and a link is one. HyperDoc already writes such links: ADAPT-DOM gives the external links in Wikipedia page content target="_blank" and no rel.

A downstream experiment

The dreyeck commit ea31d6c3 replaces only that method, without changing HyperDoc's source:

(navigation-source-view :adapter)

The link's href is upstream's PAGE-URL, HTML-escaped and nothing else; it opens in a new tab, like the links in page content. There is no thunk and no action- or eval- reference, so nothing can reach CLOG:OPEN-BROWSER. Before this commit, dreyeck withheld the upstream action from its public Catalog (35a83fdf); ea31d6c3 removed that withholding, since there is no invocation left to withhold. The public Catalog and a development server now offer the same link.

Styling is a separate, open choice

The link has the class inspector-action. Observed: in the current clog-moldable-inspector this class gives a title-bar element the look of an action, so the link looks close to an action button. Observed: the only behaviour tied to the class, the highlight while an action runs, comes through a reference, and this link has none. Open: whether upstream should make a title-bar link look like an action button at all. The semantic proposal is the link, not this class.

What the current image renders

The one executable example of this page, TITLE-BAR-NOW, renders a Wikipedia page's title bar under served parameters and under development parameters; run it from its code page. It is executable because which method renders the title bar depends on what the image has loaded: only running it shows that this image gives an ordinary link with no reference, the same served and developing. It allocates an unregistered page, fetches nothing and clicks nothing.

Tests and a manual browser witness

The adapter's test reads back four titles — Blog, Schrödinger's cat, a"b<c>&d and Schr%C3%B6dinger%27s cat — as one anchor with only class, href and target, an href equal to PAGE-URL, no second percent-encoding, and CLOG:OPEN-BROWSER stubbed and never called. The navigation regression asserts the same visible link served and developing, no reference and zero CLOG:OPEN-BROWSER calls; it does not name the adapter.

A manual browser witness is associated with ea31d6c3; this reading does not reproduce it. It ran the packaged sources locally on 127.0.0.1, once as a public-mode Catalog and once as a development server, not against dreyeck.ch. A trusted click on the link reached the window's bubble phase with defaultPrevented=false: the Inspector did not cancel it. A control handler that cancels the click was detected as cancelled. The witness then cancelled the external navigation itself, so the click did not contact wikipedia.org. CLOG:OPEN-BROWSER, stubbed on the server, was called zero times.

Separately, in each run the server made one request to the Wikipedia API while the page rendered, intercepted by the witness: upstream's Source and Parse tree views fetch when they are computed. That is a render-time fetch, not part of the title-bar navigation path.

The minimal upstream change

Proposed for khinsen/hyperdoc, in hyperbook-wikipedia/wikipedia.lisp:

 (defmethod views:title-bar-action-buttons ((page wikipedia-page))
-  (views:action-button "Open in browser"
-                       (views:thunk (clog:open-browser :url (page-url page))
-                         nil)))
+  (views:html
+    (:a :href (cl-who:escape-string (page-url page))
+        :target "_blank"
+        :class "inspector-action"
+        "Open in browser")))

with #:cl-who added to the depends-on of hyperbook/wikipedia, which would then call it directly. The class may be whatever upstream prefers. A test needs no dreyeck machinery: render the title bar of an unregistered page, expect no reference, and parse the HTML for exactly one anchor whose decoded href equals PAGE-URL and whose target is _blank.

When the downstream adapter goes

The adapter's test compares the pinned upstream method as one form and fails when it changes, with the proposed method as its positive control. When pinned upstream navigates in the client: delete the adapter, its focused test and its systems; keep the navigation regression if it still applies; and revise this page to point at upstream's implementation rather than delete it.

A related observation: FedWiki

The title-bar Open actions of a FedWiki book, a FedWiki page and a remote FedWiki page have the same shape: an ACTION-BUTTON whose THUNK calls CLOG:OPEN-BROWSER. They are not examined here; whether the same change fits them is a separate question.
