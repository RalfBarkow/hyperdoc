Planning Evidence-Based Investigations

This optional example asks SHOP3 to plan an investigation of a known Topic Maps test case. It does not run the test, edit its source, change a registered Case Record, or declare conformance. The planning domain is conformance-investigation; its task is qualify-test-case.

The evidence is retained at Topic Maps commit 88994c1b9e1edbf13e665e984a5c9c3b2cdf7575. The reader uses explicit Git file-at-commit objects. It does not load Topic Maps code or consult a moving worktree. The Slice 22A observations were made against base 1c0b92c68fe1114b926d4405b553dfb096d2f425; retaining them at the later commit does not make them new executions.

Case A, ctm/in/include-template.ctm, is registered FAIL. The recorded original deserializes, but actual CXTM has 353 bytes against a 401-byte baseline, first differing at byte 58. Formal normative disposition C is unresolved. Both preparations are justified: review-observed-mismatch prepares a byte-difference review; prepare-normative-question prepares an edition-qualified question about include environments. SHOP3 returns both with :which :all. Neither is a claim that the baseline or implementation is correct.

Case B, ctm/in/template-subject-identifier2.ctm, remains registered NOT-RUN with no registered actual outcome. A separate reader observation reports INVALID-TEMPLATE-BODY / template-identity-tail at character 34, line 3, column 15. An expanded control matches 204/204 CXTM bytes. The method investigate-registered-not-run plans to separate these observations and frame an inquiry about the original. Control success is never promoted to original-case PASS.

The report explicitly records incomplete review of the published CTM edition beyond the preview. Requesting an :edition-qualified-disposition therefore yields report-explicit-prerequisite-gap. This scope is a proposed planning request; the incomplete review is a historical recorded limitation. It does not prove the standard is unavailable or the reader lacks a normative capability. If that negative observation is removed, the planner has no basis for a blocker and returns no plan.

Registered statuses, reader observations, normative assessments and proposed goals remain distinct. Operators add only planned-* facts to simulated states. Unknown evidence stays unknown. The new ASDF system is dreyeck/work/topic-maps-conformance-planning; no new Topic Maps model, corpus importer, runner or Fable API is involved.

Inspect the real SHOP3 results

Use the intended local SLY image. Evaluate each block as a separate request so packages exist before later forms are read. Loading the optional system registers this reading HyperDoc but starts no listener and reads no external evidence automatically.

(asdf:load-system "dreyeck/work/topic-maps-conformance-planning")

The following explicit local repository path is the prepared Cloud example. On another machine, replace only the root with the actual Topic Maps Git repository containing the pinned objects. The worktree may be changing: only objects at the fixed commit are read, never its current implementation files.

(defparameter *conformance-evidence-repository*
  (make-instance 'dreyeck/git:git-repository-checkout
    :root #P"/workspace/topic-maps/"
    :root-source :explicit-read-only-evidence))
(defparameter *conformance-a*
  (dreyeck/work/topic-maps-conformance-planning:investigate-case
   *conformance-evidence-repository* :include-template))
(defparameter *conformance-b*
  (dreyeck/work/topic-maps-conformance-planning:investigate-case
   *conformance-evidence-repository* :template-subject-identifier2))
(defparameter *conformance-blocked*
  (dreyeck/work/topic-maps-conformance-planning:investigate-case
   *conformance-evidence-repository* :include-template
   :goal :edition-qualified-disposition))
(inspect *conformance-a*)

Expected: two alternatives for A, one distinct inquiry for B and one prerequisite-blocker proposal. In Investigation alternatives, open the native result and each native plan tree. The method names come from SHOP3's own tree, not a reconstructed checklist. Source references lead to the unchanged serialized Case Records, matrix, original/baseline files and historical execution provenance.

With CLOG Moldable Inspector already loaded and connected in that same image, these forms inspect the reading and the existing native result directly. They are not instructions to start or restart a service:

(clog-moldable-inspector:clog-inspect :object *conformance-a*)
(clog-moldable-inspector:clog-inspect
 :object (dreyeck/work/topic-maps-conformance-planning:run-result *conformance-b*))

All results are :plan-only. A successful blocker plan is not completed qualification. No alternative is automatically selected or executed. Actual source inspection and Lisp tests can be recorded separately; interactive browser navigation is not established by HTML-reference tests.
