Execution Authority

Three boundaries apply, and they are not the same.

1. Rendering runs nothing

Showing a page or a view of this reading, of the 22U reading or of the CTM review reads and hashes files and asks Git and ASDF questions. It runs no experiment, verification or load. Something runs only when its button is pressed.

2. The served Catalog's authority policy

In a served Catalog that is not in development mode, the policy is enforced. An Operations method or a DEFEXAMPLE button runs only under a registered contract (example-invocation-decision). This reading's Catalog is served that way. Open its Code page Explicit Runs, ASDF Origins and the Reading's Entry: before each defexample stands ▷, not run here, because no contract is registered for it.

A plain v:thunk button is not an example and is not gated. The 22U reading's Read a fresh 22U Map, the CTM review's Run the experiment and this reading's two buttons are plain thunks. Press Verify the snapshot now: the run records whether the policy was enforced when it ran. That a run is recorded with the policy enforced is the observation this claim derives from source.

3. The variant serves loopback only

Because those buttons would run for anyone who can reach the Catalog, the variant refuses every host but 127.0.0.1 and ::1, before anything is loaded: the check, recorded, claim. That is D5. The production proxy, service and policy are unchanged. Public exposure would need its own decision.
