The Roots of Lisp reconstruction layers

hyperdoc

The reconstruction must not collapse four different things into one "interpreter": semantic axioms, derived object-language definitions, top-level/browser facilities, and documentation/inspection projections.

Layer 1 — semantic core

ROOTS-EVAL consumes an already-read expression and an explicit environment. QUOTE and COND are non-strict. ATOM, EQ, CAR, CDR, and CONS evaluate their arguments. An unknown atomic operator is looked up and rewritten to its LAMBDA or LABEL value.

Layer 2 — function notation and derived library

LAMBDA pairs parameters with evaluated arguments and prepends those bindings to the current environment. LABEL additionally binds its own name to its function expression. The environment is therefore the dynamic environment of the historical evaluator, not a Common Lisp lexical closure.

Layer 3 — Stanford-style adapter

ROOTS-INTERPRET-STRING provides a stateful top level. DEFUN and a top-level use of LABEL update a session. LIST and c[ad]+r are treated as surface abbreviations so Graham's code can be entered unchanged.

Layer 4 — HyperDoc projection

The evaluator returns ROOTS-EVALUATION objects. Their event lists make evaluation order, environment lookup, operator rewriting, clause selection, LABEL recursion, and LAMBDA binding inspectable rather than hidden in terminal output.
