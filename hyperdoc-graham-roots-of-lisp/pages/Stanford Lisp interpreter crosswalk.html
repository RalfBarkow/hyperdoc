The Stanford page is an implementation adapter around Graham's paper, not merely a transliteration. Its Haskell code adds a parser, error representation, top-level definitions, LIST, generated accessors, persistent environment, and a browser Run button.

One deliberate change

The Stanford Expr type represents only atoms and proper lists. This reconstruction uses Common Lisp cons trees, so quoted dotted pairs remain representable. That makes the data model closer to the historical S-expression substrate while leaving all Graham examples unchanged.

Parser boundary

The Common Lisp reader is used as a parser with *READ-EVAL* bound to NIL. Parsed forms are data passed to ROOTS-EVAL; they are never sent to Common Lisp's EVAL.

Top-level boundary

DEFUN is implemented by storing a LAMBDA expression in a ROOTS-SESSION. This mutable top level must not be mistaken for a new primitive in the semantic core.

Evaluator identity boundary

  • Graham's corrected named-call rule is implemented by HyperDoc's Common Lisp host evaluator.
  • The object-language EVAL. definition runs inside that host evaluator.
  • Lynn's implementation is a separate Haskell/browser execution path.
  • The current reconstruction retains the historical dynamic environment; it is not silently upgraded to lexical scope.
