The Surprise as an evaluation trace

hyperdoc

Graham's "surprise" has two levels. The first is a compact evaluator written from the seven operators. The second is reflexive: the evaluator is itself an expression in the language it evaluates.

Two experiments that must remain separate

  1. Host evaluator runs LABEL/SUBST directly.

    hyperdoc-graham-roots-of-lisp:roots-direct-subst-example

  2. Object-language EVAL. runs LABEL/SUBST.

    hyperdoc-graham-roots-of-lisp:roots-surprise-example

How to read the trace

  • :ENTER and :RETURN delimit one recursive evaluation.
  • :ATOM-LOOKUP shows the explicit environment lookup.
  • :NAMED-OPERATOR-REWRITE replaces a function name by its LAMBDA or LABEL expression.
  • :LABEL-BIND makes recursion possible.
  • :LAMBDA-BIND shows parameters, values, and the extended dynamic environment.
  • :COND-TEST and :COND-SELECTED expose non-strict branching.

A bounded event limit affects only retained evidence. Evaluation continues, and TRACE-TRUNCATED-P-OF records whether the trace was clipped.

Keep the host and object-language evaluators distinct

HyperDoc's Common Lisp function ROOTS-EVAL is the host evaluator. The definition EVAL. is object-language code loaded into a ROOTS-SESSION and run inside that host. The Lynn browser runner is a third implementation. The named-call retrace compares two explicitly selected host rules without changing the corrected default.
